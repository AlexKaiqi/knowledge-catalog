# 代码信号采集 + AI 复核

要解决的问题：判断代码是否在腐化，不能只靠工具报数——工具报警常常是设计使然或误报。

怎么做（工具、阈值、步骤）自行组合：静态采集规模、复杂度、重复、churn、依赖即可；缺工具就等价替换或声明未覆盖；装新工具先征得用户同意。测试与生产分开统计，中间产物放 /tmp 不进仓库。

结论必须逐条归入三类并给证据（文件:行 / 数字）：

- **真问题**——与设计意图冲突、持续增长、或无人受益；
- **设计使然**——符合仓库明文设计（本仓库看 `docs/graph/` 与 `internal/arch` 守卫），不算腐化；
- **误报 / 可忽略**——机械代码、测试基建、一次性脚本。

提醒：跨目录调用数量本身不是坏信号，方向与环才是；组合信号（churn × 复杂度）比单信号可信。不运行测试、不改产品代码、未覆盖的信号要声明。
