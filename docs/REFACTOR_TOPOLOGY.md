## 0. 一句话目标

把"重构目标"从一张随计划文件消失的组件图，变成**可核对的目标形态**：按信任边界分面，每一格标注它今天是**已固化**、**已选定但未闭环**还是**待裁决**。没有 owner 的格子不画。

本轮基础闭环只调整 provider 合同、有界 I/O、能力隔离、恢复账本与 typed Application
Core（`DOLT-01`、`DOC-14/16/17/18/19`、`APP-CORE-01`）。动态 State、规模资格、组件选型、
多实例拓扑和全部 `REVIEW-*` 保持后续门槛；它们出现在总图中只为标明边界，不是本轮承诺。

## 1. 为什么按面画，而不是按组件画

三条已有结论决定了这个画法：

1. **组件是唯一被允许替换的部分。** 具体 authority 不得泄漏进非装配根（`A-01`），介质表"是选型，不是性能排名或生产规模资格结论"（[`STORE_ADAPTERS.md`](STORE_ADAPTERS.md) §3）。把某个引擎名写进层名，等于把可替换项钉成骨架。
2. **接入与消费不是同一种边界。** 接入接受不可信输入并改变事实，失败语义是"未提交"或"形成提案"；消费不得改变权威状态，先冻结 `{repository → commit}` 再逐请求鉴权。两者的权限模型、流量模型和扩展方向都不同，合成一层会掩盖差异。
3. **状态必须与形态一起画。** 只有形态没有状态，就会把"设计里有"当成"系统里有"。本文因此强制三态标注。

状态标记：

| 标记 | 含义 |
|---|---|
| 【固】 | 已有不变量 ID 且证据列指向存在的测试（见 [`ARCHITECTURE_INVARIANTS.md`](ARCHITECTURE_INVARIANTS.md)） |
| 【选】 | 方向已由 owner 选定，实现或证据未闭环；括号内是 [`TASK.md`](../TASK.md) 条目 |
| 【裁】 | 语义未选定，括号内是 [`TASK.md`](../TASK.md) 的 `REVIEW-*` |

## 4. 目标与现状的差距

只列已登记条目。**每一条都是"设计已选定、实现或证据未闭环"，不是新提出的方向。**

| 差距 | 现在是什么 | 目标形态要求什么 | 条目 |
|---|---|---|---|
| 写路径有界 | 每个 commit 全列路径逐 blob 读，定位表整体重写 | 单对象提交的读取次数与仓库总量无关 | `DOC-17` |
| 读路径有界 | 按对象读取时全量加载并解码定位表 | 单对象读取的解码字节数与总量无关 | `DOC-17` |
| 变化识别 | 能力缺失时吞掉错误、两次全量遍历，派生侧降级为全仓重建 | 升为 ⓪ 一等能力，缺失显式失败，退化原因是可观测的一等值 | `DOC-17` |
| 能力面收口 | 原生 Knowledge adapter 仍实现并转发原始路径写 | 原生知识装配不暴露原始树写旁路 | `DOC-14` |
| 能力判定 | 装配根对可选能力做不带 ok 的类型断言，缺能力时 panic | 装配期一次性冻结，请求期只读判定，缺能力失败关闭 | `DOC-18` |
| 守卫覆盖 | 分层守卫跳过 `scripts/`，而那里打开具体 authority | 守卫遍历全部非测试生产包，例外精确到符号 | `DOC-18` |
| provider 等价性 | 规模档选定的权威 provider 从未接入共享合同；跨 provider 等价性为空 | 合同接入 + 按步骤索引对齐的等价性 harness + 毒化项 | `DOC-16` |
| 账本可恢复 | PENDING 永不清理，命令身份可能永久不可用 | 显式解决/放弃入口 + 保留窗口，增长有界 | `DOC-19` |
| 应用核心 | 应用编排仍广泛依赖 CLI flags、dispatcher 与裸字符串标识 | typed request/result；CLI/HTTP 只转换 transport；应用核心不依赖 parser、registry 或具体 provider | `APP-CORE-01` |
| M 面合同 | 有端口、无合同；端口被带外方法击穿 | 取值只有一条路径，重读能力由接入方声明并如实转述 | `DOC-20` |
| 动态部署 | 各段有实现和局部验证，整条链无证据 | 真实 Observer/runtime/权威/服务/引擎串联并证明重启恢复 | `DYN-01` |
| 容量结论 | 有档位、用例与生成器，无有效容量基线 | 先闭合 S0/S1 测量，再逐档扩量 | `SCALE-01` |

## 6. 本文不覆盖什么

- **不裁决 `REVIEW-*`。** 表格里出现的每个 `REVIEW-*` 都仍是开放项，本文只标注它落在哪一面。
- **不定义形态。** 字段、错误码、状态机归公开类型、包 README 与 Conformance；本文出现的均为描述性措辞，不构成第二套定义。
- **不维护状态台账。** 完成度只在 [`MVP_ACCEPTANCE.md`](MVP_ACCEPTANCE.md) 与 [`TEST_CATALOG.md`](TEST_CATALOG.md)；本文的三态标注仅用于阅读目标形态时不误读为"已具备"。
- **不承诺容量。** 本文没有任何数据量、延迟或重建时长数字；那些只能由 `SCALE-01` 的实测产出。
- **不引入组件选型。** 具体引擎的取舍在第 8 步，且必须以第 1–7 步的实测为依据。
