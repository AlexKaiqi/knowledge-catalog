# 外部资源访问

## Goal

外部系统中的当前状态、事件和可调用操作，不适合都转成知识仓提交：保存稳定的访问声明，
通过接入方 runtime 取得运行值；需要长期治理的内容再显式发布为知识。Resource Access 提供
取值与操作，Collector 把选定内容变成 Writer 变更，Observer 提示已有声明所指状态发生变化。
这是三个职责，不要求三个进程，也不能因部署在一起而混用协议。

## Non-Goals

- 固定声明不冻结外部当前值，也不保证旧 runtime 永久在线；观察不成为仓内容或组合成员。
- 通知不能创建新的知识身份；新实体必须先经 Collector 对账并经 Writer 提交。
- State 接入不隐式引入通用流处理器；事件窗口与持续订阅是成组的待选合同，选定之前不写成
  已有能力。
- 保留观察不进入 Catalog pin，也不实现 Snapshot Store。
- 本页保留方向性保证，不复制消息形状、认证头、错误码或运行配置。

## 声明与运行值分开

知识版本固定怎样理解和访问某资源；观察依据说明这次实际读到了什么。固定声明不冻结
外部当前值，也不保证旧 runtime 永久在线。精确知识读取可以组合动态值，文件视图仍只交付
已固定的声明字节。

新的观察通过声明上的取值入口取得。通知只定位变化，不能把它携带的正文直接当作观察，
也不能凭一次通知或取值创建新的知识身份——新实体必须先经 Collector 对账并经 Writer
提交，否则只能作为外部资源引用返回。取值与操作是两个入口、两个授权动作：能看见某个
受保护操作的说明，不等于可以在外部系统执行它；资源操作带输入，先从本次固定版本回读
声明，只调用声明允许的操作，调用方不能覆盖声明指定的运行目标或协议，平台也不内置
具体系统的语义。源只有消息流时，由接入方 runtime 先物化出可取值的当前态；State 接入
不隐式引入通用流处理器。

资源访问的原点由接入方拥有并随知识版本化：声明原点写在领域 Schema 的规范元数据里，
操作原点写在描述本身。换机房或换环境是一次新的 Schema 发布，不是改服务端配置；整机
一个统一资源访问地址的方案被否决，它会把接入方的责任挪到平台，并让声明失去可版本化
的归属。

动态观察从 Repository 借身份，不拥有内容：归属仓、编译所依据的声明版本与 binding
摘要、按对象地址与资源引用键控、经固定 binding 代际观察。运行值不是仓内容，也不是
任何组合范围的成员；与仓完全无关的资源搜索可由上层产品提供，但不自动获得组合身份、
授权或完整性语义。集成仓与运行宿主同样不是知识仓或组合成员。

Collector 是另一条路径：明确来源、范围和对账结果，再经 Writer 发布。访问一次不自动沉淀
为知识，取值失败也不能被解释为源集合为空而触发删除。源客户端、凭证和业务映射留在接入方
运行环境，协议包不嵌入具体系统客户端。

## 一次观察需要解释什么

| 维度 | 必须能够回答 |
|---|---|
| 覆盖 | 对本次声明范围，哪些对象或条件已经检查，哪些仍未知 |
| 新鲜度 | 已完成的观察与来源进度是否满足此次用途 |
| 重读 | 来源或平台能在什么条件和保留期内返回同一观察 |
| 授权 | 当前调用方是否有权取得来源数据或明确获准共享的观察 |

这四项不能互相代替。观察时间不是来源进度，单调 revision 不是历史重读证明，
多个 Binding 也没有天然的全局原子快照。源码中的能力标签只表达其已经选定的合同，
不能从一个标签推导未提供的保证。

运行可观测状态与语义元数据要分开。watermark、滞后、可用性、最近错误、活动代际属于
运行状态，随观察高频变化，不逐次提交成知识版本；Agent 与规划者应当看到的是语义元数据
——Aspect、Schema、取值来源、逻辑访问面、新鲜度、保留与覆盖、hydrate 语义——而不是
凭证、内部拓扑或未脱敏的载荷。访问记录保留实际调用主体、可选代理用户、调用关联上下文、
固定声明版本、实际运行代际、观察依据与结果摘要或错误；载荷是否留存由证据策略决定，
且访问记录不引入新的会话概念。

查询“当前失败的任务”时，成功零命中也需要整个查询范围的时效依据。若无法证明足够新，
不能把旧观察当成当前事实交付。默认允许多旧、谁指定期限、过期时如何响应仍需选定；
在此之前不放宽现有完整性与失败关闭要求。

## 恢复与观察保留

通知会丢失、重复或乱序。后台必须能从声明身份重取并对账，或使用来源支持的增量进度恢复；
进度断档后回到可证明的恢复路径。过期策略只能阻止旧观察继续冒充当前，不能找回漏掉的变化。
来源没有顺序证明时，也不能虚构全局单调进度。

活动 Serving State 支持当前查询，保留观察支持之后按原依据复核；两者可以共用介质，
但不能混用生命周期。承诺保留的完整值与依据需要先可靠保存，再发布依赖它的结果。
只保留活动版本或摘要不等于历史保留。

来源只能返回最新值时，平台记录可能是旧观察唯一的重读依据。它是平台曾观察到的证据，
不是来源真相或连续事件历史；两次观察之间发生过什么可能根本没有被看到。
保留期内丢失记录是恢复故障，正常到期是生命周期结束，两者都不能以最新值或空历史掩盖。
统一保留观察记录还有结构性收益：只有 latest-only 来源的接入方也获得有界重读，下游
接口与依据语义不因接入方能力不同而分叉；索引重建可以直接重用保留记录，不能要求
latest-only 来源重新提供已经消失的值。

State 阶段纳入有界观察保留。接入方声明需求、平台设容量和保留上限；超出能力应明确拒绝，
不能静默缩短已承诺的期限。介质、默认期限、备份与容量不足时的行为仍由后续运行合同选定。
这些记录不进入 Catalog pin，也不实现 Snapshot Store。

## 与权限和索引控制的交接

资源访问接收可信的、适用于该目标的调用上下文，返回能够解释的观察；后台能取值不代表
所有消费者都能使用。逐调用方源授权、显式共享观察、凭证目标限制与撤销由权限设计展开，
运行时必须执行相应边界。源拒绝不能回退旧观察或占位值，动态过滤也不能先使用无权值。

索引控制根据服务需求调度观察与恢复，本组件提供可取值、可复核及来源恢复能力。
后台调度不能补造来源顺序，资源端也不因成功取值就宣称整个查询范围已经覆盖。
观察保留是本篇的消费承诺，控制器据此安排发布，查询按所需依据回读。

## State、事件窗口与订阅逐步展开

先让当前态的取值、查询、恢复和复核可信，再设计有限事件窗口。窗口需要解释顺序、来源进度、
迟到和保留缺口；持续订阅还需要恢复、背压与取消。它们不是 State 普通读取的数组模式，
也不增加 Writer 的追加写面。流处理 checkpoint 可由外部 runtime 管理，不成为知识版本。

上层物化的正确性有等价判据：含增量的构建等于先构建再应用索引增量；事件按窗口拼接与
一次性读取等价；折叠可复合；按绑定、键与源版本的重放幂等。它们是检索与物化产品的
合同，不进入仓协议一致性检查。事件流的待选合同仍然成组：分区水位、游标、窗口与部分序
如何表达；流的保留、删除标记、压实与断档后重列或重置的责任；事件投影与当前态折叠的
声明位置；旧运行代际的托管、迁移与服务期限。选定之前不把这些写成已有能力。

## 硬性约束 / Invariants

- 知识版本固定怎样理解和访问某资源；观察依据说明这次实际读到了什么。精确知识读取可以
  组合动态值，文件视图仍只交付已固定的声明字节。
- 通知只定位变化，不能把它携带的正文直接当作观察；取值与操作是两个入口、两个授权动作，
  调用方不能覆盖声明指定的运行目标或协议。
- 资源访问的原点由接入方拥有并随知识版本化；换机房或换环境是一次新的 Schema 发布，不是
  改服务端配置。
- 动态观察从 Repository 借身份，不拥有内容；运行值不是仓内容，也不是任何组合范围的成员。
- Collector 访问一次不自动沉淀为知识；取值失败不能被解释为源集合为空而触发删除。
- 覆盖、新鲜度、重读、授权四项不能互相代替；观察时间不是来源进度，单调 revision 不是
  历史重读证明。
- 运行可观测状态与语义元数据分开；Agent 与规划者看到语义元数据，而不是凭证、内部拓扑或
  未脱敏载荷。访问记录不引入新的会话概念。
- 成功零命中也需要整个查询范围的时效依据；无法证明足够新时，不能把旧观察当成当前事实

  可靠保存，再发布依赖它的结果。

  正常到期是生命周期结束，都不能以最新值或空历史掩盖。
- 源拒绝不能回退旧观察或占位值；动态过滤也不能先使用无权值。

## 选定方案 / 被否决方案

选定声明原点写在领域 Schema 的规范元数据、操作原点写在描述本身；否决整机一个统一资源
访问地址——它把接入方的责任挪到平台，并让声明失去可版本化的归属。选定统一保留观察记录：
latest-only 来源的接入方也获得有界重读，下游接口与依据语义不分叉，索引重建可直接重用
保留记录。选定 State 阶段纳入有界观察保留，接入方声明需求、平台设容量与保留上限，超出
能力明确拒绝；介质、默认期限、备份与容量不足行为仍由后续运行合同选定。

选定当前态优先、事件窗口其次、持续订阅单独设计的展开顺序；窗口需解释顺序、来源进度、
迟到和保留缺口，订阅需恢复、背压与取消，都不是 State 普通读取的数组模式，也不增加
Writer 的追加写面。上层物化的正确性有等价判据（含增量构建等于先构建再应用增量、窗口
拼接与一次性读取等价、折叠可复合、重放幂等），它们是检索与物化产品的合同，不进入仓协议
一致性检查。

## 方向性用例

### U1：查询当前失败的服务，包括零命中

运维人员得到匹配项，或得到能够支持“当前没有失败”的范围与时效依据。
丢通知或对账未完成时，不能把旧观察上的空结果当作当前结论。

### U2：区分业务空值、取值失败与没有取值能力

读取一个已知任务时，成功确认空值、runtime 故障和缺少取值入口可被区分。
失败不能制造业务缺失，缺能力不能改读通知正文或返回占位值。

### U3：通知丢失、重复或乱序后仍能恢复

后台在没有消费请求推动的情况下恢复实际状态，不改变知识仓版本。
有来源顺序证明时防止旧依据覆盖新依据；没有时如实限定承诺。

### U4：来源只能给最新值，仍能复核已交付的观察

来源已更新、服务已重启，使用者在保留期内仍能取得当时实际观察的值。
记录丢失或到期明确不可重读，不能用当前值冒充。

### U5：HEAD 前进后，Dataset 仍按原声明服务

消费方继续使用仍在服务的固定声明，后台维护不因 HEAD 改变而被遗忘。
旧 runtime 退役时明确迁移或不可用，不偷换新声明。

### U6：后台能看到，消费方未必能看到

后台身份可读但调用方未获源权时，不得交付受保护观察；撤权后的旧 pin 和记录也不放行。
显式共享观察须有独立、可解释的授权依据。

### U7：访问地址变化不扩大凭证范围

声明改到新目标或发生重定向时，不向不适用目标发送证明；
后台任务不因收到某个用户的通知而变成该用户。

### U8：持续更新不会掩盖维护成本和失败范围

接入方更新少量状态时能获得有界维护；单源失败不妨碍独立工作继续。
整体增量成本和故障隔离的判据由索引控制设计统一说明，不另立一套算法。

### U9：先看当前态，再看事件窗口

排障人员读取当前状态后，后续可请求有限窗口，并获知是否存在保留缺口。
持续订阅单独设计；需要沉淀排障结论时显式经 Writer 发布。
