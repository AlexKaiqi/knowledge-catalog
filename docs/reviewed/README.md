# 设计书

这是 docs 的现行设计书，按组件重构，不再按旧文章逐篇改写。验证、研究、规模与工程过程
资料同目录存放，按原有角色继续作为唯一权威；被替换的顶层旧设计稿已退出，不保留两套现行
解释。文档主题所有权与 Relation 以 [`docs/graph/`](../graph/) 为准；公开协议继续有效。
设计目标不表示实现已满足全部目标，可用范围见 [MVP 验收](mvp-acceptance.md)。

## 设计书只回答三件事

1. 组件解决什么问题，拥有什么，为什么在这里划边界。
2. 关键选择的理由、代价，以及尚需决定的事情。
3. 使用者在典型场景里应该看到什么，什么结果不可接受。

接口方法、消息字段、错误码、状态机、动作枚举、配置和查询语法用公开协议表达；设计书链接
源码，不另写一份自然语言规范。协议尚未选定时保留问题与所需保证，不能先在 Markdown
里造一个接口，也不能因为代码暂时没有实现而删掉设计目标。

## Object 与插件的四篇设计

按下面顺序阅读。四篇各自拥有对应的设计决定，源码、包 README 与 Conformance 拥有
具体可执行形状；设计选定不代表登记、路由或生产观察保留已实施。

| 问题 | 主设计文档 | 应能直接找到的内容 |
|---|---|---|
| 1. Object 的边界是什么，怎样描述、写入和访问 | [Object 架构与重构指南](object-refactor-guideline.md) | 表示组织、固定 Reader/Writer、要求→承诺及跨模块责任交接 |
| 2. 插件扩展体系要怎样重构 | [插件扩展体系重构](plugin-extension.md) | Repo 配置与写读作用域，两个插件的接点、payload 与结果采用；固定依据、逐值失败和身份传递的实际改接及验收 |
| 3. 声明式索引插件的契约、承诺和重构验收是什么 | [声明式索引](declarative-index.md) | 来源采用与组合查询、access、模块内控制/CLI 分工、六组先行用例及失败断言 |
| 4. 已有 LiveAccess 的重构目标与约束是什么 | [LiveAccess 插件重构](resource-access.md) | 独立目录、插件实现、无感取值、单值失败说明、身份认证自动传递与独立访问证据 |

具体索引维护和物理派生继续看[索引控制](index-control.md)，查询执行看[检索](retrieval.md)。
实施与验证顺序看[重构计划](object-refactor-plan.md)，不把所有实现步骤塞进这四篇的公共合同。

Repo 配置索引和访问插件，作用域同时覆盖该仓的写后维护和读取使用，Server 据此装配
执行。对象保存具体声明，Dataset 组合固定来源并呈现范围内的适用能力。首批假设插件
贡献没有冲突，不设计优先级或覆盖机制。系统保留当前授权、固定
范围、权威写入和交付；动态查询使用相容的来源/观察组合。Agent 从根 help 和统一插件
说明入口了解用法，具体执行沿已有任务，不操作内部实例目录。

通常先读总览，再读所改组件。章节拆分服务于独立评审，不对应新协议层、部署进程或 Go 包数。
索引声明、后台控制、请求检索分别展开；权限与 CLI 也各有产品决定，不能压进“服务负责”
一句话。Hook 与 Gate 同篇解释协作，但各自的决定依据和失败语义明确分开。

每篇需要讲清目标、责任交接、关键取舍、失败与恢复，以及可观察的方向性用例。
只出现一个名词、链接到代码，或声称“已并入某篇”，都不算接收了原设计。

[走查](walkthrough.md) 是操作与用例入口，不属于架构设计。它指向实际场景，不再维护第二份
命令清单或场景树。

## 设计、协议和证据分别在哪里

| 要找什么 | 去哪里 |
|---|---|
| 边界、理由、取舍、方向性用例 | 本设计书 |
| 可编译的接口与类型 | 各组件的公开 Go API |
| 序列化、CLI/HTTP 路由、配置、Schema 形状 | 对应注册表、解析器、协议 Schema 与 Conformance |
| 协议的用法和实现装配 | 邻近包 README；只解释用法，不形成另一套规格 |
| 必须禁止的行为 | [架构不变量索引](architecture-invariants.md)与架构守卫 |
| 场景前置、动作与实际断言 | [.data/scenes](../../.data/scenes/README.md) 和具名测试 |
| 实现缺口、执行结果与下一项工作 | [验收记录](mvp-acceptance.md)、[验证目录](test-catalog.md)、运行产物与 TASK |
| 外部调研、实验、容量资格 | [研究资料](ingestion-retrieval-research.md)、[规模演进](scale-architecture.md)等专项资料，按需阅读，不作为理解组件的前置 |

方向性用例留在有关组件的正文里，不复制详细测试步骤。用例与断言的关联继续由场景元数据
表达；文档重组不能被当作运行通过。

## 与旧 docs 的关系

重复段落可以合并，独立组件的设计不能为了减少篇数而消失。本轮保留现行设计、不更改公开
协议。原顶层旧稿的决策、否决、开放问题与用例已逐项交接进本目录各篇；执行序、差距与尚未
完成事项归根 [TASK.md](../../TASK.md) 与迁移记录，不另设设计篇。旧稿退出后不保留两套
现行解释；各篇按实际内容组织，文档图与链接检查沿[文档规范](../README.md)。

面向使用者的手册仍在 [product.html](../product.html)，它提供使用路径，不能替代
这些组件设计。
