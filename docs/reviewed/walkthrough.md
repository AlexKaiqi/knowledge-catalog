# 走查入口

走查帮助使用者从一个真实前态完成任务。设计书描述应当发生什么，可执行场景描述具体操作
与断言，运行产物说明实际发生了什么；三者不互相冒充。

本页只做导航。命令和字段以公开入口为准，完整步骤以场景为准；不再复制场景目录树、
命令清单、用例规范或详细测试名。

## 从任务找场景

| 任务 | 入口与关注点 |
|---|---|
| 初始化并确认系统知识 | `catalog-initialized`：库存、System 可读与不可写、身份和独立授权 |
| 接入来源并发布知识 | `repository-attached`：接入与发权分开，Schema 和实例发布、固定版本回读 |
| 发布供消费的 Dataset | `dataset-defined` 及其发布用例：范围、服务版切换、旧 pin 与撤权 |
| 发现并读取知识 | `projection-synced`、`dataset-query-principals-granted`：同一主体完成查询与回读 |
| 评审并采用变更 | `proposal-preview-created`：固定预览、证据与并发变化 |
| 完成业务消费任务 | `qinghe-knowledge-published`：清河茶铺实体、关系、语义与资源调用 |
| 动态状态和部署恢复 | 相关宿主的具名 Go evidence；不伪装成已构建的共享场景状态 |

场景的具体位置、可用 bundle 和构建前置，由
[场景视图](../../.data/scenes/README.md) 从清单生成。多个独立用例即使列在同一任务中，
也不依赖执行顺序传递授权、会话或验证报告。

## 设计中的用例怎样落下来

设计用例只写使用者、前提、操作意图、可观察结果和禁止结果。具体验证放在拥有语义的最低层，
跨组件旅程只证明组件组合后才出现的风险，不为每个 transport 复制全部用例。

已有断言可以在场景元数据中关联设计条目，关联说明只写实际证明的范围。没有实现的方向先
保留缺口，不建立没有构建过程的目录，也不写只有“命令成功”的 feature。

本目录尚未升格。现有产品视图仍使用现行文档 ID；正式替换时按图目录的替换计划迁移引用，
不让同一条用例在新旧文档中成为两套独立的完成声明。

## 怎样看证据

找到用例不等于执行通过。库存说明有哪些测试，局部断言说明覆盖了什么风险；
只有同一次运行的代码状态、环境、选择范围和原始结果，才能支持该次验证结论。

场景组织与执行规则见 [.data/scenes/README.md](../../.data/scenes/README.md)，
验证方法与现有缺口见 [TEST_CATALOG](test-catalog.md)。
本次设计重构不运行用例，不更新通过率，也不把新的设计承诺计为已交付能力。
