# Hook 与 Gate

平台既需要接入外部 CI、审批和通知，也需要判断某次合并是否已经获得足够证据。
Hook 负责在应用动作前后调用外部系统，Gate 负责检查精确候选已有的证据。
它们放在同一篇中解释协作，但不是同一种扩展机制，也不能相互替代。

## 三个独立的问题

| 边界 | 回答的问题 | 决定的依据 |
|---|---|---|
| 授权 | 谁现在可以请求这个动作 | 可信身份、资源与当前政策 |
| Gate | 这次治理跃迁是否具备所需证据 | 精确 Preview 与已保存的检查结果 |
| Hook | 动作前后是否调用外部逻辑 | 部署配置与已授权应用动作的生命周期 |

通过授权的人仍可能缺证据；外部脚本同意也不授予动作权限。失败要区分，不能把它们
统一描述成“审批未通过”，否则用户不知道应补权、补证据还是修复外部调用。

## Gate 检查精确预览，不临时运行业务检查

评审面对的是固定来源、候选变更和内容共同确定的 Preview，不是会移动的分支名字。
候选、目标或其它预览依据变化后，旧证据不能批准未经评审的新组合；合并仍需检查目标
没有漂移并通过条件推进，证据通过不能关闭并发保护。

Gate 要求哪些检查，由治理配置明确决定。调用者不能通过少传某项证据绕过清单。
核心只理解检查身份、结果与预览依据，不解释行业规则、审批角色的业务含义，也不托管
完整审批产品。外部系统负责运行自己的检查，再经受控入口记录结果。

记录一份外部结果不等于平台运行过检查；内建结构检查也不等于验证了业务正确性。
证据记录权限必须受控，不能让能发提案的人据此自动获得为所有套件背书的权利。

选择事先保存证据的代价是需要管理预览、证据和失效后的重新检查；收益是合并时能够复核
究竟批准了什么，不受临时脚本变化和外部系统在线与否影响。Gate 本身保持纯检查。

Gate 只控制提案合入发布目标的治理跃迁。普通 Writer 提交继续执行自身的结构、来源和
并发约束；动态观察与消费读取不额外挂 Gate。合并产生新的源提交，也不自动重新发布
已冻结的 Dataset，消费者采用更新仍由 Dataset 发布决定。

## Hook 扩展动作，不改变领域事实

Hook 挂在共享应用动作上，由 CLI 与 HTTP 共用执行时机。授权先成立，再进入动作生命周期；
Writer 和 Catalog 不导入业务脚本，也不因某个 transport 而产生不同的扩展行为。

动作之前的 Hook 可以作额外机械否决，不能修改变更内容、补造来源或代替 Schema 校验。
超时与拒绝都阻止动作落盘，不形成部分提交。前置脚本不应承担不可逆外部效果：此时
领域动作还可能失败，平台没有与外部系统组成事务。

动作之后的 Hook 发生在成功回执可靠保存以后，适合通知或触发外部工作。
投递失败进入重试，不能回滚提交，也不能把已成功发布的知识改报成未发布。
同一已接受命令的重放不再触发新一轮 Hook；但网络投递本身仍可能重试，接收方要按同一
事件依据防止重复效果，不能把这一设计说成跨系统恰好一次。

出站内容以主体、动作、资源、版本与回执等必要指针为主，正文由接收方在授权下回读。
脚本、地址与凭证是部署配置，不进入知识对象。一条动作触发一次，不能因涉及多个 Address
而放大成多次业务副作用。Hook 内不递归调用 Writer；后续知识修改应成为独立命令与来源链。

## 协作与恢复

典型协作是创建提案后通知 CI；CI 针对精确 Preview 检查并记录证据；合并时 Gate 检查已
保存的清单。前置合并 Hook 即使放行，也不能替代其中任何必需证据。

治理状态、配置、已接受回执和待投递工作要按各自耐久要求恢复。恢复投递不重复合并；
恢复提案也不假造丢失的证据。外部副作用失败独立可见，用户不必为修复通知而重复提交知识。

搜索、读取和交付遮罩不挂出站 Hook。外部资源取值走资源访问合同；源变化提示走 Observer；
内部 Snapshot 推进通知走投影控制接缝。这些机制都不能因为代码中也叫 hook 就共享配置
或交付承诺。外部直接推进源仓不经过 Writer，不会凭空产生 Writer 的用户出站事件。

## 方向性用例

### U1：审批完成后目标仓又变化

合并被拒绝，重新形成有效 Preview 与证据后才可继续。不能只核对分支名或沿用旧审批，
也不能撤销别人已经完成的提交。

### U2：必需检查缺了一项

即使用户有合并权、前置 Hook 放行，Gate 仍拒绝。少传证据标识不改变要求，
提示应明确缺的是哪类证据，而不是把用户引向重新登录。

### U3：前置脚本超时

动作未发布，目标保持原状。重试需要重新满足动作前提，不能拿脚本曾经开始执行当成通过。

### U4：提交成功，通知服务掉线

使用者得到真实的已接受结果，外部投递单独等待恢复。同命令重放返回同一结果，
不会重新提交或重新制造一次动作事件；投递重试由接收方幂等处理。

### U5：CLI 创建、HTTP 合并同一提案

两条入口使用相同的预览、授权、证据与动作时机，不能有一个入口漏过 Gate 或重复触发 Hook。

### U6：合并成功但 Dataset 仍在旧版

源仓有新的已发布知识，旧 Dataset 仍读原固定范围。采用更新需一次新的 Dataset 发布，
不能通过 Hook 副作用悄悄改变消费者版本。

## 协议入口

[ControlPlane](../../controlplane/README.md) 持有提案、预览、证据和合并编排，
[Gate](../../gate/README.md) 持有证据清单与检查，
[Hook](../../hook/README.md) 持有触发、投递和重试，
[Writer](../../knowledge/writer/README.md) 持有提交、并发与幂等保证。
具体动作、证据字段、配置、执行限制与状态转换留在这些合同中。

本文保留已有边界，不额外承诺跨系统事务、通用工作流或多副本投递一致性。
相应扩展需要独立决定其失败与恢复保证，不能借用“可插拔”一词省略。
