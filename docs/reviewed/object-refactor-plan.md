# 对象模块重构与验证计划

日期：2026-10-13。状态：执行与验证计划；共享工作树已有在途迁移，本文不确认整体出口。
Object 目标沿[对象模块重构 Guideline](object-refactor-guideline.md)，最小插件接入沿
[插件接入设计](plugin-extension.md)。本次执行按 Object 验收完成 → 插件层验收完成 →
声明式索引插件重构的顺序推进，各阶段分别记录完成分母；用例与基线先于对应实现。

## Goal

建立 Object 自身合同及跨模块兼容的验收依据，再按改动性质完成迁移。稳定身份、表示
组装、通用 Schema 校验、已记录来源、固定 Reader/Writer、受限读取、缓存、维护和任务服务各有
目标所有者及真实消费方；迁移保持既有公开能力与合同。对象 URN＋locator 的统一读写寻址、
指定内容读取及 CLI Affordance 是 Guideline 选定的产品目标，须独立实现和验证，不能
以目录迁移代替，也不把文档选定记为功能完成。

声明式索引与 Object 保持独立能力边界；本次实施等待 Object 和插件层的真实验收出口。
本文安排其依赖、验证和切换条件，
登记、选择、执行与生命周期设计由插件接入文档拥有；索引与 LiveAccess 的具体设计
各归现有 owner，不以第一种插件需要为理由预建完整宿主。

四项合同入口见[设计书](README.md)。Repo 保存插件配置，Server 按该仓作用域登记
并执行贡献，写后维护与读取使用共同生效；对象保存具体声明，Dataset 只组合。
首批假设插件贡献没有冲突，不设计优先级或覆盖机制。
LiveAccess 的登记内容与 read/invoke 路径已由资源访问篇选定，按实际切片另行实施，
不把文档已选定写成代码完成，也不要求它先实现索引角色。

R0～R3 表示合同与基线、必要行为修正、实际迁移或接入、最终证据四种工作性质。
Object、插件层和具体索引各自走完自己的出口，不能互相冒充完成；串行实施也不免除被触碰
消费合同的兼容验证。

## Non-Goals

- Object 切片包含已选目标所需代码、公开合同、回归和文档，CLI 同源出版随帮助更新；不另改完整系统出版流程或运行配置，不以进程内验收代替真实部署。
- 不重新设计 Snapshot/Dataset，不增加对象类型名单、第二身份或强制能力说明。
- 保持持久表示、既有 CLI/HTTP、Action、输出、授权、版本及写面；URN／locator
  读写寻址及其交互表达单列合同与回归，不混作目录搬迁或插件接入。
- 不定义插件内部算法或公共安装管理，不预设通用宿主、动态加载、热卸载、配置代际
  和全部 hook；具体需求及方案沿插件接入文档。
- 不复制协议、组装或字段解释，不用双实现、转发壳、放宽守卫或 skip 换绿。
- 不安装依赖、不启动服务、不清理共享在途工作区、不自动提交。

## 1. 依据与工作边界

2026-10-12 的依赖审阅显示，基础类型、固定读取、Schema、观察和查询类型贯穿原
Knowledge、Reader/Writer、索引及应用调用方。它说明迁移必须覆盖真实消费方，不证明
所有模块必须一起完成。历史包数及旧路径不能作为当前已迁移或验收的证据。

当前公开落点是 `object/`、`object/reader`、`object/writer`、`object/maintenance`、
`object/service`、`object/cli`、`object/client`、
`discovery/service`、`discovery/datasets` 与 `discovery/projection`。后续移动协议所有权
时移动同一份定义并同步调用方，不重新定义一套 ObjectID、Schema 或查询类型。
新增登记与目标选择仍是接入目标，路径存在不表示它们已实现。

| 工作 | 拥有的目标 | 不能作为其完成条件 |
|---|---|---|
| Object 重构 | 基础能力独立、混合职责拆出、公开依赖及上层合同保持 | 索引三项贡献已登记、LiveAccess 已完成内部重构或通用宿主已建立 |
| 声明式索引最小接入 | 真实实例被明确选择并参与现有任务，保留能力与失败保证 | 完整 Object 迁移、第二种能力或所有插件管理已完成 |
| 索引与 LiveAccess 专项 | 各自 owner 的声明、执行、维护及恢复保证 | 本计划的目录目标或其他切片的绿色 |

场景、组件、架构及 transport 入口可以提前建立行为证据。修改协议旅程用例前读
`.data/scenes/README.md`，复用实际共享前态与宿主 `_materials/`，不另建平行场景树。
已有覆盖不限制目标；缺失的 Oracle 提前补，不在迁移后迎合实现改预期。

## 2. 方案比较与选择

| 方案 | 判断 |
|---|---|
| 按目录或层级逐一完成，再开始下一模块 | 当前混合职责与公共类型跨旧包；机械顺序会增加临时接线和守卫，不能凭层级保证可验证 |
| Object、插件框架及全部能力一次切换，最后补测试 | 混合行为变化和结构问题，扩大分母且难判失败原因，否决 |
| 每个真实切片先定验收，修正必要行为，再切换及验收 | Object 与插件接入可各自交付；触碰合同共同验证，选定 |

本次按用户选定顺序串行实施，不把执行等待改成 Object 基础读写对插件的依赖：

| 阶段 | 开始条件 | 完成依据 |
|---|---|---|
| Object | 已选定用例与有效基线 | Guideline 的目标读写、寻址、Schema、范围及所属 CLI 实际落地，受影响消费合同与工程门禁通过 |
| 插件层 | Object 实现及验收完成 | 按插件 owner 落实共同登记、选择、说明、生产调用与生命周期；有真实贡献通过接缝执行，注册器单测或目录存在不算完成 |
| 声明式索引插件 | Object 与插件层均验收完成 | 具体实现集中于 `declarativeindex/`，U1～U6、旧查询/准备/维护合同及适用真实引擎验收通过 |

阶段完成以当前实现及同一候选的验证证据判断，用例准备或文档完成不触发下一阶段。
各模块在自己的 `cli/` 同源维护命令贡献、参数校验、执行、输出、帮助和例子；统一 KC CLI 只
静态装配贡献、绑定参数与上下文、注入认证 SDK 并编码结果。Object 的全部 CLI 及对根帮助、
既有命令的扩展唯一归 `object/cli/`，typed SDK 归 `object/client/`；不把规则复制回宿主。
确需改持久数据、公开语义或权限时先拆为行为变更，不再称为纯组织调整。

## 3. R0：建立合同、验收与有效基线

重构前先固定 Guideline 的 U1～U12 与[具体用例表](test-catalog.md#215-对象模块重构验收)。
逐项记录可重建前态、动作、准确结果／拒绝后态、拥有断言的最低层、已有入口和明确缺口，
并说明删去后会漏掉哪种独立回归。新接口未落地时先写可证伪规格及接入位置，不创建临时
API、不可执行 feature 或 skip；已有入口能证明的风险先补断言并执行。
用例规格准备、可执行断言存在、保持行为基线通过和新目标实现通过分别记录；已有红例
先进入 R1，不在红例未处置时开始对应结构切换，也不能因已有测试数量多省略新入口 Oracle。

**前置：** 核对本批实际消费的公开合同、固定依据、Schema 采用、范围及当前工作树
变化。记录源码/环境与执行范围，依赖发生变化时重新取证，不覆盖并行修改。

| 工作 | Object 切片 | 插件接入切片 |
|---|---|---|
| 列目标和分母 | 自身合同、拆出职责、真实调用方及目标依赖 | 插件接入文档中真实消费角色、目标选用及生命周期 |
| 建行为基线 | 身份/地址、组装、Schema、固定读写、CAS/回执、Dataset 辅助范围 | 现有查询、固定服务准备、推进维护及对应失败后态 |
| 补缺失证据 | 公开入口和拒绝后态，不仅是包名或桩调用 | 验证真实索引实例及选用，不能只检查登记条目存在 |
| 列结构断言 | Object 公开入口、禁止依赖及已拆出混合职责 | 消费方、实现与宿主依赖正确，真实调用使用选定实现 |
| 保存有效基线 | 同源保持行为及受影响正式合同通过 | 基线可先准备，实施仍遵守 Object 与插件层的阶段出口 |

Object 基线至少覆盖稳定身份与路径迁移、完整对象与单 Address 读取、同版本组装、
实际采用 Schema、更新继承约束、来源与历史、单仓 Writer、幂等/CAS、失败不推进、
当前权限及 Dataset 的正文和辅助材料范围。

新增访问目标另列 Oracle：对象 URN 与路径移动后仍指认同一对象；locator 从内容根
以 JSON Pointer 选择 Member 或任意深层节点，转义与空定位可复核，合法空值与缺失可区分，结果只含
所选内容及依据。当前权限、Dataset 及解释材料范围均不得扩大；选择范围进入读取
计划，验证无关单元不读取，单元内部的细粒度 I/O 按实际提供方能力说明。
Repo／Dataset 均可作为读取语境，对象身份始终保留来源 Repo，跨仓同名不混淆。
Dataset 发布固定来源 commit，额外版本不一致须拒绝；源 HEAD 推进后旧发布仍返回
原值，根读取不得补齐范围外材料或将不完整对象冒充完整。对象写入唯一 Repo，
Dataset 新发布采用来源引用与范围，两项结果分别确认。
CLI 独立走读只读 `kc help` 本身，即能理解 Object／object_id、Aspect、Member、Address、
Relation 等概念、联系、基础能力与例子，再按需要进入既有叶子帮助；没有登录态、
Server 配置或系统仓／概念标识也能完成这一步，不发业务请求。需要版本化定义时再沿帮助
进入系统仓，核对说明版本及其与已实现合同／新增目标的一致性。
随后须仅沿真实帮助完成整对象／指定数据读取、创建、更新和删除，能够理解
输入、前提、成功结果、副作用及失败恢复；基本读写只呈现对象 URN＋locator，不保留分列 Address 输入。
Object Affordance 的分母按能力所有权确定，不按“操作对象”或现有 CLI 分组确定。
每项须兑现 Object 的身份、固定声明读写及历史保证；检索发现、外部执行、交付发布和
治理不计入 Object 完成。基础任务须能在未装配发现、当前态或治理扩展时独立采用。
基本能力包含 Schema 列举与描述；目录预览、目录提交和命令回执沿 CLI 任务验收，不单列 Object Affordance。Object Writer 的对象校验、单仓原子发布及幂等恢复保证继续验证；不外呼不证明专属声明解释归 Object。
同一对象在两个固定版本中的内容对照与草稿目录发布预览分别验证，不能用当前 `kc diff --dir` 冒充对象差异 CLI；目录发布编排的完整出口不计入 Object 自身分母。
读取走读须直接取得固定版本及相应维护内容的摘要，再据此更新；用户无需先运行独立 resolve。覆盖读取后他人更新导致并发拒绝、深字段读取采用所属维护内容摘要，以及相同固定版本的依据一致。当前 READ 已保留引用、选择位置、实际维护坐标、版本、摘要和单元声明；旧 resolve 的产品形状及内部摘要查询兼容合同继续有效。
READ／PUT／REMOVE 走读须使用同一种对象 URN＋locator，分别验证整体值、Aspect、Member，
不要求调用方拆成 Address 参数，分列寻址明确拒绝。按实际维护模型确定目标，不能从路径
层数推断粒度；组合对象不能整体 PUT 覆盖，空 locator 的 REMOVE 删除整个对象。
集合及深字段删除语义另行选定，旧 Aspect REMOVE 的限制不得冒充新引用合同，深 locator
本身不产生字段 PATCH。
回执按原写入命令恢复，log 与 provenance 分别给出对象修订和已保存来源。

跨模块基线按实际触碰确定：Object 的 Schema/读取变化会影响索引候选回读；来源声明
变化会影响 LiveAccess 的声明解析。保留原查询与观察依据，不把扩展就绪当作基础发布
条件。新架构断言在切换批次加入，不用新包不存在证明原业务错误。
触碰目录发布流程时，独立验证草稿预览、缺文件不推导删除与显式批次发布；应用负责目录
处理和发布编排，Object Writer 校验及 Snapshot 提交保证仍必经，不以范围拆出绕过知识校验。

插件接入的具体验证观察沿[插件接入设计](plugin-extension.md)，查询、索引维护和
LiveAccess 的 Oracle 沿各自 owner。现有可信回读结果口不能直接作为任意第三方实现
的安全候选边界；开放新实现前应先选定共同必经边界并取得越界反例。

**出口：** 本批保持行为有实际通过基线，必要变化和缺失证据分别列明；测试存在、
静态组织检查和历史绿色都不替代本次业务基线。

## 4. R1：必要行为变化单独取证

只修复本切片实际触碰的行为，先保留反例，再实施并跑到绿。没有行为变化就进入 R2，
不为凑阶段制造修正；未触碰历史债不成为所有切片的前置。

| 历史信号 | 当前判定与处置 | 触发条件 |
|---|---|---|
| 空/空白 ObjectID 写入检查不足 | 当前 Address 已有拒绝检查；保留为所有实际写通道的回归复核，不再断言缺实现 | 基本写面改变或其实际通道迁移 |
| Repository 携带完整 Snapshot Store | 当前 Repository 已收窄为只读合同；验证公开依赖和调用方，不能按旧记录重做接口 | Reader/Writer 与装配端口切换 |
| 采用旧 Schema pin 与当前 access 编译可能混用 | 复核真实采用、字段资格、候选及回读是否同依据；并行修正不计本轮完成 | Object Schema/读取或索引实际采用链被触碰 |
| 固定 Dataset 恢复受 HEAD 门槛及逐仓进度约束 | 固定需求调度直接按已接受依据；逐 basis 继续并独立核验，补 HEAD 不可读但固定 commit 保留、同仓多版本一项失败的反例 | 多实例需求分区与 Dataset 恢复接线 |
| 动态恢复只按 HEAD，notice 请求改写后台来源上下文 | State 需求采用实际 HEAD 与 Dataset 固定声明依据；后台来源独立装配，请求仅用于本次执行，补两个身份及固定声明的反例 | 注册上下文、State 维护与 notice 调用改接 |

LiveAccess 值/basis 校验、实际访问证据和 HTTP 委托边界的历史信号保存在 TASK；其保证
沿[资源访问](resource-access.md)。只有触碰该路径并确认缺口时，才在对应专项切片
修复，既不是静态索引接入也不是 Object 目录移动的无条件前置。

**出口：** 必要行为改变有独立通过证据，保持行为仍通过；新的基线供本批 R2 使用。

## 5. R2：Object 迁移与独立插件接入

**前置：** 本批 R0/R1 可用，公开合同、真实调用方及目标依赖已明确。开始切换时
加入触碰范围的架构断言，公共类型、实现、测试和工具同步迁移，不先开放全部目录。

### Object 自身迁移

| 切面 | 迁移要求 | 完成观察 |
|---|---|---|
| 根合同与唯一语义 | 身份、Address、组装、Schema、Relation、来源和变更同归 Object | 单一类型与语义，不依赖索引、来源 runtime 或完整出版聚合 |
| 固定 Reader/Writer 与 Format | 通过所需 Snapshot 窄口，写入仍经唯一 Writer | 读口不带写权限，固定读回、Schema、CAS、回执与失败原子性保持 |
| 统一引用与内容读写 | READ／PUT／REMOVE 只用对象 URN 与 locator；读取解析为 Repo／Dataset 语境、固定依据及有界计划，写入解析为唯一 Repo、维护范围与 Writer 变更，分列寻址在实际入口拒绝 | 真实入口读回对象、Member 与深字段，按同一引用创建／替换／删除选定维护内容；拒绝旧输入不触碰正文和 ref，保留来源身份、固定依据、Schema、CAS、幂等与失败原子性，不扩大授权或材料范围 |
| 来源与能力混合代码拆出 | 声明保存、固定读取及通用结构校验留 Object；Binding 等专属语义解释交所属能力，即使只读、不外呼也不归基础 Object | 未装配能力插件仍可固定读写声明；原专属入口兼容，唯一解释实现及调用方随同迁移，实际观察不被当正文，不隐式外呼或全仓补读 |
| Cache 与 Maintenance | Reader 消费 Hydrator；共享协调不持引擎或 SourceLookup | 缓存隔离、范围和消费者独立恢复保持，维护不变成消费枚举 |
| Object Service | 可信上下文、当前授权、固定范围/依据、交付及证据归任务服务 | CLI/HTTP 共享规则，宿主只构造、注入与启停 |
| Object Affordance 与 CLI | 全部 Object 叶子及根帮助／既有命令扩展同归 `object/cli/`，唯一维护贡献、校验、帮助、执行和产品输出；`object/client/` 提供独立 typed SDK，宿主仅装配与注入 | 真实帮助指导同引用读改删；静态贡献及 SDK 依赖守卫阻止规则返回中央宿主，旧叶子输出／Action 及目录流程兼容，不以登记存在代替实际执行 |
| 可信数据与完整出版 | 基础校验依赖必要可信数据，完整出版聚合归上层 | Writer 不反向导入聚合，系统显式出版与完整核对合同保持 |
| 真实调用方与公开入口 | README、Conformance、testkit、场景、工具和守卫随同切换 | 无循环、深层访问、签名泄漏、双实现及兼容转发壳 |

Discovery 内部编译/provider 拆分、LiveAccess 内部执行与动态桥接，不在这里规定
实现步骤。Object 必须向它们提供稳定公开合同；需要联合移动某个类型或依赖时，只
把该实际依赖纳入本批，不以此扩张成所有外部模块同时完成。

当前 Object 候选已实现统一引用、JSON Pointer 计划读、维护目标映射、完整 Schema 描述、
独立 CLI／SDK 与本地根模型帮助。U5 根删除、U6 最终表示冲突和 U12 实际只读返回的原红例
保留原 Oracle 并已修复；新增回归验证真实 CLI→HTTP 读改删、同 Aspect 授权、旧 Dataset
来源固定及拒绝写源仓、真实 Writer 丢响应后仅恢复原命令。多单元 Source／Derivation
分别保留固定信封，缓存与输出不合并来源；Schema 演进与引用者查询使用有界元数据。
这些是实现与具名断言的当前状态，最终出口仍按 R3 保存同一候选的正式运行证据。

统一 Dataset 读取保留原逻辑 State 效果，专属解释与执行继续归 LiveAccess；其观察依据
不同于固定声明及可写摘要。虚拟 Bound Aspect 当前需范围内已出版的对象类型依据和 Schema，
缺材料／runtime 明确拒绝，不据 locator 发明切面。旧路径派生索引缺维护坐标时报告能力不足，
通过显式重建恢复；读取请求不全扫正文。上述兼容反例与 Object 组件、架构和 transport
证据分别关联到用例表，真实部署依其独立入口验收。

### 插件层完成后接入声明式索引

按[插件接入设计](plugin-extension.md)完成下面已经选定的切片，登记单位、目标规则与
维护分路不再留给代码实施自行决定。接入算法不在本计划重复；Schema access 及查询沿
[声明式索引](declarative-index.md)与[检索](retrieval.md)，维护、准备、就绪和恢复沿
[索引控制](index-control.md)。

| 实际工作 | 必须出现的结果 |
|---|---|
| 静态插件入口与登记上下文 | 插件自己构造 Index/Controller，登记服务、准备、推进及启停；消费侧原子接纳一个完整实例 |
| Repo 配置与写读作用域 | Repo 保存启用配置，Server 据此登记运行贡献；写后维护、请求、关系、运维与逐来源准备均使用该仓贡献，不参与未配置仓。Dataset 沿已有来源映射调用，不另绑定或覆盖，不读取隐藏全局 Index |
| 来源能力与说明呈现 | 插件登记 Affordance，根 help 解释 Object 基础能力并指向统一插件说明读取；Dataset 概览汇总范围内来源的适用能力，说明读取不运行真实能力 |
| 跨来源查询与准备 | 冻结候选逐来源准备，全部必需项成功才接受知识服务版；组合查询保持范围/总预算、具体支持、相容排序和完整性，续页保留各来源实际实例与依据 |
| 系统服务需求与两路维护 | HEAD 推进与 Dataset 固定来源恢复都按来源 Repo 配置路由，各用自己的知识依据；固定恢复不以 HEAD 为前置，State 覆盖有效固定声明；新库存、历史 pending 与提示路由遵守实际需求 |
| 资源与续页身份 | 接纳旧资源的实例保留续页核验，重新装配不转移资源归属；其他实例物理定位隔离，仓/Dataset 搜索、关系、遍历全部续页层核验执行身份 |
| 生命周期及消费兼容 | 完整装配后启动，失败逆序释放，在途请求和维护结束后关闭；原可选查询能力和全部既有索引任务保持 |

Object 和插件层的阶段出口均通过后开展，先复核已写用例与当前依赖基线。涉及同一
合同仍保持一份定义并重新验证。首个接入不能仅注册物理引擎
就宣称插件完成，也不要求先接 LiveAccess 或完整公共安装管理。

**出口：** 本批真实实现成立，全包编译、触碰架构、受影响测试和必要集成通过。
Object 与接入分别记录出口；局部绿不冒充整体绿。只回退自己的修改，不 reset/clean/
stash 共享工作区，不自动提交。

## 6. R3：分别核对分母与跨模块兼容

**前置：** 本批 R2 完成，原业务 Oracle 保留；最终证据绑定同一候选及环境。

| 验收范围 | 必须证明 | 不代表 |
|---|---|---|
| Object 自身 | Guideline 的合同、职责、依赖及完成条件成立 | 插件登记/安装或外部能力专项已完成 |
| Object 消费兼容 | 受影响索引、LiveAccess、系统出版和其他实际调用方保留原依据、授权、范围和结果 | 所有未触碰能力必须同时重构 |
| 索引接入 | 接入文档的真实选用、任务执行、失败、恢复与关闭完整验证 | 完整 Object 或通用宿主完成 |
| 真实部署 | 对应部署合同要求的实际运行链路 | 进程内夹具或静态闸已经证明部署 |

| 入口 | 证明范围 |
|---|---|
| `make typecheck` | 全包与调用方编译 |
| 架构合同 / `make test-boundary` | 所有权、真实 imports、公开入口及依赖方向 |
| `make test` | lakeFS 进程内夹具的普通/索引场景，索引使用真实 OpenSearch |
| `make test-contracts` | 正式组件、架构、应用与 transport 合同组合 |
| 受影响 race | 本批触碰的 Writer、缓存、消费者或登记/选择/关闭并发 |
| `make check-docs`、`make quality` | 文档与工程质量闸，不证明业务或部署 |
| `make deploy-local-scenes` 及对应当前态部署入口 | 独立真实部署，按入口合同使用已有环境 |

R2 编译恢复后尽早运行必要检查；R3 核对同一最终候选的完整证据。保持业务观察、
固定引用内容、范围和失败后态，不能为了前后等价归一化掉错误仓、对象或版本。
真实部署缺配置时不自动重建环境，不将未执行记为通过。

必需出口 fail/skip 均不通过，不同运行的绿色不拼接为整批绿色。三个阶段分别列
实现范围、已验证范围、保留的旧包及未完成目标；无新改动和未决
问题时不重复已通过检查。后续第二能力及新的公共管理面各有独立分母。

## 选定方案 / 被否决方案

选定每个切片按 R0 建立合同/基线、R1 修复必要行为、R2 迁移或实际接入、R3 取得
完整证据。Object 自身与最小索引接入各有分母，协议可先被消费，触碰范围共同验证。

保留转发壳，不在行为变化后补迎合实现的测试。
