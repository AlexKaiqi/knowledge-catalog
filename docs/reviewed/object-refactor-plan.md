# 对象模块重构与验证计划

日期：2026-10-13。状态：计划；尚未实施。此前按上层/下层划分的 P0～P7 顺序撤回，
以本篇的 R0～R3 为唯一执行路线。目标目录、核心与插件边界、PluginHost 及流程接缝沿
[对象模块重构 Guideline](object-refactor-guideline.md)，具体扩展设计见其 §6.1～§6.7。

## Goal

先定义并建立可执行的验收依据，再按改动性质组织重构。Object 基座、PluginHost、通用
能力分派、声明式索引、LiveAccess 和产品接入统一切换；必要行为修复和新增扩展体系的
行为分别登记、验证。每项结论有对应的业务观察或架构断言，不按目录数量制造实施阶段。

本篇拥有执行路线、验证准备和切换条件。协议及能力语义仍由各主题 owner 拥有，测试
组织、证据与用例树沿既有验证合同；已有覆盖不限制目标，缺少的证据应提前补齐。

## Non-Goals

- 本轮只评估和修订计划，不执行代码迁移、用例新增、缺陷修复或真实部署。
- 不扩展对象类型名单、统一资源包装、必填 definition、Interface 或索引发布门槛。
- 不实现媒体处理、模块执行、业务表查询或新的租约、见证与释放能力。
- 不以插件化改变既有存储格式、持久对象/Schema 身份、CLI Affordance、Action、返回
  形状、路由、授权和版本保证；确需改变的行为必须先单列合同和回归，不夹在目录搬迁中。
- 新插件管理命令、HTTP 入口和管理权限在实现前独立选定合同；本篇不编造 argv、授权
  动作或安装字段。默认 binding 从已有显式部署装配恢复原行为，不等待这些新入口；
  知识声明仅参与固定合同解析与支持匹配，不隐式创建安装。
- 不新增通用 Affordance Schema、Member 读 ACL 或发布业务校验能力；不自动合并多个
  provider，不以 Repo/Dataset 的组合关系推导插件继承或权限继承。
- 不重做 Snapshot 在途工作，不使用兼容壳或双实现，不削弱断言、不用 skip 换绿。
- 不为取证以外的目的启动环境，不安装依赖，不清盘，不自动提交。

## 1. 选择依据

### 实际依赖影响面

2026-10-12 以 `go list -json ./...` 枚举了 60 个生产包。下列为直接 import 的生产
消费方包数，不是耦合度门禁、覆盖率或运行结果；实现变动后须重算。

| 当前包 | 直接生产消费方 |
|---|---:|
| `knowledge` | 25 |
| `knowledge/reader` | 7 |
| `knowledge/writer` | 6 |
| `knowledge/serving` | 5 |
| `retrieval` | 9 |
| `index` | 5 |
| `knowledgeapp` | 1 |
| `internal/repofile` | 6 |

仅凭包数不能证明必须一次完成。结合具体代码，可以确定：基础类型、固定读取、能力
解析结果、观察依据和查询类型贯穿同一批调用方；`InterfaceCall` 直接持有 Reader
Serving 和其解析结果，查询 residual 依赖物理编译，Writer 依赖完整系统出版。
旧模块不是与新模块一一对应的独立边界，逐目录搬迁会增加中间接口、重复接线和临时
架构规则。根类型及其所有调用方的切换本身也必须保持同一类型身份。

### 验证框架可承接什么

场景树已具备冻结共享前态、隔离 probe、公开操作和后态 Oracle；可在原实现上提前补
新的发布发现用例，不必等目标包创建。Server/typed Client 验证可独立于内部包名。
2026-10-12 的 views、product、states 三项静态检查通过，仅说明组织合同，不代表
业务测试通过，也不作为“只能使用已有用例”的理由。

验证须按性质拆开：

| 证据 | 怎样提前准备 | 怎样判断 |
|---|---|---|
| 保持的业务行为 | 在旧实现上补公共入口、固定引用与失败后态用例，取得通过基线 | 重构后使用相同输入和业务 Oracle，不能为了新实现改预期 |
| 确需改变的行为 | 先补反例，确认旧实现失败，再作独立修正 | 红后绿；新的行为成为结构迁移的基线 |
| 新目标结构 | 先列依赖、所有权和公开深度断言；在结构切换批次先证明旧布局不符合 | 迁移后全绿；不能拿新包不存在当作旧实现业务失败 |

`make test` 实际只跑 Product/MetricPermission 两组场景；独立 Go evidence、组件、架构
与 transport 合同有另外的正式入口。应按目标选择并补充这些证据，不能只看一棵树或
一个命令的绿色。当前已有用例影响复用成本，不决定目标或实施顺序。

## 2. 方案比较与选择

| 方案 | 收益 | 实际代价与判断 |
|---|---|---|
| 逐层完成，再迁移另一层 | 分阶段 diff 较小 | 当前职责跨旧包；共享类型和调用方多，中间组织增加重复适配及守卫。不能仅因“从下往上”就认为容易验证 |
| 行为修正与全部结构一起改，最后才补测试 | 组织可一次到位 | 失败难分为旧缺陷、行为变化或搬迁错误；验收预期还可能迎合实现，否决 |
| 提前建立验收，行为变化单独处理，再统一切换结构 | 保持一套类型和最终结构，不经营过渡 API；失败类别清楚 | 结构 diff 较广，但有稳定行为基线及目标架构断言；选定 |

选择的是一次完整的**组织迁移及已列合同的扩展体系落地**，不是一次性混合所有变化，
也不是写完才第一次验证。PluginHost 是本轮已选定目标，不能以旧指南的当轮 Non-Goal
否决；新增运行行为仍须在 R0 列明，不伪装成文件移动。
实现时按内部工作清单逐项推进、尽早恢复全包编译并运行定向回归；不要求每移一个文件就
形成可交付中间版本。R2 只有完整结构及全部必需合同通过后才算完成。

若 R0/R1 发现需要改变持久数据、公开协议、授权或无法证明的查询语义，先将其拆为独立
行为变更；不得继续把它当成纯组织迁移。没有上述变化时，不为机械路径切换再强拆八个阶段。

## 3. R0：先建立验收与有效基线

**前置：** 核对将采用的 Snapshot 公共入口及其在途变化，固定本次源码和测试环境。
无需等待不相关的全部 Console 工作，但不在验证期间继续修改依赖的公共边界。

| 批次 | 工作 | 完成依据 |
|---|---|---|
| R0.1 | 从目标设计列保持行为、预期行为变化和目标结构；登记证据位置及 Oracle | 不以现有实现或覆盖反向裁决目标；每项必需保证有可执行判定 |
| R0.2 | 复用用例树，提前补图片、分散模块、外部表及边界用例 | 独立于旧数仓故事和新包名；经公开 Writer/Server 发布、发现和固定读回 |
| R0.3 | 补充 PluginHost、观察依据、缓存/消费者、组件故障和架构验收设计 | 区分 package、binding、request view；真实执行、作用域、注册冲突、失败与释放有可观察判定 |
| R0.4 | 执行保持行为的测试及原正式合同，保存同源基线 | 当前失败、未知和外部未执行项分别列明，不能当作重构失败或成功 |
| R0.5 | 单列扩展体系新增行为及有界 CLI 调整合同 | 注册与生命周期、默认 bindings、描述可见性及管理入口各有 owner；未选定公开命令和权限不提前实现 |

提前补的重点如下，不另建用例树或平行权威清单：

- 三类对象具有业务身份和普通知识切面；不靠文件扩展名或目录产生身份，组成引用不触发
  跨仓组装；缺 Interface、处理器或外部在线状态仍可发布声明。
- 字段 access 为唯一查询声明；搜到后同依据读回，旧 pin、路径移动和同 ID 跨仓不误合并。
- 声明适用但缺值、未就绪、来源失败和成功零结果分别观察；无能力不扫描兜底。
- 固定读取、授权撤销、Dataset 范围、分页和交付保持；拒绝写入后观察 HEAD、正文与权限。
- 普通 Interface 与 LiveAccess 分派各自正确，不调用无关来源；声明、Handler 和授权分别
  成立；调用证据及结果校验保留。
- 系统空仓显式出版、已占用精确匹配和启动仅核对；共享消费者独立进度，物理就绪不由
  工作账推导；动态值先存后发，缓存不能替代权限或观察依据。
- package 定义、作用域 binding 与请求 view 不混作一份可变注册表；同一 package 的多个
  bindings 不串配置、资源或权限。重复注册、缺依赖和实现选择歧义分别可判定；不按加载
  顺序择优，不自动扇出到多个候选 provider。
- 插件接收系统已固定的版本与受限读口；Dataset 的 Items、辅助 Schema/Binding 读取及
  旧 pin 都不扩大范围。Repo 安装不授予 Dataset 权，Dataset 安装不授予来源整仓权。
  后台维护身份与请求主体分别验证，不把维护者可见变成消费者可见。
- 默认 bindings 保留现有 CLI/HTTP 行为；声明式索引未就绪不阻断基本读写，普通 Handler
  不要求 LiveAccess 来源端口，插件输出不能跳过同依据回读、当前授权或交付证据。
- README Discover 一类第二种候选实现按明确对象地址和已有 Schema access 取值，不从
  `README.md` 路径制造知识身份；发布材料未被 Dataset 选入时不回源补齐。它与索引实现
  的选择或冲突有明确合同，不把安装成功解释为必须同时调用两者。
- 现有动作 pre、内部 Snapshot 推进、冻结 Dataset 的能力准备和成功后的 post 各按自身
  顺序及失败语义验证。pre 当前早于 CommitIntent 固定 base/CAS，不能改名为冻结候选
  检查；推进提示与成功回执通知不合并，已接受发布不因插件后续失败被撤销。
- 撤销注册、取消在途工作、等待资源关闭及依赖失效均有故障证据；当前 append-only
  listener、Start 前冻结的 Consumer 注册不能直接算作已支持插件独立卸载。
- CLI 的路径、Action、用途、用法、失败帮助和已有 describe 与公开合同对账。保留
  `invoke --implementation` 的通用分派及省略实现时的旧调用，不依据存量说明遗漏收窄
  能力；CLI、内部应用操作及 typed HTTP 三张表仍分别验证边界。

新增 Host 行为与默认行为保持分别取证。旧实现没有 Host 只说明新结构未成立，不能当作
旧业务失败；默认 binding 的输出、授权与版本基线必须在旧入口取得。公开插件管理能力
若尚未选定，登记其待选合同和分母，不让它成为基本迁移的隐式前提。

每个强类型 stage 在 R0 指定输入/输出 owner、触发位置、同步顺序或并发资格、超时取消、
输出校验与失败承诺。服务返回、机械否决、受限变换和事实通知分别判定；首个 listener
放行不能替代当前授权，通知失败不能改写已接受结果。help 的解释更新先保持既有调用；
describe 若需新增可见内容，先独立说明依据、范围与返回合同，不借展示扩充管理能力。

修改场景前先读 `.data/scenes/README.md`。probe 放最近的真实共享前态，只有实际复用
构建条件才新增状态；组件与故障注入用 Go evidence，不用一条长场景承担全部风险。
用例材料归宿主 `_materials/`，Schema 仍经 Writer，不引入生产领域处理器。

**出口：** 必需保持行为有实际通过的基线；缺失证据已经补齐或有明确阻断，不把结构
迁移之后才写业务 Oracle 作为计划。目标架构断言在 R2 批次加入，先红再绿，不以 skip
或放宽旧守卫维持基线。

## 4. R1：单独完成必要行为修正

**前置：** R0 的目标、输入及 Oracle。每项修正先红后绿，完成一项再叠加下一项。

| 项目 | 已定位的信号 | 验证重点 |
|---|---|---|
| 非空对象身份 | `knowledge/address.go` 的写校验没有完整拒绝空/空白 ObjectID | 所有实际受影响写通道明确拒绝且不推进 HEAD；有效身份、路径移动不受影响 |
| 实际 Schema 采用 | Reader 可解释显式旧 pin，索引 spec 按当前 Schema 集编译且仅按 ID 匹配 | 旧 pin 与新版 access 分歧反例；字段资格、编译、补判及回读同依据 |

这里记录的是需通过回归复核和修正的风险，不是本轮已修复的结论；不预先指定新的公开
字段、第二种索引声明或算法形态。新发现的业务差异按同一规则列项，不混进搬迁 diff。

### LiveAccess 运行行为债与触发条件

下列信号按现有访问、观察与权限 owner 的保证登记。R0 先复核当前工作树和反例，确认
缺口后在 R1 独立修复；不能把新增 Host 或路径移动当作风险已经消失。

| 位置 | 信号 | 判定与处置 | 触发条件 |
|---|---|---|---|
| `knowledge/serving/live_access.go`、`serving.go` 与 `state_lookup.go` | 通用 LiveAccess、Bound State 与直接 access 的值和 basis 核验分散，完整包络不等于采用结构及固定声明关联已核验 | 统一合法观察依据、实际采用值结构与声明关联的核验；补伪造/不匹配依据及结构不合规值的拒绝反例，保留合法空值语义，不预设新字段 | LiveAccess 注册、来源返回值及按观察依据回读切换前 |
| `invocation/verbs_resource.go` 的 `access` 与访问证据编排 | 直接返回 bindings/observations 的取值路径未完整进入与 invoke 对齐的实际访问证据链 | 在所属任务服务记录真实主体、固定声明、实际观察及成功/失败结果；保持公开 access 返回形状，不以请求完成日志替代访问证据 | access 服务迁移和默认 binding 切换前 |
| `knowledge/serving/state_lookup.go` 的 HTTP 出站装配与调用方证明转发 | 声明 origin 和通用 HTTP client 不足以证明目标信任、证明适用与重定向后的委托边界 | 由宿主注入目标/证明政策，来源适配执行目标与重定向检查；补新地址、跨目标重定向及源拒绝反例，不回退旧观察，不把凭证写入知识或证据 | LiveAccess HTTP adapter 归属切换或经 Host 装配出站证明前 |

另纠正此前一项判断：`ResourceLookup` 会返回注入的 lookup 或构造 HTTP 适配器，本身
不访问外部源；`WithLiveAccess` 优先匹配已安装 Handler。当前已有独立 Echo 的正式
调用测试。因此通用调用中出现 State 适配器属于结构耦合，不能直接判作“普通能力无法
调用”的行为缺陷。无需来源访问的契约可以提前补强，但授权动作不因拆包自动改变。

**出口：** 确需改变的行为有独立通过证据，保持行为的合同仍通过；新的基线供 R2 使用。
没有行为变化的项目只进入 R2，不为凑阶段创造修正。

## 5. R2：一次统一切换结构

**前置：** R0/R1 的验收与基线可用，目标职责、最终公开路径和需采用的 Snapshot 入口
确定。开始时加入目标架构断言，保留它们在旧布局上的失败证据。

这一阶段以一套类型、实现和最终依赖图完成下列实施切面。它们是同一批的工作依赖，
不是重新划成按上层/下层交付的阶段；内部可以交错恢复编译，但依赖未成立时不能宣称
后续切面已完成。每个切面随代码切换任务服务、真实调用方、公开合同和必要验证。

| 切面 | 核心、Host 与插件的实际调整 | 工作依赖及完成判定 |
|---|---|---|
| 基座与请求强制执行 | 提取 Object 基础类型、唯一组装、Format、Reader/Writer、同版本 Hydrator 与受限读取；所属 service 保留当前授权、固定依据、输出核验、交付及证据；完整系统出版与基础信任根分离 | 采用 Snapshot 公共入口，完成 R1 相关写面/Schema 修正；插件不能得到完整 Home、原始 Store 或另一条 Writer 路径 |
| PluginHost 与默认装配 | 分离 package 定义、Repo/Dataset binding 与 request view；提供具名强类型服务注册、依赖和冲突检查、可撤销注册及 Start/Close；从已有显式部署装配建立默认 bindings，知识声明只用于合同解析与支持匹配 | 依赖前项的受限端口；先迁移现有执行实现，再用新 Host 装配，不留旧新双注册。运行产物格式、公开管理入口未选定部分不得用假实现补齐 |
| 通用分派与独立 LiveAccess | 将固定合同解析、Registry、匹配和分派归所属服务；LiveAccess 拥有声明解释、来源端口、HTTP 适配与观察；Object 保留纯来源声明与写边界 | 依赖固定声明读口与 Host 注册；R1 观察/证据/目标政策债已按触发条件处理；普通 Handler 独立调用，LiveAccess 默认 binding 不修改共享注册 |
| 声明式索引插件与 Dataset 准备 | 提取 Discovery 字段逻辑解释与 residual 的唯一语义，分开 typed 查询、物理编译、projection/readiness 与 provider；注册查询和维护角色；Dataset 候选准备成功后再接受服务版 | 依赖实际 Schema 采用基线、受限输入和 Host；当前 Controller projection 主线不能只改名为 SnapshotConsumer 注册。基本发布不等待索引，查询不启动恢复；默认 provider 保持现有能力与结果 |
| 维护及可选动态发现桥接 | 通用协调器拥有登记、唤醒、取消和独立进度；projection 维护与缓存各有消费者；内部推进提示及周期对账弥补丢通知；`liveaccess/discovery` 拥有来源 notice、观察保留和动态候选发布 | 依赖静态查询/投影及 LiveAccess；桥接按需要显式装配，静态发现不要求来源 I/O。先保留可重读观察再发布候选，Dataset 已采用 basis 与 Repo HEAD 分别恢复 |
| CLI、typed 接入与宿主收尾 | 将现有 Affordance 的 CLI 路径、Action、用途、用法与 help 同源装配，保留既有 describe；HTTP 和内部应用操作仍各守 typed 边界；宿主仅选择、构造、注入和启停 | 依赖各能力的请求服务与默认 bindings。不因搬迁增删业务能力或扩大命令树；新管理命令与权限先回到 R0 独立合同，再按所选分母实施 |

全部生产、测试、工具与 testkit 的调用方随所属切面移动；README、Conformance、系统
出版引用、场景材料和架构守卫同时切换，已迁出的旧实现及入口同步移除。PluginHost
与 CLI 的实现边界分别沿 Guideline §6.1～§6.7 和 [CLI 设计](cli.md)，不另建平行权威。

局部实现过程中用全包编译、定向组件/场景及架构检查定位错误。Schema access 解释与
对象组装各保留唯一算法；先作行为保持的提取，再调整依赖，不复制一份算法来解决循环。
现有 HTTP、CLI、固定引用与业务 Oracle 作为验证边界，不为了适配布局重新解释其语义。

目标结构断言必须覆盖：

- Object 基本读写没有扩展运行依赖；Snapshot 不理解对象，且原文件/Dataset 能力仍可独立用。
- Interfaces 不依赖 LiveAccess；Discovery 根不导入 Projection/provider；动态取源归桥接。
- 跨模块只能进根或具名公开一级入口，全部真实生产包登记，没有循环、深层访问或
  公开签名中的实现泄漏；测试和工具也不能绕过。
- 根包不反向导入依赖它的子实现；Reader 只持 Hydrator；通用协调机制不持搜索引擎或源 I/O。
- 任务规则只有一个 executor，CLI 经 Client/Server 与显式 principal；宿主只装配和启停。
- Host 只管理插件注册与生命周期，任务强制步骤仍由所属 service 执行；package、binding
  和请求 view 的状态不混用；typed role 冲突必须显式选择，不借作用域或加载顺序覆盖。
- 请求 view 的固定依据、范围及当前主体不可被插件修改；辅助读取同样受限，后台身份不
  从最近请求继承。注册撤销与资源取消归安装实例，不删除权威回执、授权账或保留证据。
- 默认插件有实际执行，不是空转发壳；索引、LiveAccess 和可选桥接的请求/后台路径各有
  typed 端口和独立故障语义，不被通用事件广播或不透明 verb 分派替代。
- CLI 描述与 help 同源，HTTP 不读取 CLI 表；既有 Action、返回形状及 describe 合同
  保持，新管理面未选定部分明确待选，不以占位命令或静默安装算作完成。
- 旧新实现不并存，没有兼容转发壳；系统完整出版不被基础 Writer 反向导入。

耦合度量按同一政策比较改前/改后，所有 imports 仍计入。新增逻辑单元须有真实边界与
重算证据，不能靠重新分组或抬基线宣称收紧。

**出口：** 全包编译、目标架构守卫、定向及受影响正式合同、完整集成验证全部通过。
中间尚未全绿可以继续完成本批；失败证据不删，不能勾选完成或把部分模块绿外推成整批绿。
只回退本批自己的修改，不整体 reset/clean/stash 共享在途工作区；不自动提交。

## 6. R3：完整验收与独立部署

**前置：** R2 统一结构完成，R0/R1 用例原预期保留。

| 入口 | 证明什么 |
|---|---|
| `make typecheck` | 全包及调用方编译；不等于业务执行 |
| 目标与现有架构合同 / `make test-boundary` | 类型/责任所有权、真实 imports 与公开深度 |
| `make test` | lakeFS HTTP 夹具上的普通/索引场景，索引用真实 OpenSearch |
| `make test-contracts` | 组件、架构及应用/transport，包含独立 Go 证据的实际运行范围 |
| 受影响 race | Host 注册/请求 view/撤销与关闭、Registry、Writer、缓存、消费者及动态发布的并发路径 |
| `make check-docs`、`make quality` | 文档、静态及质量门禁，不证明业务旅程 |
| `make deploy-local-scenes` 与受影响当前态部署入口 | 独立真实 lakeFS 及运行链路，不以夹具代验收 |

R2 恢复编译后即运行必要检查；R3 核对同一最终源码下的完整证据、部署结果与清退，不为
无新改动的绿色反复重跑。发现问题修复后只重跑其影响范围及必要集成，不重新补迎合实现
的 Oracle。真实部署只使用合同要求的已有测试环境，缺环境不自动清盘重建。

最终核对必须包含默认 bindings 下的已有 CLI/HTTP 能力、明确选择的第二种 provider 或
Handler、Repo/Dataset scope 拒绝、插件失败与卸载、索引恢复、独立 LiveAccess 及可选
动态桥接。实际声称支持的运行格式必须真实执行；只有注册声明、接口或进程启动不算兑现。
CLI help/describe 与入口分母对账；已选定的新管理能力按独立合同验收，仍待选的入口不
纳入既有能力通过结论，也不能掩盖已选定扩展体系尚未完成。

用例比较业务观察、固定引用的实际内容、摘要、范围及错误，不硬比较独立运行的随机
commit 或观察时间；每次运行内部仍必须严格验证候选、正文、Schema 和观察的实际依据。
不能为了“前后等价”归一化掉错误的仓、对象或版本。

结果绑定同次源码指纹。必需合同 fail/skip 均不通过；混合套件中不相关 live skip 和
未执行入口分别报告，不称完整无 skip 验收。结构迁移完成与真实部署验收分别记录，
未完成最终必需出口时保持待验。模型任务收益、媒体执行、规模资格不属于本计划分母。

## 硬性约束 / Invariants

沿用主题 owner 的 A-01 / L-01、I-01 / V-01、API-01、CA-01、R-01 / R-02、
AUTH-01 / AUTH-03、OI-01～05，以及实际触碰的写入、组合、恢复保证，不另造编号。

- 以目标保证定义验证，缺用例提前补；原实现不是正确性的唯一 Oracle。
- 保持行为与改变行为分开取证，架构断言不能代替公开入口后态。
- 一次统一结构切换不等于最后才验证，也不允许失败合同被删改或跳过。
- 基本发布不等待源在线、处理器或投影，不将非强制知识规范升为门槛。
- 单仓 Writer、固定依据、当前权限与实际观察分别成立；索引只有 Schema 字段 access 一种写法。
- 插件作用域决定适用性，不授予权限；强类型注册、明确实现选择及可撤销生命周期有真实
  实现与反例，不能只凭 Host、hook 或 Affordance 名称宣称扩展成立。
- 保留既有 CLI Affordance、Action、返回形状和三张注册表的边界；有界 CLI 调整与新
  管理能力先选合同，不把新增行为藏进结构迁移。
- 所见问题要有修复、债或自动守卫去处，来源变化或并行改动使证据无效时重新取证。

## 选定方案 / 被否决方案

选定 R0 先准备验收、R1 独立处理必要行为变化、R2 统一组织迁移、R3 最终证据与部署。
否决仅按上/下层决定八个阶段、依赖尚未补齐的覆盖作选择、混合语义变化最后才写测试、
强制每个目录有独立绿色中间版本，以及未经行为反例就把结构耦合判作产品缺陷。
