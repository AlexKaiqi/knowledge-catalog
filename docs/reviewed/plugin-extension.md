# 插件扩展体系重构：合同、过程与改接

## Goal

插件支撑[Agent 对象环境](object-system.md)的业务扩展：在 Repo scope 约束内提供实际贡献，
使不同团队可以采用所需能力。

把 Home/Server 中写死的索引与访问装配，重构为**插件构造并登记贡献，系统在明确步骤
选择、调用并采用结果**。完成后，插件作者知道怎样定义入口、挂到哪里、收到什么
payload；实施者知道要改哪些代码、保持什么，以及怎样证明任务已通过插件执行。

插件由 Repo 配置，作用域是该 Repo。写入后的维护和读取时的使用沿同一配置；
Server 装配并执行，Dataset 组合来源仓的能力。首批假设插件贡献没有冲突，
本轮不设计优先级、覆盖或冲突裁决。

消费方能取得对象与系统能力的 Affordance，再从目标访问概览找到所采用插件的用法；
插件既提供执行贡献，也登记用途与说明，让 Agent 从理解对象走到实际任务。

当前扩展点由声明式索引与 LiveAccess 的实际目标反推，必须有明确调用者、输入与结果采用。
未来 Wield 等扩展也沿实际需求确定贡献与接点，本文不预选其 API 或执行合同。
没有当前用途的通用 before/after 或任意返回改写点不进入首批设计。

本篇拥有共同接入与改接合同，声明式索引、LiveAccess 的具体承诺分别由
[索引插件重构](declarative-index.md)、[访问插件重构](resource-access.md)拥有。
两个例子说明目标过程，不能代替完整重构分母。通用登记、目标选择、多实例及说明读取
接线及共同层、具体索引已分别验收；LiveAccess 已接实际贡献，正按自己的分母验收。

## 重构范围

- 保持已有公开任务、知识身份、Schema、授权、固定依据及唯一写面；补充插件说明读取
  与目标访问概览，具体入口合同在公开 CLI/API 落实。LiveAccess 新选定的
  单值失败说明须在公开合同落实，不能以旧版整次错误上返限制这个目标。
- 不新增包安装、仓内脚本执行、热加载或通用依赖框架；不按插件再生成命令树。
- 不把 Object 迁移、索引接入与 LiveAccess 接入绑成一次切换；各自交付、共同验证触碰合同。
- 不以返回接点为理由增加任意任务结果改写框架或未选定的字段隐私政策。

## 1. 重构前的问题：有接口，接线仍写死

| 当前位置与信号 | 重构必须解决的问题 |
|---|---|
| [Home](../../home/home.go) 直接构造并持有单一 Index/Controller | 插件内部组装留在宿主；换一个查询方法仍不能保证准备、维护和关闭来自同一实现 |
| [Preparation](../../discovery/datasets/prepare.go)、[Snapshot Hook](../../home/home_sidecar.go) 接全局 Controller | 固定来源准备和变化通知无法按来源采用路由，容易只换 SEARCH、漏掉固定版本维护 |
| [Server](../../server/serve_auth.go) 全局注入 StateLookup 与兼容处理器 | 已能执行取值/操作，但还没有按目标登记、选择和管理一个完整访问实例 |
| [Hydrate/ReadAddress](../../liveaccess/service/hydrate.go) 遇单值错误就返回整次错误 | 不满足新版透明取值与单值失败隔离；当前结果表示也需能区分业务值与失败说明 |
| [来源凭据传递](../../liveaccess/caller_credentials.go)已有接缝 | 必须贯通本次可信调用并执行目标适用限制，不能只证明请求里带了 principal |
| [现有 help](../../cli/help.go)有任务导航，[SchemaReport](../../object/reader/schema.go)能展示字段和 access | 仍缺从目标实际选用取得插件说明的路径；展示声明不等于消费方已知道用法 |

重构要改变构造责任和实际调用关系。移动目录、增加转发壳或登记一个 EngineOpener，
都不能证明插件接入；OpenSearch 是索引的物理驱动，不等于声明式索引插件。

## 2. 目标：定义贡献，系统负责调用

插件定义由**静态入口及其登记的实际贡献**组成。插件自己构造内部实现，消费侧用带类型
的登记口接纳，任务服务在需要的步骤调用。首批入口编译进服务，由产品装配显式执行。

| 责任方 | 重构后负责什么 |
|---|---|
| 插件入口 | 构造所属实现，登记实际服务、过程参与点、启停与释放责任，以及本插件的 Affordance 和任务合同关联 |
| 能力消费侧 | 校验完整贡献，按 Repo 配置登记其作用域和任务参与点，并提供说明；保持实际业务类型，不建立 role+any 目录 |
| 任务服务 | 对象认证授权，固定范围和来源依据，组装访问概览并保持本次来源到实现的映射；传递适用身份，逐值核验并组装；承诺可审计的读取先可靠留证再交付 |
| 产品宿主 | 按 Repo 配置加载插件入口，提供系统依赖并连接消费侧，统一激活和退出；不继续藏着插件内部组装 |

声明式索引插件登记名为 `declarative-index`，入口位于 `declarativeindex/plugin/`，
登记与来源选择归 `discovery/plugin`，任务编排和跨来源组合归 `discovery/service`；
`discover` / `discovery` 不作为此插件名称。
LiveAccess 入口位于 `liveaccess/plugin/`，消费侧由 `liveaccess/service` 拥有。
公开合同见各包 Go API 与 README，实际验收以同一候选的运行证据为准。
共同采用配置、Scope 与说明事实归 `discovery/adoption`，不依赖索引或访问运行实现；
原消费 API 保持别名兼容，两类实际登记分别归其能力消费侧。
入口依赖消费合同，消费侧不反向导入入口。
具体索引插件按其 owner 在同一 `declarativeindex/` 模块内分工：`projection/` 查询及物理引擎，
`control/` 控制构建、更新、切换和恢复，`plugin/` 装配二者；控制使用维护接口，查询不反向依赖控制。
该模块的 `cli/` 提供插件说明及所属维护命令的客户端调用，经 Server 进入任务服务，不持后台实现。
通用查询合同、选择与组合服务及业务 CLI 继续归 `discovery/`；消费侧不导入具体插件实现，
由产品装配连接。目录与登记名体现这一个插件，不将通用发现能力等同于声明式索引。

### Repo 配置与作用域

**Repo 是插件配置与生效范围的归属。**一个 Repo 可以配置声明式索引、LiveAccess 等
插件；它们按各自贡献参与这个仓的过程。对象保存 Schema、`access`、Binding 等业务
声明，不逐对象安装插件。插件模块拥有代码和说明；Server 按 Repo 配置构造并登记
贡献，持有运行资源、句柄和凭据。配置插件不等于把脚本或运行句柄写进对象。

每次调用先确定来源 Repo，再取得该仓配置的相应贡献，并解析本次固定声明。
插件收到的任务始终带来源 Repo；直接仓访问受本次授权范围限制，Dataset 访问还受
其已选择文件和版本限制。配置在 R1 的插件不因 Server 全局装配或 Dataset 组合就
参与 R2 的任务。

写与用共享这一作用域：Writer 完成 R 的源提交后，变化提示交给 R 配置的维护贡献；
查询 R 时使用该配置的查询贡献；读取 R 的外部值时使用该配置的访问贡献。
索引派生失败不撤销源提交，读取插件也不取得 Writer 权限。

Dataset 不配置另一套插件。系统利用已有来源映射，把每份查询、准备或访问任务交给
来源 Repo 的插件，再组装结果；无需消费者逐文件标插件，也不新建文件归属表。
组合中的 R1、R2 可以配置不同插件；调用 R2 时仍只允许 Dataset 选中的 R2 文件范围。

首批按插件贡献无冲突推进，同一具体任务不需要在多个竞争贡献间择优。多个插件在
同一 Repo 提供不同能力不构成冲突；跨仓结果仍遵守既有查询与来源语义。
本轮不增加默认插件、优先级或覆盖机制。Repo 配置了所需插件而实现缺失或能力不支持
时，相关任务明确失败，不回退到隐藏的全局实现；未配置扩展不妨碍基础固定读写。

### 登记与运行

索引实例共同提供真实 Index 的搜索、关系、遍历、运维，以及所属 Controller 的固定准备、
通知与启停。LiveAccess 按实际承诺登记取值、源操作、所支持固定合同的处理器及释放责任，
不被迫实现索引角色。每取得资源就登记释放责任，完整校验后才可被选中。

登记时必须带 Repo 作用域，形成该仓可供任务服务调用的贡献。一个运行实例可以服务
多个已配置它的 Repo，作用域仍逐仓明确；请求中的来源和版本不能因资源共享而混用。
Repo 配置的保存、更新及登记签名在公开合同落实，本文不指定配置文件或新增管理命令。
Repo 配置是启用权威；入口登记处理函数形成其运行视图，不另设 Server 启用配置。

本次请求采用的贡献保持稳定，准备、查询、回读和结果处理沿确定的来源映射。
对象、Schema 与 Binding 按任务的知识依据读取；不能把插件配置与 Schema 声明混为一项，
也不能用最新 Schema 代替 Dataset 的固定声明。首批在启动时读取 Repo 配置并形成
只读运行视图；配置变更在下次装配生效，不增加热更新。登记不发权，
进程内作用域不构成代码沙箱。逐请求身份和预算在调用时提供，后台身份独立注入。

### 能力说明怎样被找到

对象侧 Affordance 说明已发布对象的用途与使用方式，系统侧说明基础任务与已采用扩展
怎样调用。两者关联明确合同，目标概览连接对象声明与来源适用能力。

`kc help` 直接解释 Object 的 object_id、Aspect、Member、Address、Relation 及其联系，
给出基础访问简例，并引导插件说明读取。内置能力同样需要自描述，不因需要说明就变成可安装插件。
`kc plugin <名称> help` 是新增的统一只读说明任务：插件模块提供自己的 Affordance，
名称对应实际登记的插件；统一入口读取并返回用途、适用声明、使用例子和已有任务入口。
根帮助保持离线可读；插件说明读取经客户端与 Server，不执行插件的业务能力。
精确命令合同由 [CLI owner](cli.md)及公开入口落实，不为每个插件重建业务命令树。

进入 Dataset 的知识访问概览时，应用层按本次来源 Repo 的插件配置，顺带交付插件的简短用途和帮助入口，
调用者不必先运行一个插件列表命令，也不靠插件名字或全文检索猜说明。这里只展示当前
范围内来源实际使用的能力，说明其适用声明和位置，内容来自插件登记与来源解析，不另存一份能力清单；配置、凭据和其它
目标的实例信息不混入说明。每次对象/文件读取无需重复整份说明。

Repo 配置插件，Server 装配并管理运行实例；使用者主要通过 Dataset 感知组合后的能力，
单仓直接访问沿同一机制保留。概览由应用层组合，
Snapshot 的纯文件组合与读取不依赖插件，概览聚合出的运行匹配信息不回写 Object 正文或 Schema。
未采用扩展时基础对象访问仍成立，辅助说明缺失也不成为固定读取的新前置。

Agent 发现对象与能力后，可沿说明进入资源拥有者或既有业务申请流程；申请与业务批准
不代替受控发权，也不建立中央自动批准者。已有权限可直接使用，实际调用仍按当前授权
核验，使用记录沿所属任务合同保存与交付，具体授权责任归[权限 owner](permissions.md)。

```text
插件入口：登记本插件的说明、合同关联及真实执行贡献
目标知识访问概览：解析获准范围及来源 Repo → 取得各 Repo 配置的插件 → 返回基础访问说明与适用插件帮助入口
插件说明读取：按登记名称定位说明 → 返回 Affordance 及对应任务用法
调用方：发现对象与能力 → 阅读说明与固定 Schema → 需要时申请并获得适用授权 → 构造并调用请求 → 按任务合同留证与交付
```

声明式索引说明解释 `access` 与字段类型如何用于查询；例如数字字段声明 filter/sort 后，
说明提供数值筛选、排序的含义及合法用法。其语义复用既有查询合同，不由实现另定。
Object 继续读取和展示 Schema；首批不为这类固定解释增加请求时 describe Hook。
说明关联明确的合同与版本，不能替代实际采用的历史 Schema 或观察依据；
登记描述不是支持、就绪或授权证明；具体查询组合是否支持、投影是否就绪及本次授权
仍在执行时核验。

插件说明读取和目标概览聚合已接线，共同层尚在验收；实现状态不代替完整重构分母。
返回形状和读取合同由公开类型、包 README 与 Conformance 落实。

## 3. 由插件需求确定扩展点与 payload

```text
装配：读取 Repo 插件配置 → 执行入口 → 按 Repo 作用域登记贡献 → 生成需求 → 激活
写入：Writer 提交 R → 将变化提示交给 R 的维护贡献 → 插件更新派生状态；源提交不回滚
发现用法：取得目标知识访问概览及插件帮助入口 → 阅读能力说明 → 查看 Schema → 调用方构造请求
查询：认证授权 → 固定目标/范围/依据 → 按来源 Repo 取得查询贡献 → 对象层按同依据回读 → 采用结果
对象访问：对象认证授权 → 按来源 Repo 取得访问贡献并固定声明 → 逐值调用 → 核验并组装 → 可靠留证 → 返回
后台：来源 Repo 已发生变化 → 按该仓配置及有效需求路由提示 → 独立维护 → 核验实际派生状态
```

下面说明 payload 的用途，字段和签名仍由现有公开类型拥有。服务调用要采用返回值；
通知只提示检查，不能仅因回调被调用就改变业务结果。

| 扩展点及实际使用需求 | 调用者与输入 payload | 返回值怎样采用 |
|---|---|---|
| 说明登记与读取：调用方知道能力与声明怎样使用 | 插件入口登记自己的说明及合同关联；概览按获准范围取得来源 Repo 配置的插件，插件帮助按登记名称读取说明，此时没有查询条件 | 应用层把来源适用能力、简要用途和帮助入口放入概览，说明读取返回完整用法；不触发构建、来源取值或维护，Schema 仍由 Object 展示 |
| 查询及相关任务贡献：索引“按声明查询、原子可见、版本固定” | Discovery 任务按来源传固定 Repo/commit、查询、组合范围、预算及上下文；[现有合同](../../discovery/service/README.md) | 采用真实查询结果，候选、Schema 和对象层回读贯穿同一依据；动态命中读原观察，不再取最新值。各来源的运维、关系和遍历沿其相应实例 |
| 固定版本准备：索引“新索引完整才采用、Dataset 固定版” | 承诺知识查询的 Dataset 发布任务传权威冻结候选，逐来源调用 Repo 配置的准备贡献；[DatasetPublisher](../../discovery/datasets/dataset_publish.go)、[BasisPreparer](../../discovery/datasets/prepare.go) | 所有必需来源准备成功才接受；准备、取消或接受失败保留旧版和已经完成的源提交；来源 Writer 提交及纯文件发布不增加索引前置 |
| 逐值取值：LiveAccess“无感取得数据、单值失败隔离” | 对象访问服务从固定声明解析每个外部值，传对象/单元位置、Binding、Schema、来源及本次适用身份；[StateLookup](../../liveaccess/serving.go) | 成功值经核验填入对应位置；合法空值保留成功依据；失败只在该值处给说明，其余可读值继续，不交付句柄或假成功观察 |
| 原观察读取：索引“动态命中读原观察”，LiveAccess 既有保留合同 | 动态命中后读取或复核，使用固定声明及原观察定位；来源可重读或平台保留服务提供该能力 | 返回原观察值及原依据；丢失与正常到期分别失败，不能重新调用当前态取值冒充。原观察选择的公开接线仍须落实 |
| 显式源操作：LiveAccess“无感取值只读，修改须显式调用授权” | invoke 任务传固定实现、允许操作、业务输入和可信调用上下文；[InterfaceCall](../../interfaces/dispatch.go) | 验输入、执行授权及结果后采用；操作失败不证明没有效果，不自动重试，不混入透明取值 |
| 变化提示与对账：索引“自动更新、漏通知/重启/索引丢失恢复”，LiveAccess 既有观察恢复 | 系统按来源 Repo 的配置和有效需求传 [Snapshot](../../snapshot/dataset/hook.go)、[ChangeNotice](../../discovery/projection/notice.go)及固定服务需求 | 回调登记/唤醒，后台核验该 Repo 的投影和观察；失败隔离，不回滚源写入，不把通知正文当值 |
| 启动与退出：索引和访问实现有实际引擎、来源适配及后台资源 | 宿主完整装配后激活；退出拒新调用、取消后台，再等已接受调用并释放资源 | 运行与释放保持所属实例归属；没有后台任务的访问实现不虚构 worker |

固定对象回读、对象认证授权、适用身份传递、结果组装及可靠留证是系统必须执行的步骤，
不开放为可绕过的通用 Hook。插件接收同一固定依据和受限来源调用上下文；系统自动
向受信任、凭据适用的来源传递本次认证证明，使用者不重复输入，后台身份保持独立。

显式 notice/sync 是运维调用，保留等待执行和返回实际依据的原合同；它与提示入队回调
分别处理。内部 Snapshot 提示与用户出站 pre/post Hook 的时机、重放和投递合同仍分开，
沿[Hook 与 Gate](hooks-and-gates.md)，不借出站配置登记插件。

### 最终返回采用与失败边界

索引返回的命中，系统按命中的固定版本、范围、Schema 和观察依据解释；索引查 a，
对象层就读 a。读取期间 HEAD 或 Dataset 发布版切换，不把同一次调用改成 b；后续按
结果依据读取和分页沿原依据，失效明确拒绝，两次独立 latest 请求不承诺天然同版。

LiveAccess 返回的单值结果由对象访问服务按位置采用：数据、带依据的合法空值、
访问失败说明分别处理。一个外部值失败不抹掉其他可读值。失败说明不放进业务值冒充
Schema 合法数据，也不产生成功观察。
范围、固定依据、取消及平台交付错误继续按任务合同处理，不能一律降成单值错误。

透明读取的局部失败不等于搜索完整：用于过滤/排序的必需值或原观察无法取得时，查询
按原覆盖合同失败或如实报告受限，不把失败当 null/MISSING 或完整零命中。
原 [delivery](../../delivery/README.md) 的仓读权政策仍由系统执行。两个插件的需求不要求
另开任意末端正文改写 Hook，现有 Stage 也不承担逐值取值、凭据传递和失败隔离。

### 访问证据由哪个过程使用

LiveAccess 第 5 目标要求按请求复核当次读取。系统在采用值或失败说明时，记录调用者、
实际读取位置、时间及请求语义和关联；Snapshot 以固定版本和位置复核，LiveAccess 保留当次
实际值、固定声明、观察依据或失败说明，不能重新取最新值替代。

承诺可审计的读取先可靠保存证据再交付；证据保存失败属于平台交付失败，不能降为某个
业务值失败后照常宣布读取成功。保留期间历史版本、原观察与证据的可复核期限须匹配，
丢失与正常到期分别处理。普通读取返回对象和数据，完整证据通过
[服务边界的独立审计入口](service.md)按其权限查询，认证凭据不进入证据。
审计账可以引用可靠保留的原观察记录；承诺期内须能取回实际值或失败，只有依据指针不够。
这是系统采用结果时的强制职责，不增加插件可替换的“返回后通知”点。

## 4. 具体改什么

| 改接位置 | 必须落地的改动 |
|---|---|
| Repo 插件配置与 Home/Server 的固定构造 | Repo 保存启用配置，Server 据此调用插件入口并按 Repo 作用域登记完整贡献；运行视图不成为第二份配置，不保留隐藏全局回退 |
| 写入与写后维护 | Writer 仍完成唯一源提交；提交后依据目标 Repo 配置路由变化提示，后续准备、查询与读取使用同一仓的贡献。派生失败不撤销源提交，不凭空增加通用写前 Hook |
| 插件说明与基础帮助 | 插件模块随贡献登记 Affordance 和任务合同关联，统一读取服务接 `kc plugin <名称> help`；`kc help` 指向 Object 基础访问与插件说明入口，已有任务帮助保持同源 |
| 目标知识访问概览 | 应用层按固定范围汇总来源 Repo 已配置插件的简短信息与帮助入口，随 Dataset 概览交付；Repo 直接访问共用此机制。保持 Snapshot 文件服务独立，不新增 Dataset 绑定、强制列表前置或每次读取的说明回调 |
| 索引查询、控制和 CLI 归属 | 具体实现集中在 `declarativeindex/`，构建/更新/切换/恢复收口到其 `control/`，由插件入口连接维护接口与查询实现；查询不导入控制。插件 CLI 在所属模块经 Server 调用；通用查询及组合仍归 `discovery/` |
| 查询、关系、遍历、运维、readiness、telemetry | 按来源 Repo 配置注入真实视图，组合任务保留来源到实现的映射；固定依据贯穿索引、实际采用的 Schema、对象回读和续页。动态命中接原观察读取，保留 `AccessSpecAt`、semantic window 等能力；每个来源的 sync Index/Controller 同属一个实例 |
| Dataset 固定准备 | 从冻结候选逐来源取得 Repo 配置的准备贡献，全部必需准备成功后权威接受；不按 Dataset 身份另选一个全局 Provider，纯文件发布保持独立 |
| 单 Controller 的 Snapshot Hook | 接系统反向需求路由，HEAD 所有者登记推进，固定 Dataset 依赖者唤醒恢复；一个实例失败继续其他独立实例 |
| 全局 Dataset 扫描与 HEAD 调度 | 按来源 Repo 配置生成各贡献的有效需求；固定恢复逐 basis 准备，不先要求当前 HEAD 可读，不把仅有固定来源需求的实例改成追最新 HEAD |
| State 恢复与请求来源 | 按有效固定声明 basis 维护，后台来源独立装配；修正 notice 请求改写 Controller 后台来源的接线，请求来源仅供本次执行 |
| LiveAccess 全局注入及兼容 Handler 表 | 改接访问登记和私有支持目录，业务对象的 Repo/Dataset 读取均按固定声明无感取值；access/invoke 按来源对象实现声明选择，直接 access 仍统一核验/存证。单仓任务不能继续只读声明而将透明访问仅留给 Dataset |
| 逐值结果组装与严格索引消费 | 改接 Hydrate/Read/ReadAddress 的整次错误上返，保留其他成功值，失败归对应值且不成为业务值/成功观察；投影桥接另保持查询必需部分的严格核验，不把局部失败对象发布成完整动态投影 |
| 本次身份与出站访问 | 贯通 Server 已认证上下文、StateLookup 与源适配；自动发送适用证明，来源目标和重定向不得扩大凭据范围，后台不借最近请求 |
| 访问留证与独立审计 | 在实际值/失败被采用时留存可关联请求的访问记录，兑现先可靠留证后交付；Snapshot/原观察可复核，完整记录只从独立授权审计入口获取 |
| 原观察读取 | 落实按结果原依据读取的公开接线及真实保留能力，不以当前值查询或固定测试桩代替 |
| 退出接线 | 请求视图借用已确定的各来源实例，根宿主排空请求和维护后释放一次所属资源 |

现有 [ObservedValue](../../object/read.go) 及调用链尚未承载独立于业务值的逐值失败说明，
普通读取的原观察选择也不能靠返回一个固定记录的测试桩证明已实现。实施时须在对应
公开类型、包 README 和 Conformance 选定结果表示、原观察请求、访问记录及兼容边界，再改调用。
目标行为已经由插件 owner 选定，不因旧类型只有值/整次错误而退回旧目标。
现有 [AccessEvent/AccessQuery](../../observability/access.go) 的访问坐标、观察指针与整次
错误不足以承接逐值实际结果复核，记录请求关联也不等于已有按请求查询能力；本次审计
合同须补可取回的原结果/失败及对应查询，再以真实记录验收，不用日志存在代替完成。

组合查询已接入按固定来源选择的实例贡献；具体查询与组合保证仍随索引阶段验收。
组合任务在读取正文前约束来源版本和文件范围，统一当前授权与总预算；各必需来源须支持
具体请求，排序类型与顺序须相容，相关度保留提供方依据，覆盖和稳定归并可核验。
不能将来源能力求并集后宣称整个组合支持查询；失配按既有失败/受限合同处理，不扫描兜底。
搜索、关系与遍历续页保留各来源实际实例及原依据，换实现或失去必需依据时明确拒绝。

### 维护、资源与兼容不能漏改

系统从 Repo 配置、权威登记及 Dataset 接受记录生成三类需求：所属 Repository HEAD、
已接受 Dataset 固定来源、有效 State 声明；均路由到来源 Repo 配置的贡献。
HEAD 推进与 Dataset 固定版本恢复各用自己的知识依据，不能以最新声明替换固定声明。
固定来源同实例按仓和 commit 去重，
保留需求所有者，未接受候选不成为长期需求。一个 basis 失败仍继续其他项，历史 pending
和 notice 执行前复核有效需求；空分区明确为空，不能回退历史全仓工作。

需求完整刷新后原子替换，失败保留旧视图及资源；初始视图失败拒绝激活。启动、唤醒与
周期对账核验实际投影，进度完成不证明介质还存在。Object 正文预热保持独立，不复制
成每个索引实例。动态索引与所选 LiveAccess 的来源、授权和观察共享须相容，不混用
不相容的 State 候选，也不因后台可读而向消费者发权。

不同实例隔离工作账、观察状态与真实物理定位。当前 OpenSearch opener 忽略目录参数，
只分本地目录不足以隔离；稳定 namespace 必须进入物理定位，不改变知识身份。
接纳旧资源的实例保留旧续页核验，不因重新装配转移资源归属；实际实例身份进入仓/Dataset
搜索、关系、遍历各层续页依据，换实例拒绝旧页，原接纳实例保留旧摘要及原校验。

完整登记、关联和初始需求成功后才激活；失败先停止已启动任务，再逆序释放已取得资源。
退出先停新请求、取消后台工作以解除共享锁等待，再等已接受请求及维护排空，
最后一次关闭实例及共享资源；已接受请求保留自己的上下文。
Stop 不重复关闭资源账中的引擎，已接受知识、Dataset、回执和授权账保持。

## 5. 用两个例子检验改接是否讲得通

例子里的登记语句只表达目标接入意图，尚不是正式 API。完整贡献与改动分母以第 2～4 节
为准，下面各取一条调用说明“定义、挂点、payload、结果采用”。

### 声明式索引：组合按来源准备并查询

```text
索引入口(Repo 作用域, 登记口):
    构造本插件的 Index 和 Controller
    在该 Repo 下登记查询、固定准备、通知、运维及启停贡献
    登记 access 的使用说明及对应查询任务入口
```

R1、R2 都在仓配置中启用声明式索引，Server 分别装配为 A、B。向 R1 写入后，
变化提示交给 A 维护 R1，R2 的变化交给 B；查询也分别使用 A、B。
设 D 组合 R1@c1、R2@d1；D 没有自己的插件配置。承诺查询能力的 D 发布任务按来源
分别交给 A/B 准备，全部成功才接受；来源 Writer 提交不等待索引。消费者进入 D 的知识访问
概览，取得 Object 基础说明及这些来源相关的插件帮助入口；读说明、由 Object 查看
Schema，发现说明字段声明了 text，再构造“订单”查询。说明读取不要求索引就绪，也不触发构建。

执行时按已确定映射分别向 A/B 传固定来源、查询及本次范围/总预算；A 定位 R1 的
`service/api`，按 c1 回读“订单 API”，B 按 d1 处理 R2，系统按覆盖及排序合同归并并交付。
任务接点 `SearchExecutor.Projection` / `DatasetSearchExecutor.Projection` 消费
`discovery/plugin` 固定的来源贡献；完整例子仍随具体索引的 U1～U6 验收，不能只凭登记宣称通过。

若 A 已查 c1，而回读前 R1 推进 c2 或 D 改发布版，当前调用仍按 c1 的 Schema、范围和
对象正文完成；不能读出 c2。HEAD 跟进与旧 D 的 c1 恢复都交给 R1 的 A，传各自依据。动态命中若采用
观察 o1，源已到 o2 时仍读 o1；o1 不可用明确失败。这验证查询、准备、通知与原依据读取
都实际改接，未就绪不是零命中，最终页也不能随意删改而冒充原查询保证。

### LiveAccess：采用插件返回的实际值

```text
访问入口(Repo 作用域, 登记口):
    在该 Repo 下登记 lookup，以及实际提供的操作和支持合同
    登记所解释访问声明、透明取值效果及显式操作的使用说明
lookup(请求 payload):
    来源按固定声明和可信主体取值
    返回实际值及这次观察依据，或本次取值错误
系统组装对象:
    按位置核验并采用各单值结果；失败归该值，继续其他可读值
```

R 在仓配置中启用 LiveAccess。读取 R 的 `service/api`：固定说明为“订单 API”，health
和 quota 都从外部取值。系统先完成对象认证授权，从 R@c1 解析各固定声明，
调用 R 登记的访问贡献，按各值 Binding 自动提供本次适用认证证明。
health 返回 healthy 及合法观察依据，quota 来源超时。最终结果保留说明与 health 数据，
仅在 quota 的位置提供访问失败说明；实际值与失败先按本次请求可靠留证，使用者不拿
句柄另调，也不重新输入凭据。审计方通过独立入口复核这次 health 值和 quota 失败，
来源之后变化也不改读最新值充当当次证据。
声明仍为 c1，health 的实际观察另记，quota 没有伪造成功观察。

[OpenRequest/Hydrate](../../liveaccess/service/hydrate.go) 采用固定声明，按位置组装成功值
与失败说明；对应公共表示及回归归 LiveAccess 的专项验收。

改选访问实例不改声明 origin；把观察值改成 failed 却沿用旧依据会伪造事实。READ、
直接 access 与 invoke 都须兑现自身完整合同，不能用这个单条成功例子替代核验、存证、
来源授权、后台身份与生产观察保留的验收。

## 6. 实施顺序与完成条件

实施分四步：确认说明读取/目标概览、真实消费合同、单值失败/原观察/访问证据的公开表示及必要反例 →
提取入口并接登记/选择 → 改接全部任务、维护及资源 → 在同一最终候选核对证据。
顺序和切片由[重构计划](object-refactor-plan.md)安排；
当前 Object、插件共同层与声明式索引已通过各自阶段验收，正实施 LiveAccess 的具体插件重构。LiveAccess 按自己的分母交付，不混作索引完成条件。
模块 CLI 的命令贡献、参数、输出、帮助及例子在所属 `cli/` 同源维护；旧命令的扩展
同样由模块贡献接入，统一 CLI 只装配上下文、命令与导航，不复制所属实现规则。

插件共同层阶段验收共同登记、匹配与范围、说明读取、真实生产消费和生命周期。
须有实际贡献通过这些接缝执行，但不要求先完成具体索引的内部迁移或 LiveAccess 专项。
下表中查询/准备/维护、透明取值/观察/审计等具体保证，随各自插件的后续阶段完整验收；
不能把整张专项表作为共同层完成的前置，再反过来阻止具体索引阶段开始。

| 验收范围 | 必须看到的结果 |
|---|---|
| Repo 配置与写读作用域 | 在 R1 配置插件，写后维护和读取/查询均调用 R1 的贡献；不参与未配置的 R2。Dataset 使用既有来源映射调用各仓贡献，范围在调用前限制；不新增逐文件插件标签 |
| 说明发现与独立走读 | 根帮助直接解释 Object 概念与基本访问，Dataset 概览取得固定来源的适用插件及帮助入口；无需预先猜插件名称或查询条件，读说明、看 Schema 后能构造并执行合法请求；单仓访问复用机制 |
| 说明与执行分离 | 改组合范围显示对应来源能力与适用位置，不新增 Dataset 绑定、不列无关实例或配置；说明读取不构建索引、不访问来源、不运行维护，不增加 describe 回调或每次读取的说明前置。无扩展及说明缺失时固定读取仍成立；合法用法不虚报实现支持或就绪 |
| 实际接点与来源选用 | 第 3 节每项贡献有真实调用与结果/效果采用；R1 配置 A、R2 配置 B，D 组合后二者按来源被调用。同一来源进入不同组合使用该仓贡献；配置的实现缺失或缺能力时拒绝，无隐藏全局实现；插件冲突不纳入本轮分母 |
| 跨来源查询与准备 | 按每份固定声明准备，全部必需准备成功才接受知识服务版；不同实例查询遵守范围/总预算、具体支持、相容排序和完整性，续页绑定各来源及实际实例，不能把能力并集冒充整次查询支持 |
| 发布与固定依据 | 冻结准备失败保留旧版；在索引查 a 与对象回读间推进版本/切 Dataset，仍用 a 的范围、Schema、正文及原观察，或明确失效；分页同样核验，不能混读 |
| 维护恢复 | R 更新不替换 D 的固定依据；漏通知、重启、投影丢失恢复，HEAD 不可读不阻断合法固定 basis；退役及旧 pending 不继续无效工作 |
| 透明访问与失败隔离 | Repo/Dataset 对象访问都看到数据而非句柄；一对象同时含固定值、成功外部值、合法 null 及失败外部值，其他值保留，失败说明按位置且不成为业务值/成功观察 |
| 身份、严格查询与重读 | 来源实际收到本次适用认证证明，消费者不重输凭据；目标/重定向不扩权、caller 不替换后台身份。局部失败不放宽动态索引/搜索完整性，原观察重读和丢失/到期分别验证 |
| 模块分工及可审计交付 | 索引查询不反向依赖控制，模块 CLI 经 Server 且不持后台实现。按请求能复核当次 Snapshot/实际值/失败；留证故障阻止成功交付，完整证据的独立查询及保留期限授权正确 |
| 隔离、续页和退出 | 实际物理数据/进度不串用，换实例拒绝旧页，既有资源升级保留原续页校验；构造失败及退出资源只释放一次，在途请求和维护可排空 |

受影响回归、架构及并发合同，以及 `make check-docs`、`make quality` 必须通过；普通
场景与正式 contracts 沿既有入口执行。真实部署按独立合同验收，使用已有环境。
报告实现范围和已验证范围，必需项 fail/skip 不通过；文档检查、注册成功、一个例子成功
都不能记为完整插件重构验收。

## 需要保持的合同

保持 W-01/W-02、V-01/KS-01、C-01/R-01/R-02、AUTH-01～03/KS-02、P-01/PC-01、L-01/API-01：

- 插件配置与作用域归 Repo，写后维护和读取使用该仓贡献；本次选用保持稳定，配置的实现失效不回退，Dataset 不另定义或覆盖来源配置。
- 当前授权、固定范围、唯一写面、权威接受及交付继续由系统保证，插件不接管这些权力。
- 候选、正文、声明及观察保持各自真实依据，通知与进度不代替结果或就绪证明。
- 外部单值失败、操作失败与查询依据失败各按目标合同处理；局部值说明不伪造业务数据或搜索完整性。
- 准备、通知及维护保留各自失败后果，派生失败不撤销已接受写入。

## 接入方式与取舍

选定 Repo 配置、静态入口按 Repo 作用域登记、消费侧完整接纳、实际任务贡献及系统结果采用；
所有接点从两插件的实际承诺反推，并由具体任务消费；平台强制阶段不作为可替换 Hook。
选定插件登记可复用说明、统一插件帮助读取、知识访问概览顺带交付范围内来源的适用能力；
Repo 配置与登记插件，Server 据此装配执行，Object 保存具体声明，Dataset 保持组合。
首批假设插件贡献没有冲突，不预建优先级、默认选择或覆盖机制。
Object 保持基础模型与 Schema 查看，固定声明解释不另开请求时 describe 回调。
通过改接与验证完成重构，例子辅助解释。否决仅改目录、转发壳、单查询成功作为完整
出口、无消费需求的通用末端改写点，以及用旧失败形状阻止新选定行为。
