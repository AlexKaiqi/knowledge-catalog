# 服务边界

应用服务把 Snapshot、Catalog、Knowledge、Retrieval 与外部运行时接成完整任务。
它负责请求上下文、政策执行、范围、交付和恢复装配，不重新解释知识，也不是新协议层。
CLI、HTTP、文件网关与宿主插件是同一产品的入口，不是多套业务规则。

## 请求规则放在同一个应用入口

客户端发送明确的业务意图，服务端认证后按当前权限确定范围，再调用领域组件。
CLI 与 HTTP 共用 typed 应用用例，彼此不调用解析器，也不能让一条入口绕过另一条入口的
授权或版本规则。具体 adapter 只在装配处选择，不泄漏到知识和组合协议。

普通使用者不需要知道存储驱动、内部连接地址或索引代际。部署方提供服务和存储策略；
日常连接、供给、发布与分享通过获准的管理能力完成。供给、连接、Catalog 登记与授权
仍是不同事实，恢复时不能用一个成功记录推导其它步骤也成功。

远程消费不引入会话对象：额外会话只制造状态、续租与可用性问题，认证与撤权逐请求处理。
pin 坐标不带时效、不绑定身份，也不是可转授的能力凭证；允许的服务端传输优化——按 pin
的不可变解析缓存、网关签发的依据信封——必须保持无身份、可重建，不得演变成公开会话
标识、续租协议或会话存储。认证 token 可由边界本地验签，或按凭证摘要做短时效缓存；
失效窗口属于认证器策略，不改变授权语义，token 刷新也不改变 pin。

## 应用执行中的责任交接

认证结果成为可信请求上下文，权限组件据当前政策判定动作与范围；应用服务据此调用
Catalog、Knowledge 和 Retrieval，再按政策交付结果并记录证据。固定版本与当前授权
共同成立，不把曾通过的登录、pin 或缓存命中当成新的准入决定。

把知识交给模型时，锚定不能在最后一跳丢失：组装出的模型上下文必须保留固定引用、内容
摘要、片段定位与来源摘录；模型推断可以存在，但必须与仓中已接受的知识明确区分，
推断要成为知识仍走正常写入或提案。

应用层还负责跨组件任务。产品若承诺 Dataset 新版一经采用即可搜索，应用先固定候选、
准备所需投影，再接受发布；准备失败保留旧服务版，不回滚来源已完成的提交。
这是知识应用的附加采用条件，纯文件 Dataset 的组合与交付不依赖知识层或索引。
治理则先核对证据再请求 Writer 条件推进。这些编排不把索引导入 Catalog，不把 Hook
放进 Writer，也不把业务决策散落到 CLI、HTTP 和插件三处。

权限政策、索引恢复、治理扩展和 CLI 交互分别由相应设计展开。本篇关注装配顺序和失败
归属：范围错误不能靠后置遮罩补救，证据不足不能冒充无权，派生失败不能撤销已接受写入。

## 文件与插件只是固定视图的交付

所有产品拓扑的文件读取统一经文件网关代理，理由有四：服务侧凭证不下发客户端；每次
服务端读取都重新认证与授权；`file.read` 访问证据可完整记录；交付字节全部绑定同一固定
版本。本机挂载必须连网关，不得直开来源仓，客户端也不自建第二套文件视图。宿主挂载
保持只读；读取不能自动创建提交，打开旧挂载也不能自动跟随新发布。

知识的语义文件视图在显式挂载阶段从固定版本构建并缓存：按领域实体形成分目录布局，
文件保留对象标识、来源仓、版本与各切面的 Schema 坐标，使 rg、grep 之类的宿主工具
仍可追溯身份与来源。它由已组装内容生成，不产生另一种权威，也不接受写回。

已有项目采用 Dataset 时，应明确挂到哪里、采用哪个版本，保持原项目文件。
界面隐藏一个展示入口不应偷偷撤掉挂载或更改授权。文件便利性不能改变固定版本和来源语义；
文件浏览只属于项目附着旅程，不能替代服务端发现、知识目录或结构化查询。

## 恢复按丢失后果区分

| 状态 | 恢复要求 |
|---|---|
| 知识与 Catalog 的 Snapshot 历史 | 恢复原权威，不能从缓存猜出一份新历史 |
| 身份、授权、供给记录、写回执与治理证据 | 保持既有决定和幂等结果，缺失时不能当空状态重建 |
| 外部观察的保留记录 | 履行已承诺的复核期限；不可再生的旧观察丢失须明确报告 |
| 索引、工作副本与正文缓存 | 可丢且可按明确依据重建，不借恢复修改权威 |

初始化是显式管理动作，服务启动只恢复；不能因状态卷损坏重新发管理员权限。
来源暂时离线与耐久绑定丢失也要区分，不能在恢复时自动收养同名来源或重新建仓。
当前目标是可恢复的单实例服务，不通过文档合并引入多副本一致性承诺。

接入既有来源是应用操作：只读打开既有权威，校验身份、可用性与固定版本，再原子提交
成员登记。校验或登记失败不创建版本、不推进其引用，也不留下半个登记。平台仓供给的
创建进度与连接记录属于独立耐久账，不能只存在于进程内存或缓存；跨介质失败不假装全部
回滚，按原请求与已完成阶段恢复，不覆盖既有仓、不重复发权。服务端自身的系统事件账与
访问审计账是只存指针与关联字段的耐久过程账，替换实例后必须恢复，不因接入外部日志
管道而改名或降级。

客户端一侧的本地覆盖、凭证、任务 pin 与挂载生命周期不属于服务端恢复权威。挂载认证或
授权失败后停止新读取、标记降级并返回明确错误，不自动切换版本，也不静默返回空文件。

## 证据与诊断各有用途

访问证据说明谁基于什么版本进行了什么访问，检索、模型处理与反馈可相互追溯。
承诺记录证据的读取，在证据未可靠保存时不能声称成功完成；已经提交的写入则不能因随后
诊断或出站副作用失败被改报为未提交。证据库有自己的存储合同，但不是快照存储、不是知识
仓、也不是检索投影：登记不收录它，搜索不发现它。审计读取是存储合同上的三种有界读——
按证据身份点查、时间窗等值有界分页、派生视图折叠——不是知识检索，也不隐式放行全量
导出；热窗外闭日分区删除后不可点查，是既定的保留语义。检索成功响应携带检索证据标识；
后续精炼失败不得涂改已确认的检索证据。精炼证据只保存精确的模型输入（投影值与内容
摘要），不含密钥、传输正文或未投影字段，且只能经审计入口读取；未执行的计划不得伪装
成已经发生的观测。

运行指标在进程内聚合后导出、不采样；采样策略只作用于诊断日志与 trace（错误类日志必须
完整保留，头部采样丢弃的 span 无法恢复）。它们解释健康、耗时与瓶颈，不能替代需要
保留的访问证据。访问次数、反馈或模型结果也不自动成为知识真相、授权规则或训练标签：
Agent 自评默认不可训练，只有用户或评审的接受与纠正形成可训练样本；训练流水线在系统
边界之外，不回写知识仓。反馈只关联已经存在的知识访问 trace；trace 是系统边界内的调用
证据，不保存思维链内容。调用方绕过应用服务直读来源仓或索引时，平台观察不到逐条访问，
也不声称拥有逐条审计。追踪与请求标识等诊断头非法、冲突或缺失属于诊断上下文问题，不能
成为业务请求失败的原因；出站调用也不把主体身份或凭证传播进追踪上下文。健康合同保持
轻量：存活探针只反映进程，就绪探针是各启用入口就绪条件的合取，探针成本有约束；细则归
HTTP 入口与部署资料。具体事件、保留参数、标签与配置交给协议及部署文件。

## 方向性用例

### U1：同一任务经 CLI 与 HTTP 执行

两个入口在相同主体和范围下得到相同的领域结果；不能一个入口固定版本，另一个读最新；
也不能通过直接打开本机仓绕过 Server 授权。

### U2：替换实例后继续使用

原登记、身份、权限、提案和写回执可恢复。重放建仓或准入请求不创建第二份资源，
不重新授予已撤销权限；状态丢失明确要求恢复。

### U3：把 Dataset 接入已有工作项目

消费者采用确定版本的只读视图，原项目文件保留。重新采用更新是显式动作，
隐藏界面入口不改变文件访问事实或权限。

### U4：证据存储故障

需要证据的消费不假装记录成功；已经接受的写入仍返回其真实接受事实，
后续投递与诊断失败可单独追踪，不诱导使用者重复发布。

### U5：第一次接入并发现可用知识

消费方用同一个已认证身份了解来源与 Schema、选择 Dataset、检索并读取。有界浏览给出
名单式入口，搜索覆盖关键词与过滤；库存、自描述知识和正文权限分别解释，使用者无需知道
底层存储地址，也不能借发现入口扩大范围。

### U6：定位一次读取为什么慢

使用者能区分客户端、范围解析、候选查询和同版本回读的成本；目录展开只读取一页直接
子项，浏览器、插件、文件网关与授权各段分别计时，本机 p95 目录首屏超过 100ms 视为性能
回归。连接或查看已有固定视图不应触发隐式全库扫描。具体延迟目标和规模资格由测量场景
证明，不因设计书改写而被删除或宣称达标。
