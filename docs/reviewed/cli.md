# CLI：面向人的交互接口

## Goal

CLI 是用户与 Agent 理解和操作系统的一条完整交互路径：此刻要完成什么，已经知道什么，下一步
怎样找到，以及成功或失败后怎样继续。interactive interface 包含发现、选择上下文、操作与
反馈；不能只剩命令列表，也不能因为已有 HTTP 就省去交互设计。
文件任务的交互实现由 Snapshot 模块拥有，KC 装配全局上下文并保持统一任务入口。
补齐插件说明读取与知识访问概览，让使用者从 Object 基础能力继续了解来源声明适用的扩展。

## Non-Goals

- 命令组织不按协议分层、岗位或后台包目录照搬一遍。
- 公开消费面没有对象实例列举，也不提供产品级快照导出；发现走库存与检索，不设无界清单
  类命令。
- 不在交互里自动发权；平台不托管申请或审批队列。
- 不让一条读命令同步建索引，也不把「能执行命令」视为交互已经完整。
- 本轮没有选定或承诺一套新的 REPL/TUI；后续向导或全屏交互应复用相同上下文与动作。
- 不按每个 Plugin 生成一棵命令树，不因实现更换而改写既有路径、Action、操作或结果合同。
- 静态 help 不证明目标当前可用；本文选定插件说明读取入口，不预设安装管理、结果 DTO 或错误码。
- 模块收口不新增命令框架、独立二进制或按包目录生成的命令树，不在 CLI 复制服务业务权威。

## 模块任务与全局上下文

Snapshot 的文件任务由 `snapshot/cli` 持有命令合同、参数适配、输出与所属 SDK 调用，可以
在没有 KC 应用包的宿主中使用。模块通过 `snapshot/client` 请求同一受控服务；不自行打开
存储、推导权限或发布第二份范围。命令仍按用户任务组织，模块目录不是公开命令路径的理由。

KC 负责全局身份会话与上下文、部署、宿主管理及跨模块任务，将已认证运输和本次主体
交给模块入口。已有 argv、帮助、操作与结果合同保持；KC 的注册表采用模块的同一命令
定义，执行与帮助不另写两套。模块 CLI 与 SDK 不依赖 KC 的命令 dispatcher、Home 或
Invocation 实现；全局装配也不把模块业务留在中央再加一层转发。

模块同时拥有叶任务的操作数映射、参数适用范围、产品结果和所属帮助导航。统一入口从
模块声明绑定输入与展示说明，不再维护第二份模块叶名单或参数规则；宿主负责全局导航、
跨模块旅程和运输身份。引用模块的装配及集成测试可留在宿主，空壳和重复叶实现不作为
兼容层保留。

模块也应提供其任务所需的静态概念与分组引导，统一入口同源装配。解释页属于帮助，
不因此增加业务动作或另建一棵命令树；这些静态说明不依赖宿主会话或服务查询。

## 从用户任务组织入口

主要路径是连接一套服务、发现并读取知识、向一个仓发布知识、接入来源并分享给他人。
Dataset 发布与采用穿过这些路径，评审、排障和权限管理按需要进入相应功能组。
命令组织按任务和使用频率，不按协议分层、岗位或后台包目录照搬一遍。

发现有两条路：已知身份直接读取；不知道身份时先用有界浏览和搜索定位。浏览返回来源、
Dataset与单仓已发布实体名单——`schema/*` 只点名实体，不返回合同正文；它有界、分页、
按固定依据执行，既不依赖无界扫描，也不要求用户先猜关键词。空查询或 `*` 不是浏览。
公开消费面没有对象实例列举，也不提供产品级快照导出；发现走库存与检索，不设无界清单
类命令，本机存在目录也不构成绕过服务的理由。

根帮助说明日常能做什么和最短路径；功能组说明有哪些动作；叶子帮助才解释当前动作的
操作数与取值方法。用户输入一个尚未完整的功能组时，应看到就近选项，不能意外执行某个
默认写动作。复杂值需要可理解、可复制的写法，不要求先阅读内部类型定义。

零知识使用者应能从分组说明建立资源、版本和交付关系，找到输入坐标的来源，再沿一个
连贯例子完成选择与消费。复杂文件输入要给出完整合法样例；当前未提供的发现或管理能力
须说明真实边界和可达的下一步。对可供性的验收包括仅沿实际 CLI 输出的独立走读，不能
以命令有说明或章节齐全替代理解与任务完成。

系统仓分开解释模型、操作入口与运行机制，并提供能力说明和使用指南；CLI help 负责同版本
命令的精确调用。Writer 与 CLI 的说明属于操作入口，不能因它们有公开接口就列作核心模型。
能力的调用入口从既有登记与 help 同源发布，自动检查覆盖命令与入口漂移；完整参数表保持
单一维护来源。系统仓中的指引不代替当前 Server 的启用、就绪和授权判断。

这套结构应让首次使用者逐步了解系统，也让熟悉者直接完成任务。成功路径不强制先做一次
预览或手工拼协议文件；需要检查即将发生什么时，提供明确的只读查看能力。

## 插件能力与可供性的呈现

目标扩展体系中，Plugin 提供能力实现，Affordance 是描述能力的说明规范，CLI/help 是现有
承载方式。说明回答用途、输入输出、适用条件、效果与保证，并给出可理解的例子；插件代码
通过系统开放的服务与过程参与点实现承诺。能力说明关联提供能力的插件和既有任务合同，
不再引入并列的 Interface 能力主体；说明不授予权限，也不证明某个实现
已安装、已就绪或能够在当前目标上执行。

可供性要求落实到当前叶子帮助：读完能够确定怎样输入、需要什么条件、成功得到什么、
哪些状态会改变，以及成本、主要风险和失败后怎样继续。只读查询也须说明结果范围与
完整性，写操作须说明不可逆后果、可能已经发生的独立副作用及可恢复边界；本机写入须
交代覆盖、部分产物与空间成本。各叶用自身真实保证和实例说明，不能用相同的空泛章节
替代内容。完整帮助由模块同源提供给独立入口与统一 CLI，静态阅读不发业务请求或读写
用户输入文件。

首个切片让声明式索引通过插件接缝参与已有发布推进与发现过程，沿用同依据回读。
已有 search、read、access、invoke 等任务继续沿自己的公开入口执行，不按插件重建路径；
独立固定读取不依赖索引。内部登记本身不改写已有任务合同；本篇另行选定只读插件说明
任务与目标概览，公开接线尚待实施。既有叶子帮助按实际行为差异或已定位的说明遗漏同步。

声明式索引插件名称为 `declarative-index`；选定的只读说明示例为
`kc plugin declarative-index help`，尚待公开接线。其能力是按 Schema 字段的 `access` 与类型
执行已有查询，并准备、更新和恢复索引；说明解释输入、结果、条件与保证，不代替当前支持、就绪及授权核验。
OpenSearch 是它采用的物理引擎
driver，不是与该插件同层的业务 Affordance。提供方、投影与维护诊断仍沿已有运维合同
说明，不因 driver 可替换而生成新的业务命令树。

Schema 查看任务的帮助解释字段 `access` 与类型怎样用于查询，并指向插件说明，例如
`kc plugin declarative-index help`。某个来源 Repo 配置了哪些插件，沿已有选定的知识
访问概览呈现，限定于本次来源范围。先落实这两处导航，不把运行匹配结果注入已发布
Schema，也不为旁注新造 Schema 字段或改写机器 JSON 返回；说明可读仍不证明查询就绪。

| 披露位置 | 回答什么 |
|---|---|
| 根帮助 `kc help` | Object 身份、切面/成员、固定读取、Schema 与来源解释、Writer 维护等基础能力；日常从哪里开始，怎样继续读取插件说明 |
| 功能组帮助 | 本类任务有哪些动作，怎样继续了解 |
| 叶子帮助 | 当前动作怎样调用，输入输出、前提、效果、保证和失败后怎样继续 |
| 插件说明 `kc plugin <名称> help`（目标入口） | 该插件增添什么能力，适用什么声明、条件与保证，怎样沿已有任务入口使用 |
| 知识访问概览（待接线） | 本次固定范围内来源 Repo 已配置插件的能力、简短用途和帮助入口；状态与执行仍按各自合同核验 |

根、功能组及已有叶子 help 保持同版本、离线可读，不因展示导航连接 Server 或执行插件。
系统仓出版物与任务 help 同源关联能力和操作入口，不复制另一份完整参数表。
`kc plugin <名称> help` 则是明确的只读说明任务：插件所属模块提供内容或固定说明引用，
统一客户端经 Server 读取，CLI 与 HTTP 消费同一服务合同。读取说明不调用业务处理器、
来源或启动维护；说明关联现有任务及其 help，不形成另一套方法分派。

Repo 保存插件配置，Server 据此按该仓作用域登记并执行贡献；对象保存 Schema、access
及 Binding 等具体声明。Dataset 的知识访问概览聚合范围内来源仓已配置的插件，呈现
简短用途、适用位置和帮助入口，不另设插件配置。直接 Repo 消费使用同一仓的贡献，
写后维护与读取查询也沿同一配置；不要求先创建 Dataset 或每次 read 都展开插件信息。
概览由上层知识任务装配，Snapshot 的 Dataset 文件核心继续组合来源引用，
交付固定文件范围。
声明、支持、就绪与本次授权分别表达，说明可读不证明能力当前可用。

插件说明任务与目标概览的公开接线尚待实施。上述入口是选定交互目标，名称解析、
操作数、版本定位与精确 argv 在公开 CLI 代码、包 README 和 Conformance 落实；
不以文档示例认定命令已可执行，也不把说明读取变成包安装任务。

静态 help 不拼入内部注册表或服务端配置。能够读取能力说明，不表示可以读取其它目标的
配置或来源秘密；插件说明读取与目标概览经 Server 当前授权，目标相关结果仍受本次
Repository/Dataset 范围约束，不借这次展示设计新增 Member ACL 或第二份能力清单。

Server 依据 Repo 配置装配插件，运行贡献与该仓关联，不声称已有公开安装管理能力。
阅读对象声明或插件说明不触发代码加载；Dataset 使用来源仓的贡献，不借此取得
来源整仓、维护或外部源权限。

以后出现真实插件管理任务时，再为该任务定义共享 typed service、管理权限、审计和恢复
合同，由 CLI 与 HTTP 分别登记入口；完整包管理和安装运行视图不作为首批前提。现有
operations Hook 管理仍是出站动作扩展，不兼作 Plugin 注册或内部生命周期配置入口。

## 上下文与本次目标分开

Server 与可信身份属于 Client 已保存的上下文。一套服务只有一个登记空间，连接服务后直接
操作来源或 Dataset；不要求创建、选择或切换 Catalog。登录凭证只负责认证，不保存业务范围。

本次操作的 Repository、Dataset、知识对象和写入命令身份则必须明确。单仓读取不要求先建
Dataset；Dataset 用于消费范围，不能用作 Writer 目标。服务的登记状态不是
默认搜索所有仓的隐式范围。

一次请求在服务端解析一次固定版本。日常消费者按 Dataset 名称使用当前服务版，回执仍可
用于复核；需要重读精确内容时使用明确版本。客户端不要求用户管理内部 pin 文件，也不能
把上一次解析结果伪装成长期有效的授权。

## 一条动作只表达它承诺的副作用

供给或连接仓、登记到服务、发布知识、发布 Dataset 与发权分别可观察、可恢复。
交互可以把它们组织成易懂的旅程，但不能在一个看似“接入”的动作里隐含授予读写权限。
移除已登记成员也不能被描述成删除源仓或清除历史。

写入命令身份由用户明确提供，便于在响应丢失后重试同一次维护。客户端不能为了让调用
看起来方便，在每次重试时偷偷生成一个新身份。`kc diff --dir` 回答这个目录相比固定仓基点会新增、修改什么，不写仓；`kc writer commit --dir` 提交目录变更，回答是否接受及产生哪个版本，用户无须先导出 ChangeSet。当前这两条入口接收对象草稿，发布须经过 Writer 校验；这项输入约束不使目录预览、目录提交成为 Object 的基本操作，也不表示任意文件目录均可直接提交。

`kc writer receipt` 按原命令查询整批写入结果，供响应丢失或结果不确定时恢复；回执不按对象、Aspect 或 Member 分发。目录缺文件不推导删除，删除须显式表达；预览不代替发布校验。文件保存和版本推进由 Snapshot 承担，对象内容的表示、Schema 与来源校验仍由 Object Writer 承担。

预览、校验和发布的区别要体现在反馈中。显示“检查通过”不能让用户以为知识已发布；
源提交成功不能让用户以为 Dataset 已采用更新或检索已经就绪。

## 输出回答用户的问题

| 用户的问题 | 交互应交付什么 |
|---|---|
| 我能在哪些来源里找知识 | 库存、范围和继续了解该来源的入口 |
| 这个 Dataset 接受了哪些来源和发布版本 | 选定发布的定义、来源与元数据，以及当前服务版和有界历史；详情可见不表示文件可读 |
| 交付目录里有什么、其中一个文件是什么 | 一个目录的有界直接子项或一个文件的字节范围，附可继续使用的固定发布依据 |
| 怎样调整已有授权 | 保持规则身份和来源的条件原子更新；同时检查旧、新范围的当前管理权，冲突时保留旧规则 |
| 哪些对象匹配 | 可用于后续读取的稳定命中坐标与必要结果说明 |
| 这一份是什么、读后怎样继续更新 | 内容、来源身份、固定版本及相应维护内容的摘要；目标读取入口直接交付，不要求先运行定位命令 |
| 墙外这个值现在是什么 | 此刻观察值连同其依据，不是声明回显 |
| 哪些关系连着它 | 命中的关系对象坐标；多步邻接走有界遍历，不是路径枚举 |
| 可以怎样查询 | 逻辑字段与访问能力，不是引擎 mapping |
| 有哪些 Schema、结构与约束是什么 | Object 提供 Schema 列举与描述；完整 Schema 正文沿读取取得 |
| 这个目录会改什么 | 相对固定基点的变更预览，不是内部 ChangeSet 倾倒 |
| 这个目录的变更提交了吗 | 是否接受发布，以及产生的仓版本；源提交不代表 Dataset 已采用 |
| 这次写入是否已接受 | 能支持同命令重试与固定版本复核的结果 |

CLI 可以采用面向任务的表示，HTTP 可以保持完整 typed 信封，但二者调用相同应用能力。
编码差异不能改变结果语义、权限与副作用，也不能把未完整查询、未就绪或已失败的任务
打印成成功的空列表。公开 stdout 与退出行为由生产入口维护，设计不另列 JSON 字段全集。

按需文件访问与整棵交付树物化、宿主挂载并列，均复用同一文件网关。浏览后的续页与读取
应显式延续已选发布，不能把多条独立命令默认取当前版说成同一依据；消费者不需要拼装
内部 pin 或建立消费会话。单文件保存不覆盖已有目标，失败不能留下看似成功的目标文件。
文件访问交付的是发布范围内的原始材料，不把文件路径解释成知识对象身份。

现有定位诊断不属于 Object 基础操作，也不是读取的前置步骤。目标读取须交付上述维护依据，当前 CLI 读取输出尚未完整交付，实施时同步公开合同、帮助及读取后更新的回归。

查询定位的缺席是正常答案：现有定位命令未命中时返回明确的未定位回执（单仓一条、Dataset
一个空名单），不当作读取失败；它与“对象存在但解释或读取失败”属于不同失败代数，
交互与脚本都不能把两者混成同一种错误。

交互中的说明、机器可消费的结果与诊断应有清楚边界，使用户能把一次操作接入脚本，而
不必解析随意变化的自然语言。已有协议结果仍是事实来源，提示文字只帮助理解和下一步操作。

## 失败以后怎样继续

用法错误说明本次为什么不成立，并给当前动作的用法；不把整本根帮助倾倒给用户。
身份无效、无权、资源不存在、投影未就绪、版本冲突和暂时不可用，需要给出不同的解释，
不能都引导用户补一个 flag 或重新登录。

没有权限时帮助用户识别缺少的能力，但不在交互里自动发权。查权交互只回答本人当前
授权、部署可选的外部申请地址与授权管理者：平台不托管申请或审批队列，也没有申请对象，
发权由授权管理者通过受控入口执行。索引未就绪时可以查看维护
状态，不能让一次读命令同步建索引。写入响应丢失时，引导沿原命令身份查明或恢复结果，
不能让用户用新身份盲目再提交一次。

正文受保护与查询无匹配也要区分。用户看到命中却无正文时，应理解发现与读取的授权差异；
查询本身不允许的情况下则明确拒绝，不能用遮罩结果掩盖准入失败。

## 同一个应用，多种交互载体

CLI 与 HTTP 各自登记入口，调用同一 typed 应用执行器。HTTP 不调用 CLI 解析器，CLI
也不为了逐项映射 HTTP 路由而增加无意义命令。所有业务调用经 Server 与显式身份，
本机存在目录不构成绕过服务的理由。

文件挂载、产品 HTML 与外部宿主提供不同的使用方式，但不重写授权和版本规则。产品 HTML
负责可独立阅读的任务说明；完整命令和参数来自公开入口，实际旅程来自场景。
Agent 不注册一套模型专用工具，而是调用同一分组 CLI；文件经只读挂载成为普通宿主路径，
`ls`、搜索与查看工具直接可用，用户工作目录的其余路径保持可写。原有 DSH 宿主侧栏集成已
退役，不作为当前产品入口。外部宿主采用知识时仍应明确来源、固定版本、挂载与更新状态；
文件树开关只改人用视图，不改变 Agent 能看到什么。
若后续增加提示式向导或终端全屏交互，它应复用相同上下文与动作；本轮没有选定或承诺
一套新的 REPL/TUI，也不把“能执行命令”视为交互已经完整。

## 取舍与评价

选定任务化入口与逐步披露，减少日常认知负担；代价是需要独立设计 help 与产品结果，
不能直接打印协议对象。选定显式目标与独立副作用，接受少量必要操作，换取授权和恢复清晰。
否决按 HTTP 资源树机械生成命令、用“远程访问”解释每条命令的价值，以及让进阶能力
掩盖日常任务走不通。

评价时先写清用户的一句问题，再比较现有命令、普通文件工具和 HTTP 已经能做什么；
成功输出、失败反馈与帮助首句必须回答同一个问题。布局好看或参数齐全不能代替这三项。

## 硬性约束 / Invariants

- 浏览返回名单：`schema/*` 只点名实体不返回合同正文，有界、分页、按固定依据执行；空查询
  或 `*` 不是浏览。
- Server 唯一确定登记空间；登录凭证不承担保存 Repository 或 Dataset 操作范围的责任。
- 模块命令可独立使用，核心不反向依赖 CLI/SDK；命令与帮助同源，迁移不改任务、副作用与
  授权语义（L-01、API-01、KS-01、AUTH-02）。
- 一次请求在服务端解析一次固定版本；客户端不要求用户管理内部 pin 文件，也不能把上一次
  解析结果伪装成长期有效的授权。
- 供给或连接仓、登记到服务、发布知识、发布 Dataset 与发权分别可观察、可恢复；不能在
  一个看似「接入」的动作里隐含授予读写权限。
- 写入命令身份由用户明确提供；客户端不能在每次重试时偷偷生成一个新身份。
- 显示「检查通过」不能让用户以为知识已发布；源提交成功不能让用户以为 Dataset 已采用更新
  或检索已经就绪。
- 编码差异不能改变结果语义、权限与副作用；不能把未完整查询、未就绪或已失败的任务打印成
  成功的空列表。
- 定位未命中返回明确的未定位回执，不当作读取失败；它与「对象存在但解释或读取失败」属于
  不同失败代数。
- 用法错误给当前动作的用法，不倾倒整本根帮助；身份无效、无权、资源不存在、投影未就绪、
  版本冲突和暂时不可用需要不同解释。
- Agent 不注册一套模型专用工具，而是调用同一分组 CLI；文件树开关只改人用视图，不改变
  Agent 能看到什么。
- Plugin 实现与 Affordance 说明分别承担责任；CLI/help 渐进呈现现有能力，不因每个插件
  增加独立命令树。静态说明不证明运行匹配、就绪或当前授权。
- 首个索引插件接入由 Repo 配置确定参与插件，服务端据此装配，不因内部注册新增公开命令、参数或结果。
  另行选定的插件说明任务与目标概览须落实公开合同；资源元数据和能力说明不触发加载，
  装配选择不隐含发权。
- 根 help 离线解释基础能力并引导插件说明读取；插件说明由所属模块提供、统一经 Server
  读取。知识概览聚合来源 Repo 配置的插件，Dataset 不另设插件配置；
  两者不复制已有任务分派，不把说明当作就绪或授权证明。

## 选定方案 / 被否决方案

选定任务化入口与逐步披露，减少日常认知负担；代价是需要独立设计 help 与产品结果，
不能直接打印协议对象。选定显式目标与独立副作用，接受少量必要操作，换取授权和恢复清晰。
选定根帮助/功能组/叶子帮助三层披露：用户输入尚未完整的功能组时看到就近选项，不能意外
执行某个默认写动作。
选定模块拥有所属任务交互、KC 装配全局上下文；否决把全部交互留在中央再增加模块转发，
也否决为迁移按协议包生成另一套命令树或认证会话。

选定 Plugin 提供实现、Affordance 描述能力、CLI/help 承载渐进说明；现有路径、Action、操作
与结果合同保持。首批以声明式索引实际接入为界，Repo 配置参与插件，Server 据此装配，叶子帮助按实际
差异或已定位遗漏同步。选定离线根帮助、经 Server 的只读插件说明，以及随目标知识访问
概览呈现范围内来源 Repo 的插件能力；Dataset 保持组合，不另配置插件。
说明与任务 help 关联，当前支持、就绪和授权另行核验；否决把完整
插件管理作为首批前提、按插件或物理 driver 生成业务命令树，以及复用出站 Hook 配置充当插件注册。

否决按 HTTP 资源树机械生成命令、用「远程访问」解释每条命令的价值，以及让进阶能力掩盖
日常任务走不通。选定面向任务的 CLI 表示与完整 typed HTTP 信封并存但调用相同应用能力；
评价时先写清用户的一句问题，再比较现有命令、普通文件工具和 HTTP 已经能做什么。

## 方向性用例

### U1：首次进入系统并读到一份知识

用户从帮助了解入口，连接获准服务，发现来源和 Schema，再在明确范围搜索、
读取。无需知道存储地址或索引代际，也不会把可发现误认为已有正文权限。

### U2：接入一个已有仓并分享 Dataset

用户能区分连接、登记、选择文件、发布和授权分别完成了什么。中途停止时已有结果仍清楚，
继续操作不会重复建仓或隐式扩权。

### U3：提交目录后网络中断

用户持原命令身份重试，得到同一已接受结果或明确的恢复状态；不会被要求换一个身份
才能继续，也不会把 post Hook 失败说成知识未提交。

### U4：命中对象但没有正文读权

交互说明当前可发现与可读取的差异，后续读按真实授权返回。对于 Dataset，范围外对象
根本不能借这条交互被发现。

### U5：搜索未就绪或输入写错

两种失败给出不同反馈。前者不返回零命中、不现场建索引；后者显示当前叶子的原因和用法，
用户无需翻整套设计书才能修正一次输入。

### U6：脚本与人工使用同一动作

脚本得到稳定的公开结果与失败语义，人工有可理解的帮助与恢复指引。切换到 HTTP 后，
授权、固定版本与副作用保持一致；只有面向使用者的表示可以不同。

### U7：声明式索引通过插件接缝执行既有查询

Repo 配置声明式索引插件，服务端据此登记贡献；写后维护和读取查询使用同一仓配置。
使用者沿已有入口发布、查询和读取，在既有 describe
及执行反馈中理解访问声明、固定范围与就绪状态。不要求先操作新的安装命令，也不把物理
引擎选择当成新的业务能力；当前授权、同依据回读和未就绪失败语义保持。

### U8：从基础帮助了解来源适用的插件

用户离线阅读 `kc help`，理解固定对象读取与维护等基础能力，找到插件说明入口。
连接获准 Server 后，在 Dataset 知识访问概览看到所选来源 Repo 已配置的插件、
简短用途和帮助入口，
再通过 `kc plugin <名称> help` 读取所属模块的说明，并沿既有 search/read/access/invoke
任务帮助完成使用。直接 Repository 消费得到同样引导，不必额外发布 Dataset。
缺说明、来源 Repo 未配置插件、配置的实现未加载或未就绪如实区分；组合不改写来源配置。
整个说明过程不执行来源操作，不替换本次授权。
Schema 查看任务的帮助解释 `access` 并指向相应插件说明；纯 Schema 与机器 JSON 返回
不因导航提示或运行匹配而变化。帮助不把 Schema 声明已存在说成该仓已配置插件或索引已就绪。
