# Dataset：交付

Dataset 是多团队协作里的交付单元：为某个用途从多个团队的仓里挑选内容、固定版本，单独授权给
使用者。用户用的是对象，找的是 Dataset：Dataset 决定这一次能看到什么、看到哪一版、凭什么有权看。
它停在文件层，没有知识层也能独立使用。

Dataset 只做三件事：可见范围、固定版本、消费权限。它不负责把对象拼完整（同一 ID 的方面由对象层
自然归到一起，见[对象](object.md)），也不决定插件行为（插件声明在类型上，见[插件](plugins.md)）。
拿 Spring 类比，它更像发布用的 BOM，而不是容器。

## 目标

- 按用途组合，不复制来源仓的布局，也不复制字节。
- 发布时固定每个来源的版本。来源后来改了不影响已发布版本；再发一版，新请求才使用新版。
- 有自己的消费权限。能消费 Dataset 不等于能读来源仓，能读来源仓也不等于能消费某个 Dataset。
- 消费方日常只用名称，系统默认采用最新发布版；需要复核时，结果里带着具体依据。
- Dataset 不是发现的唯一入口。调用者也可以在自己可读的全部仓里按类型发现。

## 例子

运维组发布 `oncall`：

| 来源 | 交付位置 |
|---|---|
| 交易团队仓的 `services/orders/` | `services/orders/` |
| 支付团队仓的 `services/payments/` | `services/payments/` |
| SRE 团队仓的 `runbooks/common.yaml` | `runbooks/common.yaml` |

值班 Agent 只有 `oncall` 的消费权。它看到统一的目录，每个文件仍能追溯原仓、版本和原路径。

## 组合规则

- 可以选目录，也可以选单个文件；目录保持内部的相对布局，单文件要明确交付位置。
- 同一个交付文件只能有一个来源，冲突时拒绝，不按顺序覆盖。不同仓的同名文件可以放在不同位置或改名交付。
- 目录结构也是发布内容，只调整交付路径也要发新版。
- 不拼接文件、不改写文件里的标识或相对引用，交付路径不是对象身份。对象身份只看 `object_id`。
- 同一对象的同一方面来自两个来源仓时，拒绝发布，指出冲突的对象、方面和来源。
- 空清单不是“整个仓”；未选中的相邻文件不能被读取或列出。
- 可选的自定义键值元数据随发布保存，改元数据也要发新版，不扩大范围、不改变授权。

## 发布

发布是一次可恢复的采用决定：先固定候选版本，检查范围、路径冲突和发布权限，再接受一条不可变
记录并切换当前版本。

- 消费方只能看到已接受的记录，看不到准备到一半的。
- 两个维护者并发发布时，不会覆盖对方的历史，也不会让当前版本退回旧版。
- 发布中途失败，来源仓的提交仍然成立，原有发布版继续服务。
- 选入每个来源需要该来源的内容发布许可；只有 Dataset 管理权的人不能借此选入自己无权的私有来源。
- 启用了索引时，新版的索引准备好之后才切换；准备失败保留旧版。这是知识层附加的条件，纯文件发布不需要。

## 消费

- 一次请求只解析一次 Dataset 版本，后续的读取、列目录和翻页都用同一范围和版本。
- 客户端带来的版本坐标只是坐标，不是授权；撤权后下一次请求就拒绝。
- 已发布版本引用的来源版本必须保留；来源版本不可用时明确报错，不自动改读最新版。
- 退役 Dataset、移除登记成员、删除来源文件是三种不同操作。

## 交付方式

| 方式 | 适用 |
|---|---|
| 服务端读取与目录分页 | 默认方式，按需读单个文件，也适合在采用前挑选和核对材料 |
| 只读挂载 `kcfs` | 本机放得下的 Dataset；Linux FUSE；挂载点必须不存在或为空；不自动跟随新版 |
| 知识层消费 | 在 Dataset 范围内读对象、搜索，继承同一范围和版本 |

挂载不是编辑入口。修改要回到具体的来源仓，经 Writer 提交，再发布新版 Dataset。写回多个仓时
是多次单仓提交，第二个失败不回滚第一个，系统如实报告部分完成。

## 用例

场景树按 `dataset#U<编号>` 关联验证入口和缺口，见 [测试](../engineering/testing.md)。

### U1：把两个来源组合给使用者

发布者选择两个仓的文件，使用者只得到选中的范围。同名文件映射到不同目标位置，并保留各自来源；
没选入的相邻文件不能通过补读出现。

### U2：源更新之后发布新版

源仓已经更新，使用者仍读当前发布版。新布局冲突、来源版本不可用或发布未被接受时，继续保留
当前版；新版被接受后，新请求用新版，已经打开的视图不漂移。

### U3：撤权以后继续使用旧 pin

使用者保留了旧文件清单和版本坐标。撤权后的新读取必须拒绝，不能因为版本不可变就绕过当前授权；
已经交付到客户端的字节不承诺能远程收回。

### U4：退役与来源保留

维护者停用 Dataset 或移除某个来源登记，系统按当前生命周期拒绝不再允许的消费，
但不因此删除源仓内容或改写它的历史。

### U5：两个发布者并发发布

其中一次发布被接受后，另一方不能覆盖同一版本号、回退当前版本，或让使用者看到半份清单。
准备工作可以重试，已接受的发布必须保留。

### U6：只发布目录中的部分文件

目录里有公开说明和没选中的内部文件。使用者只能枚举和读取选中的内容，即使某个已交付文件
引用了内部文件，也不自动补上；路径中间的父目录跳转同样不能越过范围。

### U7：没有对象层也能交付文件

来源只有普通文本、图片或代码，没有 Schema，也没有索引。发布和文件读取照样成立，交付的字节
保持原样；文件里含 URL 或声明文本，读取时也不触发解析、外部请求或内容改写。

### U8：把 Dataset 接入已有项目

使用者得到明确版本的只读视图，原项目文件保持原状。新发布到来后，已有挂载继续用原版；
采用更新、隐藏界面入口和撤销权限分别是不同的操作结果。

### U9：从多个仓挑选子目录，交付统一目录树

维护者发布 Dataset，使用者在新目录位置枚举并读取所选内容。一个仓的两个片段可以出现在
不同位置，来源身份与版本仍可追溯。上游其他目录不可见，源布局不变。调整交付路径后发布新版，
已打开的旧视图继续按旧路径工作。

### U10：挑选零散文件放到同一个交付目录

维护者从不同仓选几个文件，分别指定目标文件名。使用者只看到选中的文件，不带出来源文件夹里的
其他内容；目标冲突明确拒绝。发布、目录枚举、文件读取与授权要一起成立，`kc dataset clone`
能把交付目录物化为普通本地目录。

## 代码位置

定义、发布、历史和路径组合在 `snapshot/dataset/`；文件 HTTP 在 `snapshot/service/`；
管理页面在 `snapshot/console/`；挂载在 `datasetfs/` 与 `cmd/kcfs`。

## 进度

| 进度 | 内容 |
|---|---|
| 已有 | 目录与单文件组合、发布时固定版本、独立消费权限、默认最新发布版、启用索引时准备后切换、自定义元数据、只读挂载 |
| 近期 | 同一次 Dataset 定义的重复提交幂等；发布时检查方面冲突；不再承担插件配置汇总 |
| 未到 | 真实部署下准备失败保留旧版、重启后接续发布的验证 |
