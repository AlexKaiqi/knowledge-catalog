# 服务

服务层是所有请求的统一入口：确定身份、范围和版本，检查授权，交给所属模块执行，留下证据。
它也负责装配插件和管理生命周期。

## 目标

- 同一业务任务无论从命令行、HTTP 还是 SDK 进入，都由同一个执行器处理，规则只有一份。
- 部署方一次性建立服务、存储和准入策略，之后不参与日常。
- 可恢复的单实例：替换实例后，原来的历史、授权和操作结果都还在。
- 访问证据和运行诊断各有用途，不能互相代替。

## 一次请求

1. 认证：得到可信的用户名。每个请求自带凭证，服务端没有会话。
2. 授权与范围：按当前政策确定能做什么、在哪个范围内。
3. 固定版本：一次请求只解析一次版本，之后所有读取都用它。
4. 执行：交给所属模块的服务，例如 `object/service`、`discovery/service`。
5. 交付与留证：按政策交付结果，承诺留证的读取先可靠保存证据再返回。

版本坐标不带时效、不绑定身份，不是可以转授的凭证。服务端可以缓存按版本解析的结果，但缓存不能
变成会话。

## 跨模块任务

服务层负责几件跨模块的编排，每件都有明确的失败归属：

- Dataset 发布且启用索引时，先接受记录并同批登记构建意图，索引在后台构建；构建失败只让该版本停在
  检索未就绪，不回滚来源提交，也不撤销接受。
- 评审在工作分支上进行，Writer 合并前校验对象并调用 `writer.merge` 前置 Hook，再条件合并。
- 把对象交给模型时保留固定引用、内容摘要和来源；模型推断与已接受的对象明确区分。

这些编排不把索引塞进 Dataset，不把 Hook 塞进 Writer，也不把业务规则分散到命令行、HTTP 和插件里。

## 文件网关

所有文件读取都经过服务端的文件网关：服务端凭证不下发，每次读取重新授权，访问证据完整，字节绑定
同一版本。本机挂载也连网关，不直开来源仓。

## 恢复

| 状态 | 要求 |
|---|---|
| 仓、登记与 Dataset 历史 | 恢复原权威，不从缓存猜 |
| 身份、授权、供给记录、写回执（含合并回执） | 保持已作出的决定和幂等结果，缺失不能当空状态重建 |
| 外部观察的保留记录 | 履行承诺的复核期限，丢失须明确报告 |
| 索引、工作副本、正文缓存 | 可丢，按明确依据重建 |

初始化是显式管理动作，启动只恢复。客户端的本地覆盖、凭证、挂载生命周期不属于服务端的恢复范围。

## 证据与诊断

| 类别 | 回答什么 | 规则 |
|---|---|---|
| 访问证据 | 谁基于什么版本做了什么访问 | 承诺留证的读取在证据可靠保存前不能报成功；独立入口按权限读取；不进入搜索 |
| 查询归因 | 一次搜索用到了哪些索引声明成员、各起什么作用 | 随查询结果证据保存；回读的访问证据关联到它 |
| 反馈 | 使用中发现了什么问题，或是否采纳某个命中 | 只关联已发生的访问；不自动批准修订，不发写权 |
| 运行指标、日志、追踪 | 健康、耗时、瓶颈 | 指标不采样，日志与追踪可采样；不代替访问证据；追踪头异常不导致业务失败 |

访问次数、反馈和模型结果都不自动成为对象、授权规则或训练标签。插件按声明成员汇总使用记录，只作为
数据公开给 Dataset 的维护者，不给建议、不写分支，见[发现](discovery.md#使用记录)。调用方绕过服务直读
存储时，平台不声称有逐条审计。

## 部署与认证

- 认证方式：local（本地测试）、Taihu（推荐经太湖网关）。认证是可替换的能力：新增或替换一种认证方式只在
  `identity/` 下加一个子包并注册，服务与授权代码不改，授权语义不变。
- lakeFS 只作存储，不作身份来源。KC 在认证与授权之后用部署的服务私有凭证访问 lakeFS，用户凭证不转发。
- 未配置认证器时不接受裸 Bearer，不把测试身份当默认回退。
- 部署脚本与环境说明在 `scripts/deploy/`；本地运行 `kc serve`，进一步拆成多个进程是部署选择。

## 用例

场景树按 `service#U<编号>` 关联验证入口和缺口，见 [测试](../engineering/testing.md)。

### U1：同一任务经命令行与 HTTP 执行

两个入口在相同身份和范围下得到相同结果；不能一个入口固定版本、另一个读最新，
也不能直接打开本机仓绕过 Server 授权。

### U2：替换实例后继续使用

原登记、身份、权限和写回执都能恢复。重放建仓或准入请求不创建第二份资源，
不重新授予已撤销的权限；状态丢失时明确要求恢复。

### U3：把 Dataset 接入已有工作项目

使用者采用确定版本的只读视图，原项目文件保留。采用更新是显式动作，
隐藏界面入口不改变文件访问或权限。

### U4：证据存储故障

需要证据的消费不假装记录成功；已接受的写入仍返回真实的接受结果，
后续投递与诊断失败可以单独追踪，不诱导使用者重复发布。

### U5：第一次接入并发现可用对象

使用者用同一个已认证身份了解来源与 Schema、选择 Dataset、搜索并读取。有界浏览给出名单式入口，
搜索覆盖关键词与过滤；名单、自描述说明和正文权限分开说明。使用者不需要知道存储地址，
也不能借发现扩大范围。

### U6：定位一次读取为什么慢

使用者能区分客户端、范围解析、候选查询和同版本回读各自的耗时；展开目录只读一页直接子项，
浏览器、插件、文件网关与授权分段计时，本机目录首屏 p95 超过 100ms 视为回归。连接或查看已有
固定视图不触发隐式全库扫描。延迟目标和规模资格由压测场景证明。

## 代码位置

| 目录 | 负责 |
|---|---|
| `server/` | HTTP 路由、处理器、调用认证判定与授权强制 |
| `httpsurface/` | 已退役（ROUTE-MANIFEST-01）：封闭路由清单只留在 `server/routes.go`，金样为 `server/routes_golden.txt` |
| `invocation/` | 一次已解析调用的载体，连接授权、固定范围、证据与所属服务 |
| `invoke/` | 命令行与 HTTP 共用的调用词汇 |
| `home/` | 部署装配：连接存储、装配 Writer、Reader、插件，统一启停 |
| `identity/` | 认证器注册表与请求认证判定、具体认证器子包、身份绑定 |
| `delivery/` | 结果交付链：把对象内容变成调用方可见的形式 |
| `observability/` | 访问证据、检索与反馈记录 |
| `client/` | 模块 SDK 组合；`auth/` 拥有认证运输与身份 SDK；`session/` 拥有持久登录、逐请求重读与刷新；地址与路径算法共享 `internal/clientconfig` |

## 进度

| 进度 | 内容 |
|---|---|
| 已有 | 统一执行器、无会话认证、文件网关、可恢复单实例、命令幂等、访问证据与反馈、指标与追踪；请求级视图隔离印记，并发写由版本化条件提交裁决，没有进程级调用锁 |
| 近期 | 路由清单只保留一份；登录与会话代码收进 `client/`；拆分 `home/` |
| 未到 | 多实例部署、分布式协调与租约、灾难恢复；多语言 SDK；生产级 SLI 与告警 |
