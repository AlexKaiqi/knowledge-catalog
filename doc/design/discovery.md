# 发现与声明式索引

discover 回答“有哪些对象，哪个适合这个任务”。已知对象身份时直接读；不知道时先找到要用的 Dataset，
再在 Dataset 里搜索，最后按同一版本回读。声明式索引是实现搜索的插件，适合某一类对象数量很多的场景。

## 目标

- 搜索只有一种范围：一个 Dataset 的一个发布版。交付给使用者的是 Dataset，检索空间也跟着它走；
  跨仓、跨类型在 Dataset 里自然成立，不再有“调用者可读的全部仓”这种临时范围。
- 索引怎么建由 Dataset 的维护者声明。声明是对象，经 Writer 发布、有版本和来源，选进 Dataset 才生效；
  Schema 只描述结构，插件不自行决定索引什么。
- 声明可以写得很细：哪些字段、怎样组合、用什么分词或向量模型，都是声明的一部分，系统按声明构建，
  不在代码里写死。细粒度只在插件实例公开的能力清单之内。
- 系统只负责两件事：用 Affordance 说清能配什么，按声明解释执行。意图由谁提出、配置由谁生成，
  不归系统管；业务可以接入自己的 Agent，读说明后和用户确认意图、写出声明。
- 索引只给候选，内容必须按同一版本回读，避免“直接读”和“搜到后读”变成两种结果。
- 未声明、不支持、未就绪、预算不足、确实没有匹配，几种情况明确区分。
- 索引可以丢失重建，不是内容权威。
- 每次使用索引都留下可归因的记录，并作为数据公开；判断哪条声明有没有必要、要不要改，归维护者。

## 找到 Dataset

搜索之前先确定用哪个 Dataset。服务库存按调用者的消费权限列出他能用的 Dataset，附带名称、用途说明
和元数据，可以按名称和用途做简单匹配。这是库存层的列举，规模小，不经过对象索引。

- 生产方想搜自己的仓，就发布一个只包含这个仓的 Dataset。
- 需要“全局搜索”时，由平台或某个团队显式维护一个大的 Dataset，例如 `all-services`。它和其他
  Dataset 一样有人声明索引、有人承担成本，不另设特殊范围。

已知对象身份时的直接读取不受影响，仍在 Dataset 或调用者可读的仓里解析，见[对象](object.md)。

## 索引声明

索引声明是一个对象的 `index` 方面，由 Dataset 的维护者写在自己的仓里，像其他文件一样选进 Dataset。
只有选进 Dataset 的声明在这个 Dataset 里生效；来源仓里的声明不跨到别的 Dataset。

每一条声明是一个成员：成员键是这条声明的稳定名字，正文说明一个检索字段怎样构建，包括输入、
构建方式和用途。输入用对象引用的定位符指向 Schema 里的字段，可以有多个。示意：

```json
{
  "object_id": "ops/oncall-search",
  "aspect": "index",
  "member_key": "service-semantic",
  "schema_ref": "kc/index-declaration",
  "value": {
    "catalog": "declarative-index/opensearch@2026-10",
    "inputs": [
      {"from": "schema/service.definition#/fields/name"},
      {"from": "schema/service.definition#/fields/summary"},
      {"from": "schema/oncall.guide#/fields/body", "maxTokens": 512}
    ],
    "build": {"kind": "vector", "template": "{name}\n{summary}\n{body}", "model": "embed/bge-m3@2026-09"},
    "uses": ["semantic"]
  }
}
```

- 输入指向 Schema 文档里的字段，而不是某个实例，所以一条声明覆盖 Dataset 里采用这个 Schema 的全部
  对象。定位符沿用对象引用的写法，不另加通配语法。Schema 按 ID 引用，可以固定版本。
- 多个输入可以来自同一对象的不同方面，按 `object_id` 组合；某个对象缺少其中一个方面时，按声明里
  写明的缺值处理构建，不从范围外补读。
- 构建方式只能从能力清单里选。会影响结果的部分（分词器、同义词表、向量模型）必须带版本；换版本
  就是改这条成员，触发重建。
- 声明写明所依据的能力清单版本。插件按这个版本核对，清单里没有的写法，这条成员标为“不支持”并
  说明原因，其他成员照常构建。
- 写入时 Writer 检查输入能在所引用的 Schema 上解析，构建方式在形状上合法。Schema 后来删掉了字段，
  这条成员标为失效，查询它明确报失效，不当作零命中。
- 成员键是声明的身份，归因和使用记录都挂在它上面。改输入或构建方式是更新同一成员；换键等于撤下
  旧声明、新建一条。可以并存两条配置不同的成员做比较，使用记录分别统计。
- 声明里不写插件实例、引擎地址、分片或容量，这些属于部署和插件实例的配置。
- 系统不按字段类型自动推出默认声明，也不现场生成声明。
- 输入是外部单元时，只接受取值描述为 `shared` 的；`per-caller` 的值进共享索引会越过外部系统的授权，
  见 [LiveAccess](liveaccess.md#规则)。成员覆盖的单元里只要有一个 `per-caller`，整条成员标为不支持并
  列出这些单元；不逐单元跳过，因为跳过会让过滤结果悄悄不完整。需要索引其中共享的那部分时，把它
  建模到单独的方面。
- 重建按成员进行：改一条成员只重建它涉及的检索字段，不重建整个 Dataset 的索引。
- 调优效果要先试再改。试运行只校验写法，不评估效果；做法是另建一个 staging Dataset，选入同样的来源
  和候选声明，比较之后再把声明改进正式的 Dataset。这不需要新机制，只是两个普通 Dataset。

## 能力清单

能力清单是声明式索引的 Affordance：这个插件实例支持哪些构建方式、每项的取值范围、改了要不要重建、
有哪些上限。清单按插件实例公开，不按插件：同一个插件，装了中文分词、配了向量模型的实例和没有的
实例，能力不同。清单有版本，摘要进入索引的物理摘要，清单变化会触发受影响成员重新核对。

首批 OpenSearch 实例开放的能力：

| 类别 | 可配置 | 对应 OpenSearch | 改了是否重建 |
|---|---|---|---|
| 全文 | 分词器（从清单里选）、同义词表引用、前缀补全 | `text` 加 analyzer、`edge_ngram` | 是 |
| 精确 | 规范化（如转小写） | `keyword` 加 normalizer | 是 |
| 过滤与排序 | 数值、日期、布尔、范围 | `long`、`double`、`date`、`boolean` | 是 |
| 向量 | 已登记的模型及版本、距离、拼接模板、截断长度 | `knn_vector`（hnsw） | 是 |
| 组合 | 多个输入拼成一个检索字段、按字段加权 | 由编译器生成 | 是 |
| 数组 | 平铺，或保留元素边界 | 平铺字段或 `nested` | 是 |
| 打分 | 全文字段权重、混合检索的归一化方式和权重 | 查询时 boost、search pipeline | 否 |

不开放：原始 mapping 与 settings、脚本、任意 ingest pipeline、分片与副本数。关系的邻接索引由系统
固定构建，不经声明。

清单里的类别用中立的名字，具体可选值可以沿用引擎自己的名字。换引擎时换清单，声明的写法不变。

清单从三个入口读到：`kc plugin declarative-index help` 给人读的说明；describe 给机器可读的清单；
访问概览列出这个 Dataset 里的声明由哪个实例解释、清单版本是什么。另有试运行校验：给出一份声明，返回逐成员
是否支持、哪里不合法、会不会触发重建，不写入任何东西。

## 访问原语

查询方式和声明分开，调用者学一次就够，不随某个 Dataset 的配置变化。查询里不出现成员键：过滤和
排序按 Schema 字段的定位符写，全文和语义只给查询文本，具体用哪些成员由插件规划，并在结果依据里
写明。

| 原语 | 调用者给什么 | 和声明的关系 |
|---|---|---|
| search | 查询文本，加上按字段定位的过滤和排序 | 插件选用成员，结果标明每个命中由哪些成员以什么角色参与 |
| read | 命中坐标和版本 | 不走索引，按同一版本回读 |
| relations | 对象、关系类型、角色、方向 | 系统固定构建，不需要声明 |
| traverse | 起点、关系约束、跳数上限 | 系统固定构建，有界 |
| feedback | 某次回读、是否采纳、可选原因 | 关联到参与那个命中的成员 |

## 从声明到结果

1. 固定本次 Dataset 发布版，以及选进的声明版本和解释它们的插件实例。
2. 结合选进 Dataset 的声明、实例的能力清单和预算，选择合法的执行路径。
3. 插件返回候选坐标，并标明每个候选由哪些声明成员以什么角色参与（过滤、排序、全文打分、语义召回）。
4. 对象层按同一版本回读，必要时补判条件。
5. 返回命中、依据，以及结果是否完整。

声明了不等于插件支持，插件支持也不等于这一版已经就绪。三者都满足、并且调用者能消费这个 Dataset，
才能执行。Dataset 的消费权限是整体的，能消费就能读清单里的全部内容，检索结果不再逐对象过滤权限。

## 完整性

- 两个条件分别能执行，不代表合在一起也能。先各取少量命中再求交可能漏掉结果，无法证明时拒绝。
- 必需的部分没有能力执行时默认失败。只有调用者显式允许尽力而为，才返回部分结果并如实说明。
- 一个 Dataset 是一个检索空间、一套打分，内容可以来自多个仓，每个命中保留来源仓和版本。
- Dataset 没有声明查询用到的字段时，明确报“未声明”，不当作没有匹配；标为不支持或失效的成员同样
  单独说明。
- 关系遍历是有界的：固定范围，按类型、角色、方向扩展到显式跳数上限，越界停下并标明。
- 语义召回（semantic、hybrid）只在已准入的范围内召回，结果标为近似；缺向量能力时失败，不降级冒充。
- 用到外部值的条件按建索引时的观察执行，回读取到新观察后补判，不再满足的命中淘汰；结果标明用到
  外部值的条件和观察时间。

## 不做什么

不提供任意字符串查询语言、SQL、正则或通配；没有“列出全部对象”；分面和总数不随搜索返回，需要时
做成独立能力；查询碰到未声明的条件时不现场建索引；核心不替业务提出意图、生成或修改声明（可选的
发现包见下文）。这些边界
保证每次查询都能说清覆盖了什么。

## 翻页与预算

- 一个后端页不等于一个产品页，补判淘汰后要继续取。预算用尽时报告限制和续页位置。
- 续页沿用原查询和原版本。原依据不可用时要求重新开始，不接到新的索引上。
- 取消要向下游传播。

## 索引维护

- 通知缩短延迟，对账保证恢复。通知丢失、重复、乱序或进程重启后，最终结果等价于重建。
- 只有解释规则连续时才增量更新。声明、所指 Schema 或能力清单变了，受影响的成员和对象要重新判断。
- Dataset 发布时只冻结来源版本与选进的声明并接受记录，索引作为该版本的后续任务按冻结来源准备、
  按来源差异增量。固定的 Dataset 不跟随来源的最新版本。
- 接受与检索就绪是两个状态。版本被接受即对文件读取生效；检索就绪是同一版本上的第二个状态，构建期间
  检索继续服务上一个已就绪版本，检索视图只在目标版本就绪后前移。构建失败不改变已接受事实，只让该版本
  停在未就绪，重试由下一次发布或显式准备触发。
- 发布由维护者手动触发，或在来源分支前进时由系统自动触发（见[Dataset](dataset.md)的跟随）；两者走同一条
  路径。搜索永远看不到构建到一半的版本：要么整份旧版，要么整份新版，不混合、不返回部分文档。
- 默认搜索解析到最新检索就绪版本，并在响应里回报实际使用的版本号。显式指定版本且该版本未就绪时返回
  未就绪，不静默回退到上一版。
- 逻辑上每个 Dataset 版本是一个检索空间，查询依据是“Dataset 加版本”。每个版本物化自己的查询语料：
  选入范围、统一打分统计、倒排与 ANN 结构随版本冻结，不跨版本共用。打分统计若共用，同一版本的检索
  行为就会随别人写入而变，归因链随之断掉。成员的计算产物（成员值与已生成向量）可以跨版本复用，
  条件是成员有效输入与构建依赖一致；复用不改变每个版本各自的语料边界。这是实现选择，语义只看版本。
- 构建进度按对象计：`done` 与 `total` 都数对象，包含被声明排除、不产出文档的对象；`objectCount` 是
  可检索文档数。构建结束时 `done == total`，而 `objectCount` 通常更小，两者不相等也不互相印证。
  未配置索引实例时进度查询返回能力不可用，不退化成“没有构建”。
- 能搜哪些版本由 Dataset 的检索保留策略决定：当前版本总能搜；超出保留的版本搜索明确报“检索已不可用”，
  不当作零命中；已退役的版本读取和搜索都拒绝。被替换的版本在续页宽限内续页可用。
- 准备受 Dataset 配额约束，超出时不接受新版本；自动发布有最小间隔。紧急清除时，与保留版本共用的
  物理索引按受影响的对象重写，见[Dataset](dataset.md#紧急清除)。
- 多个 Dataset 的实际构建输入与解释一致时，可以复用已有构建值；直接复用查询结构还须保证范围、打分和
  续页等价，不能仅凭同一来源提交或字段子集判定。复用条件、成员增量与回收闭环见[索引物理布局](index-physical.md)。
- 每个实例的进度、失败和退出相互隔离，一个阻塞不影响另一个。
- 搜索只检查是否就绪，不触发构建，也不靠扫描全仓弥补。

## 使用记录

使用记录是一条链路，每一环都关联上一环：

| 环节 | 记录什么 | 记在哪里 |
|---|---|---|
| 查询 | 查询条件、参与的声明成员及角色、声明版本；因未声明而拒绝的条件 | 查询结果的证据 |
| 回读 | 回读了哪个命中，关联到那次查询 | 访问证据 |
| 反馈 | 采纳或不采纳这个命中，可附原因，关联到那次回读 | 反馈 |

- 信号分三层：进入候选、被回读、被明确采纳。只有明确采纳是强信号；没有反馈不等于不采纳。
- 过滤类成员对命中是必要条件，打分类只是贡献，汇总时分开计。
- 因未声明而拒绝的条件说明“缺一条声明”，和“某条声明没用”分开统计。

插件按声明成员汇总这些记录，连同索引体积、维护延迟这些成本，作为数据公开给 Dataset 的维护者：
每个成员进入候选、被回读、被采纳的次数，因未声明被拒的条件，以及所占成本。插件不给建议，也不写
任何分支；要不要新增、撤下或调整成员，由维护者（或他接入的 Agent）读数据后自己决定，经 Writer 发布。

- 汇总不扩大谁能看到谁的访问：样本只给引用，查看原访问仍按访问证据的权限。
- 使用记录不进入搜索，不成为授权规则，见[服务](service.md)的证据规则。

## 插件与作用域

声明式索引是插件 `declarative-index`，是 `index` 方面的解释器，不绑定 Dataset 或仓。部署装了它，
声明里的能力清单名由部署对应到实例；选进 Dataset 的索引声明决定索引什么。没装时 `index` 方面只是
普通方面，在这个 Dataset 里搜索明确报没有检索能力。谁使用、谁声明、谁承担索引成本，都落在 Dataset 的维护者身上，来源仓只提供
内容。同一对象的多个方面按 `object_id` 合并，见[插件](plugins.md)。

## 发现包（可选）

discover 不在核心里封装。核心提供访问原语，并把调用方的检索过程记成使用记录；调用方可以自己编排原语，
也可以用一个可选的发现包。发现包的合同只看输入和输出，内部是规则、多步检索、模型还是从使用记录学出的
策略都可以，是不是 Agent 不重要。

它像 Agent 可以选装的 web search：装了就把任务交给它，拿回命中再自己去读；不装也能用，只是筛选的
精力花在调用方自己身上。它也像 web search 一样靠使用记录越用越准。和 web search 不同的两点必须守住：
结果说明覆盖了什么、哪里不完整，而不只是给出排在前面的几条；每个命中绑定 Dataset 版本和得来的原语调用，
事后能按同一依据复现。

发现包不是[插件](plugins.md)。插件由部署安装，解释仓里的声明，是核心能力的一部分；发现包不解释声明，
建在访问原语之上，和调用方自己写的编排处在同一层，没有特权。

- 输入：任务说明、Dataset 和预算。不给 Dataset 时，发现包按调用者的消费权限在库存里选。
- 输出：命中对象，形状与 search 的结果一致：命中坐标和 Dataset 版本、每个命中由哪些原语调用得来、
  结果是否完整及原因。只给命中，不给回答或摘要；内容由调用方按同一版本回读。

规则：

- 只用公开原语，以调用者的身份执行，没有特权路径。调用者没有消费权的 Dataset，发现包也用不了；
  调用者自己编排原语能做到的，发现包不多给。
- 原语报的未声明、不支持、未就绪、不完整照实传出，不包装成没有匹配。
- 任务说明就是意图，连同每一步原语调用进入使用记录。调用方自己编排时同样记录，两条路径的数据进入同一套
  汇总，换用别的实现不丢数据。
- 实现有版本，使用记录写明用的是哪个版本，优化效果才能归因和比较。
- 发现包优化的是它自己的执行策略。它想改索引声明时只能给出候选，在 staging Dataset 上比较后由维护者经
  Writer 发布，不直接改声明。
- 部署形态和代码位置待确认。

## 入口

`kc search`、`kc relations`、`kc traverse` 在一个 Dataset 里执行查询；`kc plugin declarative-index help`
说明声明写法、能力清单、试运行校验和使用记录。

## 用例

场景树按 `discovery#U<编号>` 关联验证入口和缺口。先写用例、跑基线，再改接到绿。

### U1：字段

文本、数字、日期和缺值的检索排序，核对结果集合和值；未声明、类型错误、有歧义、不支持的组合
明确拒绝；缺值、不适用和取值失败分开说明。

### U2：Dataset 是检索空间

两个仓各有一种类型的对象，组合进同一个 Dataset，并选进一份索引声明。同一查询在 Dataset 里同时找到
两类对象，每个命中带来源仓和版本；同样的来源组合成另一个没有声明的 Dataset，查询明确报未声明。
插件没装、清单名没有对应实例、撤销消费权限都明确拒绝；不提供不带 Dataset 的搜索。核对总预算、排序与续页；
访问概览与实际生效的实例、清单和声明一致，帮助只读。

### U3：更新恢复

增删改对象、声明和 Schema，通知丢失、重复、乱序，重启或删除索引；自动恢复的结果和重建等价，
固定的 Dataset 不跟随 HEAD。

### U4：原子与失败

命中 Dataset 版本 a 后，Dataset 推进到 b；对象值、声明、Schema 和范围仍属于 a，或者明确失败。
构建、准备、接受失败或接受前取消，都不公开半成品，保留当前发布版。来源分支前进触发的自动发布同样
如此。b 接受后 a 超出检索保留时，在 a 上搜索报检索已不可用，按固定版本读取 a 照常。

### U5：分页回读

第一页或动态命中之后源更新，续页和回读沿用原依据。引擎失败、坏坐标、错版本、正文或原观察丢失、
过期、换实例都明确失败；发布失败保留原观察，不冒充零命中。

### U6：隔离退出

两个插件实例用同一引擎服务两个 Dataset，一个阻塞或失败不影响另一个。后台身份不随请求变化。
构造失败按逆序释放；退出时先停新请求，等在途请求与维护结束，资源只释放一次。

### U7：索引声明

在维护者的仓里发布一条声明并选进 Dataset 后，Dataset 里采用目标 Schema 的对象可按声明检索；没选进的
声明不生效。输入不能在 Schema 上解析时写入拒绝；Schema 删掉字段后成员报失效。一条成员拼接两个方面
的字段建向量，缺一个方面时按声明的缺值处理。改构建方式是同一成员的新版本并触发重建，只改打分权重
不重建；换键是撤下加新建。Schema 里写访问声明、声明里写引擎或实例，都明确拒绝。引用 `per-caller`
外部单元的成员标为不支持；只改一条成员时其他成员的检索字段不重建。

### U8：能力清单与试运行

读到实例的能力清单与版本；按清单写的声明试运行通过且不写入；用了清单外的分词器或模型时，试运行
与准备都把该成员标为不支持并说明原因，其他成员照常构建。清单升级后受影响成员重新核对。

### U9：使用记录

一次查询用到两条声明成员：结果证据列出两者及角色；回读关联查询，反馈关联回读。只有明确采纳计为
采纳；未声明而拒绝的条件计为缺失需求。维护者读到按成员汇总的数据和成本；插件不写任何分支，当前
声明不因汇总改变；样本不让看的人读到无权的访问。

### U10：先找 Dataset 再搜索

调用者只知道任务，不知道用哪个 Dataset。库存按他的消费权限列出可用的 Dataset 和用途，他选定一个后
搜索；没有消费权的 Dataset 不出现在列表里。
