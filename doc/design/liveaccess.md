# LiveAccess：外部取值

access 不只是读仓里的内容。对象的某个方面或成员可以声明“值来自外部系统”，读取时由 LiveAccess
透明地取回，就像懒加载代理。

## 目标

- 读取方无感：读对象时，外部值在原位置出现实际值。
- 单值失败隔离：某个值取不到，只在那个位置说明原因，其他值照常返回；不用旧值或空值掩盖失败。
- 身份自动传递：调用者的认证按目标适用的规则传给外部系统，只发给可信目标。
- 每个值都有依据：观察时间、来源代际、一致性，以及可选的来源版本。
- 当次结果可复核：保留这次采用的值或失败、固定声明和原依据，事后按请求取回，不重新读最新值冒充历史。
- 声明由业务在仓里维护：值从哪个系统来、怎么取，写在方面或成员上，不写进 Schema。

## 声明

外部取值由两样东西组成，都是仓里的对象，经 Writer 发布：

| 部分 | 回答什么 | 谁维护 |
|---|---|---|
| 取值描述（ResourceDescriptor） | 一个外部系统怎么访问：`origin`、State 还是 Stream、取值协议和操作 | 外部系统的团队，可以发在自己的仓里 |
| 单元的取值来源 | 这个方面或成员的值来自哪个取值描述 | 这个单元的维护者 |

取值描述，示意：

```json
{
  "object_id": "sre/monitor-health",
  "kind": "ResourceDescriptor",
  "origin": "https://monitor.example.com",
  "mode": "state",
  "runtime": "http",
  "protocol": "resource-access/v1",
  "identity": "per-caller",
  "access": {"lookup": {"call": "lookup"}}
}
```

订单服务 `runtime` 方面下有三个成员：`health` 来自监控系统，`qps` 来自指标系统，`sla` 是写在仓里
的静态值。`health` 成员的头部写取值来源，没有正文：

```json
{
  "object_id": "trade/order-service",
  "aspect": "runtime",
  "member_key": "health",
  "schema_ref": "schema/service.runtime",
  "valueSource": {"kind": "binding", "binding": {"descriptorRef": "sre/monitor-health"}}
}
```

读取结果里 `runtime` 三个成员都在原位置，`health` 和 `qps` 各带自己的观察依据。监控系统超时时，
只有 `health` 报取值失败及原因，`qps` 和 `sla` 照常返回。

声明规则：

- 取值来源写在单元上，单元是方面或成员，最细到成员，不到成员里的某个字段。需要部分字段从外部取、
  部分手写时，拆成两个成员。一个单元只有一种值来源。
- 同一个方面要么整体声明外部取值、不带成员文件，要么由各个成员分别声明，方面本身不带取值来源。
  这沿用对象表示一致性的规则，不存在方面声明、成员覆盖的优先级。
- 取值来源只引用取值描述，不内联取值方式。取值描述按 ID 引用，可以引用别的仓发布的，并固定版本，
  规则和引用 Schema 相同。
- Schema 只校验值的结构。取回的值不符合单元采用的 Schema，算取值失败。Schema 里写 `origin` 或
  取值声明，Writer 拒绝。
- 声明的版本由单元版本和取值描述版本共同决定，任何一个变了，声明摘要都变；固定版本的读取仍按
  原声明取值。
- 取值描述不含凭证。凭证可以发往哪些 origin 只由部署配置决定，取值描述写了别的 origin 也不能
  扩大这个范围。origin 与可信范围按 scheme、host、port 三者精确匹配（缺省端口按 scheme 补齐），
  不做通配，不按域名后缀放行。
- 取值描述声明结果是否随调用者变化：`per-caller`（默认，外部系统按调用者授权，不同人可能拿到不同
  结果或被拒）或 `shared`（结果与调用者无关，例如表的行数）。写成 `shared` 是外部系统团队的承诺，
  决定这个值能不能进共享的索引，见下文规则。
- Dataset 选入了单元所在的仓，没有选入取值描述所在的仓时，取值描述按修订冻结的依赖版本解析
  （见[Dataset](dataset.md#发布)），和跨仓 Schema 相同；取值描述本身不因此进入消费者可见的范围。
- 外部系统按请求里的单元地址（如 `trade/order-service#/runtime/health`）识别要取哪个值。需要显式
  参数时再加，当前不加（待确认）。

## 规则

- 业务空值、取值失败、没有取值能力是三种不同情况。
- 观察依据每个外部单元一份，放在值旁边，按单元地址对应：不写进值，也不写进仓。值保持单元
  Schema 规定的形状，静态值和外部值形状一致，读取方不必先判断来源；值摘要、定位和索引只对值计算，
  不随观察时间变化。声明维护的条件依据已保存的声明，防止并发覆盖，不采用外部观察结果或观察时间。
  取值失败同样按地址列在旁边，和合法的 null 分开。需要在值旁边看到观察时间时，
  由命令行或 Console 按地址拼接展示，不改变结果形状。
- 外部值可以进索引：选进 Dataset 的[索引声明](discovery.md#索引声明)指向 Schema 字段，值取自观察，
  同时保留原观察依据；动态命中回读原观察。
- 只有取值描述为 `shared` 的单元能作为索引输入。索引由服务身份准备，Dataset 的消费权限又是整体的，
  `per-caller` 的值一旦进索引，外部系统本会拒绝的人也能通过命中或摘要看到它；这类成员在核对时标为
  不支持并说明原因。读取时外部值仍按调用者身份逐值取。
- 外部值不随 Dataset 版本冻结。命中带着建索引时的观察依据；回读取到新观察后按查询条件补判，不再
  满足的命中淘汰。结果标明哪些条件用到了外部值、观察有多旧。只有当前版本的外部值会刷新，保留的
  旧版本沿用固定时的观察，刷新成本不随保留的版本数增长。
- 一次读取里的外部取值共用请求剩余的时限：每个单元的调用时限取它自己的时限和请求剩余时限中较小
  的。时限用尽时，未完成或未开始的单元逐个报取值超时，已经取到的值照常返回。
- 后台有权取值，不表示所有消费者都能看，见[权限](permissions.md)的“外部状态有两次授权”。
- 访问地址变化或重定向不能扩大凭证范围；凭证不进入对象、日志或证据。
- 证据可靠保存后才交付成功结果。证据丢失和到期要能区分。
- 紧急清除（见[Dataset](dataset.md#紧急清除)）覆盖证据：被清除对象在证据里的观察值替换为“已清除”
  标记，保留摘要、依据和访问记录，审计仍能说明当时交付过什么摘要、给了谁。
- 动态状态默认不保存全部历史，能否按旧依据重读取决于来源能力和保留策略。

## 合同

取值调用是 `LookupState(ctx, StateLookupRequest) → (StateObservation, error)`。请求带 Binding、
SchemaRef、来源、身份、追踪和请求标识；成功返回值和依据。精确形状以 `liveaccess/` 的 Go API 为准。

## 入口

读取对象时自动生效，不需要单独的命令；`kc plugin liveaccess help` 说明声明写法、适用条件、对结果
的影响以及认证和审计承诺。

同一方面下一个成员从外部取值、兄弟成员是静态值，读取时各在原位置，失败只影响该成员；整个方面
声明外部取值也成立。两个外部成员各有一份观察依据，按地址列在值旁边，值本身不含观察字段，
重复读取时观察时间变化不改变值的摘要。同一方面既在方面上又在成员上声明、Schema 里写 `origin`、取值来源内联取值方式，
都由 Writer 拒绝。取值描述发在另一个仓并固定版本，HEAD 改了 `origin` 不影响固定读取；改取值描述
会改变声明摘要；取值描述写了部署未信任的 origin，不带凭证外呼。

### U22：外部值进索引不越权、不冒充最新

行数来自 `shared` 取值描述，健康状态来自 `per-caller` 取值描述，索引声明两者都引用。行数成员可以
过滤排序，健康状态成员标为不支持；外部系统拒绝某个用户的健康状态时，他既读不到也搜不到它。行数
在建索引后变化，回读按新观察补判，不再满足的命中淘汰，结果标明观察时间。保留的旧修订不再刷新
外部值。

### U23：跨仓取值描述、读取时限与 origin 匹配

Dataset 没选入取值描述所在的仓，外部单元仍按引用版本取值，取值描述不出现在 Dataset 的文件列表里。
三个慢成员各自没超时，合计超过请求时限：先完成的值照常返回，其余逐个报取值超时。可信范围是
`https://monitor.example.com` 时，同 host 不同端口、`http` 或子域名都不带凭证。

## 代码位置

| 目录 | 负责 |
|---|---|
| `liveaccess/` | 声明解释、取值与认证适用政策 |
| `liveaccess/service/` | 值采用和逐值失败 |
| `liveaccess/plugin/` | 插件入口 |
| `liveaccess/handler/` | 处理器合同、实现声明与注册表（内部机制） |
| `liveaccess/dispatch/` | 处理器调用任务：解析实现、授权、调用与结果校验 |
| `liveaccess/evidence/` | 原结果保留 |

| 进度 | 内容 |
|---|---|
| 已有 | 外部状态的精确读取、独立的动态索引、内容与观察两套依据、变化通知后按需拉取 |
| 已有 | 声明只在方面或成员上，只引用取值描述；`origin` 与 State/Stream 在取值描述里，Schema 上没有取值声明与内联写法；取值描述带 `identity`（缺省 `per-caller`）；取值描述所在仓未选入 Dataset 时按冻结的依赖版本解析 |
| 已有 | 一次读取的外部取值共用请求剩余时限；origin 按 scheme、host、port 精确匹配，范围外不带凭证外呼；外部 404 与不可达逐值报失败 |
| 近期 | 独立插件：取值透明、逐值失败、身份传递、独立证据 |

| 未到 | 真实部署下通知失联、乱序和重启恢复；默认时效约定；观察保留期；事件窗口查询；显式取值参数 |
