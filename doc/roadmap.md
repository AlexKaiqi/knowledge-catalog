# 路线

## 现在在哪里

基础已经立住：仓与版本、Dataset 交付、对象与 Schema、Writer 发布、固定版本读取、搜索后同版本
回读、权限、身份与自助接入，都在单实例参考实现上具备。当前专注 discover 与 access。对象身份与对象层
已经按新设计改完；两个插件（声明式索引、LiveAccess）原先按“插件有作用域”的方案改造，2026-10-15 改为
“插件只作解释器、索引声明选进 Dataset 生效”，旧方案中止，按新设计重新做。验收规格先行，已写在场景树里。

## 能力总览

| 能力 | 已有 | 近期 | 未到 |
|---|---|---|---|
| [Snapshot](design/snapshot.md) | lakeFS、不可变版本、条件提交、单一登记空间、托管仓与自有仓 | SDK 与命令行归入 `snapshot/` | 容量与恢复实测、多实例 |
| [Dataset](design/dataset.md) | 组合、固定版本、独立授权、默认最新、只读挂载 | 跟随来源分支、检索保留与退役、配额与紧急清除；定义幂等 | 部署下的发布恢复验证 |
| [权限](design/permissions.md) | 统一用户名、三种资源分开授权、撤权即生效 | 拒绝空身份 | 改名回收、准入方式、转授上限 |
| [对象](design/object.md) | 模型、Schema、Writer、固定读取、系统仓 | 统一对象引用；供给写法 | 不兼容 Schema 迁移；直接改仓的检查 |
| [插件](design/plugins.md) | 登记、部署安装实例、说明入口 | 声明移出 Schema；索引声明按清单名路由；能力清单按实例公开 | 插件间优先级 |
| [发现](design/discovery.md) | 全文、过滤、排序、关系、同版本回读、后台维护 | 选进 Dataset 的细粒度索引声明；只按 Dataset 搜索；查询归因、采纳反馈与使用数据 | 跨 Dataset 复用分段；分面；检索轨迹与意图；可选发现包 |
| [LiveAccess](design/liveaccess.md) | 精确读取、动态索引、双依据 | 声明落在方面或成员上并引用取值描述；透明取值、逐值失败、身份传递 | 部署恢复、时效、保留期 |
| [Affordance](design/affordance.md) | 分层帮助、插件说明入口、系统仓 | `kc help` 与系统仓一致 | wield、MCP 网关 |
| [服务](design/service.md) | 统一执行器、文件网关、可恢复单实例、证据 | 路由清单合一、拆分 `home/` | 多实例、多语言 SDK、SLI |
| [治理](design/governance.md) | 反馈、工作分支、条件合并、Hook | 已删除 controlplane 与 gate，审批归业务 | 真实任务中的修订效果 |

## 近期：马上要改的

按先后顺序排列，前一项是后一项的基础。

| 顺序 | 事项 | 完成时应看到 |
|---|---|---|
| 已完成 | 文档重写、对象身份去掉仓、对象层收尾 | URN 只由带命名空间的 `object_id` 构成；读取按范围收集同一 ID 的方面；读写只用统一对象引用 |
| 1 | 验收规格可执行 | 插件与 Dataset 修订的验收规格各有用例，测试源随用例环境起停，先跑出“能力还没有”的红 |
| 2（已完成） | 插件只作解释器 | 部署装了插件就按声明形状认领，能力清单名对应唯一实例；按仓选择实例已去掉。索引声明按清单名路由随第 5 项 |
| 3 | LiveAccess 声明与读取 | 取值来源写在方面或成员上，只引用取值描述（含 `origin`、`identity`）；逐值失败说明、请求时限、可信范围精确匹配 |
| 4 | 索引声明与能力清单 | Schema 只描述结构；索引声明是 `index` 方面，Writer 查形状，实例按清单核对，有试运行 |
| 5 | 检索空间按 Dataset 修订 | 搜索只以 Dataset 为范围，只认选进的声明，按成员增量构建；只有共享的外部值进索引 |
| 6 | 使用记录与 Dataset 修订生命周期 | 按成员公开使用数据；来源默认跟随、检索保留与退役、来源提交保留、配额、紧急清除 |
| 7 | 系统出版物同步 | 说明与新行为一致，和 `kc help` 的自动检查通过 |
| 8 | 目录重组与已登记的质量债 | 见下表；服务端拒绝空身份、Dataset 定义幂等 |

每一步改完行为时，按旧设计写的用例同批改写或删除，不提前删，也不保留成第二条路径。

目录重组的具体内容：

| 改动 | 原因 |
|---|---|
| HTTP 路由表只保留一份（已收口：`httpsurface` 退役，清单留在 `server/routes.go` + `server/routes_golden.txt`） | 原来有三处路由清单需要对账 |
| 命令行里的会话与登录代码收进 `client/` | 会话属于调用方，不属于命令行 |
| `cli/` 里的合同测试按所测模块搬回各自目录 | `cli` 测试代码约是生产代码的 6 倍 |
| 拆分 `home/` | 装配入口承担了过多职责 |
| 可选：给 `invoke/` 改个更清楚的名字 | 和 `invocation/` 太像 |

## 未到：愿景里有，暂时还没走到

| 方向 | 为什么现在不做 |
|---|---|
| wield：让对象执行有副作用的操作 | 当前专注 discover 与 access；合同等真实需求出现再定 |
| 可信的动态状态：真实部署下的通知恢复、时效约定、观察保留 | 先完成 LiveAccess 插件化 |
| 规模与生产资格：容量、吞吐、历史增长、备份与故障恢复的实测范围 | 压测执行器和基线还在建设 |
| 多实例部署、分布式协调、灾难恢复 | 单实例形态尚未在规模上验证 |
| MCP 网关、多语言 SDK | 先稳定 Go SDK 与命令行 |
| 事件窗口查询（Stream）、分面统计 | 等实际任务需要 |
| 跨 Dataset 复用索引分段 | 等多个 Dataset 引用同一来源出现真实规模压力 |
| 不兼容 Schema 的迁移方式 | 方案尚未决定 |
| 直接改仓时的发布前检查 | 需要先定在哪里拦截 |
| 真实任务收益：证明多源任务更快更准，反馈修订循环有效 | 需要在对象供给写法统一之后跑完整任务 |
