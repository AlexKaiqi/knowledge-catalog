# 路线

## 现在在哪里

基础已经立住：仓与版本、Dataset 交付、对象与 Schema、Writer 发布、固定版本读取、搜索后同版本
回读、权限、身份与自助接入，都在单实例参考实现上具备。当前专注 discover 与 access，正处在一轮
结构重构的收尾：对象层和两个插件（声明式索引、LiveAccess）按“插件有作用域”的方式改造，代码目录
随之重组。

| [对象](design/object.md) | 模型、Schema、Writer、固定读取、系统仓 | 统一对象引用；供给写法 | 不兼容 Schema 迁移；直接改仓的检查 |

## 近期：马上要改的

按先后顺序排列，前一项是后一项的基础。

| 顺序 | 事项 | 完成时应看到 |
|---|---|---|
| 1 | 文档重写（本目录） | 设计定稿，删除旧 `docs/`，更新所有指向它的链接、`AGENTS.md` 与 `make check-docs` |
| 2 | 对象身份去掉仓 | URN 只由带命名空间的 `object_id` 构成；读取按范围收集同一 ID 的方面；方面冲突明确报出；Schema 按 ID 跨仓引用 |
| 3 | 对象层收尾 | 读写只用统一对象引用；代码和测试按负责的目录归位，删除空壳和迁移转发 |
| 4 | 插件作用域落地 | 插件按 Schema 声明自动生效，仓可关闭；Dataset 不参与插件配置 |
| 5 | LiveAccess 插件化 | 取值透明、逐值失败说明、身份自动传递，有独立的访问证据 |
| 6 | 声明式索引插件化 | 按类型跨仓发现，结果按对象 ID 合并；Dataset 只作可选范围 |
| 7 | 目录重组 | 见下表 |
| 8 | 已登记的质量债 | 服务端拒绝空身份、Dataset 定义幂等、服务调用并发锁 |

目录重组的具体内容：

| 改动 | 原因 |
|---|---|
| HTTP 路由表只保留一份（`httpsurface` 与 `server/routes.go` 二选一） | 现在有三处路由清单需要对账 |
| 命令行里的会话与登录代码收进 `client/` | 会话属于调用方，不属于命令行 |
| `cli/` 里的合同测试按所测模块搬回各自目录 | `cli` 测试代码约是生产代码的 6 倍 |
| 拆分 `home/` | 装配入口承担了过多职责 |
| 可选：给 `invoke/` 改个更清楚的名字 | 和 `invocation/` 太像 |

## 未到：愿景里有，暂时还没走到

| 方向 | 为什么现在不做 |
|---|---|
| wield：让对象执行有副作用的操作 | 当前专注 discover 与 access；合同等真实需求出现再定 |
| 可信的动态状态：真实部署下的通知恢复、时效约定、观察保留 | 先完成 LiveAccess 插件化 |
| 规模与生产资格：容量、吞吐、历史增长、备份与故障恢复的实测范围 | 压测执行器和基线还在建设 |
| 多实例部署、分布式协调、灾难恢复 | 单实例形态尚未在规模上验证 |
| MCP 网关、多语言 SDK | 先稳定 Go SDK 与命令行 |
| 事件窗口查询（Stream）、分面统计 | 等实际任务需要 |
| 不兼容 Schema 的迁移方式 | 方案尚未决定 |
| 直接改仓时的发布前检查 | 需要先定在哪里拦截 |
| 真实任务收益：证明多源任务更快更准，反馈修订循环有效 | 需要在对象供给写法统一之后跑完整任务 |
