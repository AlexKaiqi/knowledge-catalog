# 任务

一个任务一个文件，所在目录就是状态：

| 目录 | 含义 |
|---|---|
| `todo/` | 待做：目标和验收已经写清，还没开始 |
| `doing/` | 正在进行：已开始，进展写在文件里 |
| `done/` | 已结束：验收全绿后完成，或者未完成就关闭；关闭的条目末尾有 `## 关闭`，写明原因与去向 |
| `explore/` | 待回答的问题：结论未知，不预设交付物；不是第四种状态，见下 |

改状态就是移动文件（`git mv tasks/todo/X.md tasks/doing/`），文件里不另写状态字段。`make check-docs`
检查这个布局：只有这三个状态目录加 `explore/`；文件名是任务 ID；标题以同一个 ID 开头；同一个 ID 不会
同时出现在两个目录；文件里的链接都有效。

## 族（状态目录下的子目录）

一条主线上的多条任务可以放进状态目录下的族子目录，如 `doing/object-versioning/`，让成员与顺序一起可见。
族只改变摆放，不改变状态：状态仍是第一段目录，族内任务照样移动文件换状态；同一个 ID 也不能既在族里
又在状态目录下。

- 族名用小写词，如 `object-versioning`、`index-refactor`，与任务 ID 一眼可分。
- 族可以带一份 `README.md` 作索引，写成员、顺序、真实依赖与哪条任务承接什么。它是文档不是任务，
  标题不写任务 ID；索引里的成员表会随状态移动而失效，所以成员之间按 ID 引用、不写成链接。
- 不嵌套：族内只能是任务文件与这份索引。
- `done/` 保持扁平：它是历史，不随主线重组搬家。族里的任务完成后按普通规则移到 `done/`。
- 族不是为了让任务变多，而是为了一条主线不再把所有路径、并入债和证据堆进一个文件。什么时候拆：
  一条任务里出现两条以上可以各自判定通过的使用路径，或文件涨到读不出"现在缺什么"。

## 探索（`explore/`）

`explore/` 放的是**待回答的问题**，不是待做的工作。"这个入口的权限判定是否一致"有明确答案，但没有
已知的交付物和验收标准——先写验收等于先假定结论。因此它不进 `todo/`：`todo/` 的每一条都能判定变绿，
而探索的合法结论包括"没有问题，不改代码"。

- 不用 `audit` 这类命名：审计预设有问题存在，而探索的结论可能恰恰是没问题。目录名描述的是产出形态，
  不是对结论的预判。
- 探索文件不移动状态，在原位结束：末尾加 `## 结论`，写确认了什么、排除了什么、证据在哪。
- 确认的问题不就地修，另开任务承接。新任务用自己的 ID，不复用探索的 ID（同一个 ID 不允许同时是探索
  和任务）。探索文件保留结论作为该任务的由来。
- 排除了的疑点也写进 `## 结论`，避免同一疑点被反复重开。
- 探索不写 `## 验收`，改写成 `## 要回答的问题` 和 `## 判定标准`：前者是要消除的不确定性，后者是
  什么证据能让问题关闭，不假定结论方向。

## 写法

新任务的 ID 用大写词加两位序号，如 `PLUGIN-INTERPRETER-01`；债以 `DEBT-` 开头。`done/` 里有些历史
条目没有序号，保持原样。

```markdown
# <ID> · 一句话标题

## 目标
做完后系统是什么样，写结果，不写步骤。

## 依据
触碰的设计篇，链接到 doc/。

## 验收
哪些用例或规格变绿、哪些门禁通过。不写“命令成功”。

## 前置
依赖哪些任务，或要等什么条件。没有就写“无”。

## 不做
明确排除的范围。
```

- 开始：移到 `doing/` 即开始。前置已完成、彼此不改同一批文件的任务可以并行推进；有前置或改动重叠的按 `## 前置` 依次做。任务文件不记录由谁、在哪个分支执行，进展和交付只写事实与证据。
- 完成：契约（含 `make check-docs`、`make quality`）全绿、无 skip，才能移到 `done/`；在文件末尾加
  `## 交付`，写实现范围、已验证范围和提交。实现完成不等于验收通过，两者分开写。
- 关闭：不再做的任务也移到 `done/`，末尾加 `## 关闭`，写原因和剩余部分去了哪个任务。
- 债：质量“三出口”里登记为债的问题就是一条 `DEBT-` 任务，`## 目标` 之前加 `## 债`，写位置、信号、
  判定、处置、触发条件。
- 债的归并：登记时一个信号一条债；执行时按文件和环境归并。债的触发条件指向某个任务，或与某个任务改同一批
  文件、占同一测试环境时，该任务开工即把债并入（债登记时该任务已在 `doing/` 的，登记后立即并入）：主任务
  加 `## 并入`，写原债的位置、信号与剩余验收；原债移到 `done/`，末尾 `## 关闭` 写明并入哪个任务。不为单个
  信号另开一条与主任务改同一批文件的并行线。
- 大任务拆成多个文件，用 `## 前置` 连起来，不在一个文件里嵌套子任务清单。
- 任务之间按 ID 引用（写成 `` `PLUGIN-INTERPRETER-01` ``），不写成链接：文件会随状态移动，链接一移就断。
  链到 `doc/` 等不移动的位置照常写链接。
- `done/` 是历史，内容不再改写；词汇守卫对它豁免，对 `todo/`、`doing/` 不豁免。
- 本机 `.validation/` 证据用代码路径记录，不写 Markdown 链接；忽略的运行产物不随检出交付。

## 目录重组的共同约定

适用于 `ARCH-*` 等以移动职责为主的迁移任务，子任务不再各自复述。

- 实施前记录本批迁移清单：现 owner、目标 owner、生产消费者、公开入口、对应测试，
  以及正在修改同一文件的任务。归属按设计与实际调用判定，不按文件名、代码行数或测试/生产比例。
- 每次迁移同时迁移对应测试并执行到绿，不把测试留给最后的收尾任务。禁止复制算法、
  增加私有原样转发、为测试扩张公开面，或把新包作为绕过层约束的中转。
- 保留既有 CLI、HTTP、配置、耐久数据及公开 Go 入口的合同。必要的兼容桥只委派唯一实现；
  行为设计的缺口归相应行为任务，不借目录调整实现新协议。
- 门禁按改动范围取：迁移任务跑受影响包回归、`make check-docs`、`make quality`；
  全量 `make test`、`make test-contracts`、`make test-all`、`make deploy-local-scenes`
  在联合候选（`ARCH-LAYOUT-01`）和 `FINAL-ACCEPTANCE-01` 上执行一次，不在每个子任务重复。
  路径变化须同步实际测试登记、包 README 与拥有该职责的设计篇。
- 迁移任务的验收写"搬完后哪些既有行为断言不变"，不把开工后才能产出的归属表、
  对应表、逐项说明当作验收对象；这类产物是过程证据，写在 `## 交付`。
- 无前置且文件不重叠的任务可以分别推进；共享架构守卫、文档和耦合基线变更按候选顺序合入。

## 改同一份设计篇与场景树时

多条任务改同一份设计篇或同一棵场景树（如 `doc/design/discovery.md` 与其规格文件）时：

- 设计修订在设计篇所在的批次内一次写完，各任务只补自己那节的用例编号，不各开一轮修订。
- 门禁按条跑：每条任务跑自己那几条规格加 `make check-docs`、`make quality`；
  全量 `make test` 由该批次最后一条任务跑一次，结果记在该任务，不要求每条重复。
- 各任务仍是独立文件、独立验收，不因为共享材料就合成一条。合并只在"一句话讲不清"时做，
  不因为改同一份文件就合并。
