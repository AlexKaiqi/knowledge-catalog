# 任务

一个任务一个文件，所在目录就是状态：

| 目录 | 含义 |
|---|---|
| `todo/` | 待做：目标和验收已经写清，还没开始 |
| `doing/` | 正在进行：已开始，进展写在文件里 |
| `done/` | 已结束：验收全绿后完成，或者未完成就关闭；关闭的条目末尾有 `## 关闭`，写明原因与去向 |

改状态就是移动文件（`git mv tasks/todo/X.md tasks/doing/`），文件里不另写状态字段。`make check-docs`
检查这个布局：只有这三个目录；文件名是任务 ID；标题以同一个 ID 开头；同一个 ID 不会同时出现在两个
目录；文件里的链接都有效。

## 写法

新任务的 ID 用大写词加两位序号，如 `PLUGIN-INTERPRETER-01`；债以 `DEBT-` 开头。`done/` 里有些历史
条目没有序号，保持原样。

```markdown
# <ID> · 一句话标题

## 目标
做完后系统是什么样，写结果，不写步骤。

## 依据
触碰的设计篇，链接到 doc/。

## 验收
哪些用例或规格变绿、哪些门禁通过。不写“命令成功”。

## 前置
依赖哪些任务，或要等什么条件。没有就写“无”。

## 不做
明确排除的范围。
```

- 开始：移到 `doing/` 即开始。前置已完成、彼此不改同一批文件的任务可以并行推进；有前置或改动重叠的按 `## 前置` 依次做。任务文件不记录由谁、在哪个分支执行，进展和交付只写事实与证据。
- 完成：契约（含 `make check-docs`、`make quality`）全绿、无 skip，才能移到 `done/`；在文件末尾加
  `## 交付`，写实现范围、已验证范围和提交。实现完成不等于验收通过，两者分开写。
- 关闭：不再做的任务也移到 `done/`，末尾加 `## 关闭`，写原因和剩余部分去了哪个任务。
- 债：质量“三出口”里登记为债的问题就是一条 `DEBT-` 任务，`## 目标` 之前加 `## 债`，写位置、信号、
  判定、处置、触发条件。
- 债的归并：登记时一个信号一条债；执行时按文件和环境归并。债的触发条件指向某个任务，或与某个任务改同一批
  文件、占同一测试环境时，该任务开工即把债并入（债登记时该任务已在 `doing/` 的，登记后立即并入）：主任务
  加 `## 并入`，写原债的位置、信号与剩余验收；原债移到 `done/`，末尾 `## 关闭` 写明并入哪个任务。不为单个
  信号另开一条与主任务改同一批文件的并行线。
- 大任务拆成多个文件，用 `## 前置` 连起来，不在一个文件里嵌套子任务清单。
- 任务之间按 ID 引用（写成 `` `PLUGIN-INTERPRETER-01` ``），不写成链接：文件会随状态移动，链接一移就断。
  链到 `doc/` 等不移动的位置照常写链接。
- `done/` 是历史，内容不再改写；词汇守卫对它豁免，对 `todo/`、`doing/` 不豁免。
- 本机 `.validation/` 证据用代码路径记录，不写 Markdown 链接；忽略的运行产物不随检出交付。
