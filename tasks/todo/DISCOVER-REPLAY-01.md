# DISCOVER-REPLAY-01 · 用积累的使用记录回放评估声明

## 目标

维护者可以从一个 Dataset 积累的使用记录里选出一批查询（连同意图、会话和采纳结果），在另一个 Dataset
（通常是选入候选声明的 staging Dataset）上回放，得到逐查询的对比：原采纳的命中是否仍在候选里、名次
变化、新出现的命中、因未声明或不支持被拒的条件。回放只读，不写使用记录、不产生反馈、不改任何分支。

学出来或由 Agent 生成的候选声明，也走这条路径比较，再经 Writer 发布进正式 Dataset：策略始终是一份
有版本、可回放的声明，不是运行时里看不见的排序。

## 依据

- [发现](../../doc/design/discovery.md)：索引声明（“调优效果要先试再改”）、使用记录。需在该篇补写回放的
  语义与边界。
- [Dataset](../../doc/design/dataset.md)：staging Dataset 只是普通 Dataset。

## 验收

- `discovery.md` 补写回放后有对应用例，场景树规格全绿。
- 同一批记录在同一 Dataset 修订上回放，结果与原查询的候选一致（排除外部值观察时间带来的差异，并标明）。
- 回放不产生新的使用记录和反馈；调用者无权读的原访问只给引用，不能借回放读到内容。
- 回放的范围、预算与续页遵守与 search 相同的完整性规则，超预算明确报告。
- `make check-docs`、`make quality`、`make test` 通过。

## 前置

`INDEX-USAGE-01`。意图与会话字段在 `DISCOVER-INTENT-01` 完成后一并带入回放；回放本身不依赖它。

## 不做

不自动生成或推荐声明；不对采纳信号做曝光纠偏（另行设计）；不提供在线 A/B 分流。
