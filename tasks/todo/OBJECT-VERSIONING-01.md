# OBJECT-VERSIONING-01 · 对象版本与读写重构

## 目标

落实[对象版本与读写](../../doc/design/object-versioning.md)：对象状态比较和精确回读有明确范围，
无变化命令可恢复与重放，长历史可连续查询且不伪造引入点。减少重复读写的方案以实际成本决定。

按设计语义审查本任务中的 HTTP/CLI 接口候选后确定实施范围；拟交付 `basis/state`、对象两版比较、
无变化回执和连续历史查询。新增条件写、历史加速和 head 缓存另行选择。设计修订不代表接口已实现或验收通过。

## 依据与实施入口

以下事实基于 2026-10-20 的工作树核对；实施前复核受在途任务影响的部分。

## 设计审查结论（2026-10-20）

采用以下语义边界；接口选型、持久记录与恢复机制仍待实现前落实，主任务尚未开工：

- 状态摘要只回答同一逻辑范围内的本地状态是否相同；固定读取坐标和修订历史分别回答读取哪版、何时变化。
  来源或选择规则变化属于范围变化，新增或删除 Unit 属于同范围内的状态变化。局部摘要不升级为全局版本或仓级 CAS 的替代。
- 单仓提交只固定该仓的本地保存内容。精确回读还须固定全部所需解释依赖，携带完整依据并重新鉴权；
  依赖不可用时失败，不回退最新。外部观察可变与解释依赖漂移分别处理。
- Dataset 的整仓和文件切片消费均不授予来源历史权。查询来源历史须独立校验来源仓权限，每次续页重验；
  合法发布版本之间的内容比较继续使用双侧 Dataset 消费权限。
- 无变化命令可在全部校验后的最后一次权威 ref 条件检查线性化，最终回执持久化后才返回成功。
  没有持久完成证明不得恢复成原成功；持久记录能证明从未调用提交且已限定为无变化处理时，可重新鉴权、校验原请求和原基准后重新判定，
  不将原基准替换为新 head。可能已调用提交时进入原有未知提交恢复流程。
- 目录零差异须保留可验证的原始意图，交 Writer 完整校验；显式空 ChangeSet 仍拒绝。
  无变化按全部业务效果判断。Merge 即使内容树相同，只要推进目标 commit 就属于仓变化。
- 历史按固定 first-parent 链连续扫描。扫描预算与修订返回上限分别处理，未证明引入点的状态段跨页保留；
  空页也必须使扫描位置单调推进，不得以重复游标形成死循环。
- 性能收益单独测量。固定 commit 或新增摘要本身不是收益证据；优化未达成本目标时停止，不阻塞正确性修复。

以及历史扫描进度和未完成状态段如何跨页保存。逐一说明基准检查、提交调用、账本保存和响应之间的故障恢复；

新增行为同步公开 Go API、包说明及相应 CLI/HTTP 合同；
已存在的行为只补必要缺口，不因本任务重新实现。

## 验收

以采纳后的接口方案验收以下路径；新条件写或缓存用例仅在另行采纳时执行。

| 场景 | 判定 |
|---|---|
| 其他对象提交、仅声明变化、Unit 拆分变化；字段投影未返回的字段变化 | 比较粒度符合设计，既有维护摘要兼容；未选 Unit 不为摘要被读取 |
| D1 选 A 仓、D2 选 A+B；部分无权、失败或冲突；同一选择规则下新增或删除 Unit | 范围差异和未决项可见，不误报完整对象比较；Unit 集合变化仍可比较同范围状态，本地状态不混入描述符版本或外部观察 |
| 固定回读期间主仓或依赖仓 head 前进；Dataset 两版同来源 commit 但范围不同 | 沿原来源和完整依赖坐标读取及续页，不回退最新；普通新请求仍按既有新鲜度约定解析。只有 Dataset 消费权的调用方仍可读取清单内内容，不能借回读越界 |
| Dataset 根目录整仓交付、文件切片；来源历史授权授予后再撤销 | 仅有消费权均不能查询来源历史；独立来源仓授权适用于首页与每次续页。双侧有消费权的发布内容仍可比较，无须追加来源仓读权 |
| 新增条件写（若采纳） | 条件匹配目标维护范围；命中、冲突及拒绝后不推进仓均验证，不承诺跨仓原子条件、不放宽仓级 CAS |
| 正文相同但路径、provenance 或 Binding 声明变化；全部业务效果相同；目录零差异；显式空操作集 | 有业务变化时保存全部效果；目录零差异有可验证原始意图并走完整 Writer 校验，无变化结果可重放，显式空集仍拒绝；无变化不推进仓、不发仓推进通知 |
| 过期基准、前置失败、同命令异请求；判定期间并发写入；内容树相同但 Merge 推进 commit | 校验不被无变化出口绕过；原基准不得被新 head 替换。Merge 推进 commit 仍报告仓变化并保留相应通知 |
| 最后 ref 检查后、回执持久化前崩溃；其后 head 不变或已前进；回执已持久化但响应丢失；同命令并发恢复及旧执行者迟到写回 | 无持久完成证明不补造原成功。可证明未调用提交且限定为无变化处理时重新鉴权和校验原请求、原基准；可能已提交时走未知提交恢复。已有完成回执可原样重放，失效执行者不能覆盖最终结果；不以当前内容相同冒充成功 |
| 超过 1000 单页、10000 原窗口及所选扫描预算；状态跨页持续相同；连续多个空结果页 | 连续遍历不漏项、不重复；窗口边界不伪造引入点及作者时间，未知边界可识别并可继续；空页游标携带未完成状态段且扫描位置单调推进，只有证明终点才结束 |
| `A → B → A`、删除后原样重建、合并提交 | 历史保留 first-parent 上的实际变化；加速结果与完整逐提交结果一致，端点 diff 为空不跳过真实修订 |
| 缓存改动（若采纳）：同名仓来自不同存储、来源绑定变化、撤权、旧 commit 复读 | 不串来源、不越过当前授权和范围；head 缓存另验写后读、外部写入可见时限及失效后旧请求回填 |

HTTP 与 CLI 分别执行“读取取得 basis → 同范围回读 → 两版比较”“条件写 → 无变化回执 → 响应丢失恢复”
及“首页 → head 推进 → 仅游标续页”。覆盖 basis 与其它坐标混用、改变选择范围、跨重启回读，
以及完整依赖缺失、无权或不可解析时不回退最新，预算耗尽时空页仍可继续。
仅凭 Dataset 消费权查询来源历史，无论交付整仓还是文件切片均须拒绝；已发布两版内容比较仍按双侧权限成立。
同命令恢复的 `changed` 不丢失，不同无变化命令共享 commit 时回执仍可区分。

与 `INDEX-PHYSICAL-01` 的交叉场景统一见该任务的“联合验收”。本任务验证其中的范围、
完整候选来源与依赖回读、本地状态摘要、真实历史修订、无变化回执，以及索引回收后的读取依据和观察证据
仍按各自合同可用；索引侧验证成员复用、物理资源保护与释放，在同一候选上核对双方结果。

所选优化按[压测合同](../../.data/scale/CASES.md)记录环境、规模与前后结果：

- 分解受影响路径的 ref、locator、正文和依赖读取次数及延迟，覆盖相关的冷/热缓存与最新/固定坐标。
- 无变化写入计入新增比较成本和节省的提交成本；历史加速同时对照完整遍历结果。
- 涉及 head 缓存时同时测量新鲜度。夹具通过不能替代真实 lakeFS 回源与性能证据。

在同一候选上通过受影响回归、`make check-docs`、`make quality`、`make test`、`make test-contracts`，
无 skip；交付记录实现范围、已验范围和性能证据。

## 推进安排与固定读取依据交付（2026-10-20）

先与 `INDEX-PHYSICAL-01` 审查完整读取依据、逻辑范围、候选来源和解释依赖，
明确读取依据、观察证据与查询资源各自的保留责任，再落实公开接口与持久解析机制。
审查结束后优先交付固定读取依据基础，让索引使用真实实现，不让它自行定义一套临时版本模型。

“固定读取依据交付”是索引实现的前置交付点，须同时满足：

- 既有设计要求的对象、选择范围、来源绑定、完整候选来源及解释依赖已由对象层统一表达和校验；
  索引可消费的接口、owner 与适用范围落实到公开代码、包说明和合同。
- HTTP/CLI 读取取得依据并沿原依据回读，跨重启仍可解析；来源或依赖推进后不跟随最新，
  缺失、无权、错误范围或不可解析时明确失败，Dataset 消费与来源仓授权边界保持。
- Reader/服务实际路径与当前授权回归通过，提供索引消费该接口的契约用例；
  记录接口版本或源码指纹、回归结果及剩余未验项，仅有类型声明或设计文字不算交付。

随后索引推进资源保护、恢复和成员产物复用；本任务继续对象比较、无变化写入和连续历史。
互不依赖且文件不重叠的部分可以分别推进，共享接口变化先合入同一候选再验证。
单条执行线优先交付上述基础，再推进索引及本任务剩余交付，最后做 ARCH 主要迁移。

向 ARCH 的放行还须有索引任务的“索引接入与接口稳定交付”，不能在本基础交付后立即搬 DatasetPin。
执行器涉及的比较、无变化回执和历史接口，分别在该批实现与回归通过后才能迁移；
可选优化的未完成不自动阻塞未涉及的目录工作。
各交付点只供下游判断开工，不代表本任务全部验收通过，也不改变任务状态。
