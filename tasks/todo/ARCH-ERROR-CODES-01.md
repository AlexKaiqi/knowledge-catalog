# ARCH-ERROR-CODES-01 · 无生产者错误码独立清理

## 目标

对原目录任务中的错误码清理独立审计和验收：每个候选都有生产者、公开合同与消费者证据，
仅删除确认已退役且无合同保留需要的定义和相应死映射；仍有意义的错误与失败分类保持。

## 依据

- [架构](../../doc/architecture.md)、[架构不变量](../../doc/engineering/architecture-invariants.md)。
- [工程质量闭环](../../doc/engineering/quality.md)、[测试与验证](../../doc/engineering/testing.md)。
- 实施时读取 `kernel/README.md`、错误信封公开代码及各候选所属能力的 README 与 Conformance。

## 范围

核对错误常量、直接与间接构造、转换表、provider 透传、HTTP 映射、SDK 解码、公开合同和测试。
“仓内没有直接引用”不是删除依据；既有公开合同要求识别或保留的码不能据此移除。
若候选涉及仍在实施的行为，保留并归原行为任务确认，不用清理决定新协议。
审计可能得出无可删项；此时交付完整候选与保留理由即可，不为任务制造删除。

## 验收

- 候选清单逐项列出定义、实际生产/透传路径、消费者、合同依据及删除或保留判断；
  区分已退役死定义、仍有公开识别责任和正在实施的行为。
- 删除项无生产路径、无仍有效的公开合同责任；关联的死映射与说明同步清理，
  不改活跃错误码、错误信封、HTTP 状态或现行失败分类。
- 对仍有效的错误，provider、服务、HTTP 与 SDK 的现有一致性合同继续通过；
  不可用、未找到、权限拒绝和固定依据冲突不能因清理互相混淆。
- 若重复出现同类死定义信号，增加能识别间接构造和合法合同保留的守卫及正反例；
  不把简单文本引用计数当作删除判定。
- 受影响错误合同、`make check-docs`、`make quality`、`make test`、`make test-contracts`
  全绿且无 skip，记录源码候选与清理范围；结果由 `FINAL-ACCEPTANCE-01` 独立核对。

## 前置

无目录任务的整项前置，也不阻塞 `ARCH-LAYOUT-01` 的目录验收。
可提前进行只读候选审计；删除排在所属行为合同与生产路径稳定之后，不作为 Object 或 Index 的前置。
每个候选须在其所属行为合同和生产路径已明确、相关文件无重叠在途修改时处理。
对象版本、索引与 Dataset 生命周期新增或待定的错误由原任务决定，不能提前认作无生产者。

## 不做

不借清理设计新错误码，不删除仍有效的协议/conformance 断言，
不把目录搬迁和错误行为调整合成一次验收，不以保留不明为理由静默删除。
