# DISCOVER-INTENT-01 · 串起检索轨迹，尽量拿到意图

## 目标

不封装 discover，也不限制调用方用什么 Agent；系统只把调用方的检索过程串成可还原的轨迹，并在调用方
愿意时拿到意图。

轨迹按三层串联，前两层是事实，第三层只是推断：

- 数据流：后一步用了前一步的产出（命中坐标、续页位置、relations/traverse 返回的对象引用、库存列出的
  Dataset），系统自动记下“由哪一步得来”，不要求调用方配合。现有“回读关联查询”是它的一个特例。
- 调用方标注：沿用已有的 `trace-id`/`span-id`/`parent-span-id`，同一 trace 即一条轨迹，包括数据流串不上
  的改写、换 Dataset 等步骤。客户端可以从环境变量继承 trace，Agent 不需要每次都显式传。
- 推断：同一主体在短时间窗内的相邻调用，可以在汇总时推断为同一轨迹，必须标为推断，不和前两层混算。

意图是一段可选的不透明文本，挂在 trace 上，也可以挂在单次调用上；系统不解析，也不按意图改变执行路径
和结果。拿意图的入口要便宜：命令行参数与环境变量、帮助和 describe 里说明“附上任务说明能帮助改进检索”、
反馈的原因字段。没有意图时，查询文本和轨迹结尾的采纳或放弃作为弱信号保留。

按成员和按 Dataset 汇总时，能看到轨迹级信号：以采纳结束、以放弃结束、中途改写、换 Dataset、改走关系
的次数，以及这些情况在三层串联中各占多少。意图的可见范围与原访问证据一致，汇总只给引用。

## 依据

- [发现](../../doc/design/discovery.md)：目标里“意图由谁提出不归系统管”、使用记录、访问原语。本任务把它
  细化为“系统不解释意图，但记录意图与轨迹”，需先修订该篇再实现。
- [服务](../../doc/design/service.md)：证据规则，使用记录不进入搜索、不成为授权规则。
- 现有入口：命令都接受 `trace-id`/`span-id`/`parent-span-id` 并记入访问证据，HTTP 读 `X-Kc-Trace-Id`；
  检索结果带检索证据编号。复用这些，不另起会话标识。

## 验收

- `discovery.md` 修订后有对应用例（在 U9 上扩展或新增编号），场景树里有关联的规格并全绿。
- 不带 trace、不带意图的调用行为与现在一致；带意图的调用结果与不带时逐项相同。
- search → relations → read → feedback 不传 trace 也能按数据流串成一条轨迹；传了 trace 时，数据流串不上
  的改写和换 Dataset 也在同一轨迹里；推断出的关联在汇总里单独标出。
- 从环境变量继承的 trace 与显式参数一致，显式参数优先。
- 没有访问权的人在汇总里读不到他人的意图原文。
- `make check-docs`、`make quality`、`make test` 通过。

## 前置

`INDEX-USAGE-01`。

## 不做

不封装 discover 流程，不提供替调用方执行检索的 Agent；不按意图路由、改写查询或调整排序；不做意图
分类或理解；推断出的关联不当作事实，也不进入授权或证据；不按使用记录自动改声明。
