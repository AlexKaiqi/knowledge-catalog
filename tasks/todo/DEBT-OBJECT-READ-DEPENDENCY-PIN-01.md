# DEBT-OBJECT-READ-DEPENDENCY-PIN-01 · 限定单仓提交的精确回读承诺

## 债

- 位置：`doc/design/object-versioning.md` 的固定读取与缓存（原“读取与回读”末句）；
  `invocation/descriptor_scope.go` 与 `invocation/descriptor_scope_test.go` 的跨请求依赖解析合同。
- 信号：提案无条件称单仓可用仓与提交直接回读，同时要求精确回读固定所有所需依赖。
  单仓对象仍可引用其他仓的取值描述；新请求按其他可读仓当时的版本重新解析。
- 判定：2026-10-20 静态审查确认，固定本地提交不足以固定完整解释。
  `TestRequestDescriptorsNewRequestRefreshesVersionAndAuthorization` 已表达相同主仓提交下，
  后一次请求采用依赖仓新版本的行为；本次只阅读该回归，未执行。
- 处置：设计明确单仓提交能固定的内容边界；带跨仓依赖的精确回读使用完整固定依据，
  或明确要求所有解释依赖已由该提交确定。不要把外部观察可变与依赖声明漂移混为一件事。
- 触发条件：`OBJECT-VERSIONING-01` 的回读方案开工时并入。

## 目标

“精确回读”不因请求只指定一个主仓而遗漏跨仓解释依赖。

## 依据

- [对象版本与读写](../../doc/design/object-versioning.md)：固定读取与缓存。
- [对象](../../doc/design/object.md)：跨仓 Schema 引用与版本向量。
- [LiveAccess](../../doc/design/liveaccess.md)：跨仓取值描述与固定声明。

## 验收

- 主仓提交不变、依赖仓推进时，普通新请求与携带原固定依据的回读分别符合其承诺。
- 固定依据不可用或当前无权时明确失败，不回退最新依赖。
- 外部观察仍可变化，但回读使用的本地声明和解释依赖保持原坐标。
- 文档不再将单仓提交等同于完整依赖向量；通过受影响回归、`make check-docs`、`make quality`，无 skip。

## 前置

与 `OBJECT-VERSIONING-01` 的固定依据持久化及解析方案一并审查。

## 设计修订（2026-10-20）

对象版本设计已限定单仓提交只固定本地保存内容；精确回读的固定依据须覆盖全部所需解释依赖，
当前授权与坐标可用性重新检查，失败不回退最新，外部观察独立记录。
本轮未实现完整依据的持久解析与回放，未执行上述行为验收，本债保留待做。

## 不做

不承诺重现外部实时值，不静默改变普通新请求的依赖新鲜度。
