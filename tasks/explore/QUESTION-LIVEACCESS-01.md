# QUESTION-LIVEACCESS-01 · 外部取值在四个面是否一致呈现

## 要回答的问题

同一对象的 LiveAccess 动态值在 `read`、`search` 命中回读、`files read`、`traverse` 四处是否呈现一致；
失败值是否只影响该位置；动态值是否被误当成 Snapshot 字节。

## 已知证据

[liveaccess/README.md](../../liveaccess/README.md) 声称成功外部值在原位置呈现、合法 null 保持 null、
失败只在该位置呈现原因并进入 `ObservedValue.Failures`、不用旧值或空值掩盖；声明 commit 保持固定，
每个动态单位另带 `UnitObservation`，不表述为 Snapshot 字节。这些性质目前主要在 README 声明，四个面
的实测一致性尚未验证。

## 判定标准

- 四处呈现逐字段比对，差异全部能归到设计条款，关闭为"一致"；有无法归因的差异，关闭为"确认缺陷"。
- 失败三态（不可达、认证失败、合法 null）在四个面都只影响该位置，关闭为"失败隔离成立"；任一面把
  失败渲染成 null 或旧值，关闭为"确认缺陷"。
- 无实例认领时取值描述报"没有能力"而非通用失败码，关闭为"合同成立"。
- 完整候选坐标出现在交付制品或证据中，关闭为"范围泄漏"，另开任务。

## 前提

无。

## 不涉及

不新增取值协议、不扩张插件认领语义；不为验收给外部来源加真实凭据。
