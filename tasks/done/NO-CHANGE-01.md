# NO-CHANGE-01 · 无变化写入与回执恢复

## 目标

合法命令的全部仓内业务效果都与基准相同时，不创建提交，并返回可恢复、可重放的无变化结果。
判据包括路径、provenance 和声明；仅正文或本地状态摘要相同不够。Binding 虽无 Snapshot 值，
仍有持久声明，须纳入比较。

无变化出口保留正常写入的全部授权、归档、Schema、操作前置和基准约束，包括基准与期望目标一致、
目标引用的可写性及存在性检查。显式空操作集仍拒绝。

条件合并即使两棵树相同，只要目标引用推进到另一个提交就属于仓变更，不能按无变化省略。

## 依据

设计篇：[无变化写入](../../doc/design/object-versioning.md#无变化写入)的判据与结果、接受与恢复；
[条件合并](../../doc/design/governance.md#条件合并)的仓推进边界。

## 已交付

### 阶段账本基础

Snapshot 的可选 `StagedCommandLedger` 实现独立执行身份与耐久阶段：只有记录为无变化处理的 PENDING
可以在原 digest、原请求和原坐标下重新进入回调，且恢复执行永远不能转成提交。普通未知结果、预留后
尚无阶段证明、可能已调用提交者均继续拒绝自动重跑。

Bolt 的 `ConditionalCommandStore` 以整条原记录作条件，在一个事务内预留、转换阶段、完成、释放或
显式处置。普通 Execute 也使用同一条件替换。跨 ledger 的并发空读只允许一个 authority 回调，
迟到完成与迟到失败清理都不能覆盖或删除新回执。不支持条件替换的外部 CommandStore 仍可执行普通命令，
不启用阶段恢复，不另加一套无条件恢复特例。

耐久性复核修复了更新路径会重新创建丢失数据库或命令桶的问题：创建时同步初次文件的父目录，
更新只打开既有账本并验证已有桶。

### Writer 无变化出口

Writer 消费阶段账本：完整 codec、Schema、操作前置、路径、provenance 与派生定位符计划完成后，
比较全部实际树效果；全部相同才持久选择 NO_CHANGE，再通过实际存储的写入准入与最后目标 ref 条件
检查，保存 `changed:false` 回执。lakeFS 复用发布锁与相同的目标校验，并在临时分支验证实际写权限，
不创建提交、不推进引用、不发仓推进通知。未知能力不启用该出口；正常变更返回 true，旧回执保持未知。
不同无变化命令有独立回执身份。

物理仓绑定进入来源身份，防止同 endpoint 同逻辑仓名替换为另一物理仓后重放旧结果。

## 验收

| 场景 | 判定 |
|---|---|
| 全部业务效果相同；显式空操作集 | 有业务变化时保存全部效果；无变化结果可重放，显式空集仍拒绝；无变化不推进仓、不发仓推进通知 |
| 过期基准、前置失败、同命令异请求 | 校验不被无变化出口绕过；原基准不得被新 head 替换 |
| 判定期间并发写入 | 最后权威 ref 条件检查作为线性化点；其他命令可推进仓，原结果仍对应检查时的基准 |
| 内容树相同但 Merge 推进 commit | 仍报告仓变化并保留相应通知 |
| 最后 ref 检查后、回执持久化前崩溃；其后 head 不变或已前进 | 无持久完成证明不补造原成功。可证明未调用提交且限定为无变化处理时重新鉴权和校验原请求、原基准；可能已提交时走未知提交恢复 |
| 回执已持久化但响应丢失；同命令并发恢复及旧执行者迟到写回 | 已有完成回执可原样重放；失效执行者不能覆盖最终结果；不以当前内容相同冒充成功 |
| 旧回执缺少变化信息 | 保留未知，不默认为无变化 |

HTTP 与 CLI 分别执行"条件写 → 无变化回执 → 响应丢失恢复"，并覆盖同命令恢复的 `changed` 不丢失、
不同无变化命令共享 commit 时回执仍可区分。

## 前置

无。走 Writer 阶段账本与最后权威 ref 检查，不依赖固定读取依据，可与本族其它任务并行。

## 不做

不新增条件写语义或跨仓事务。不把"成员输入未变"当作可省略的修订；Dataset 同一发布的幂等重放
与新修订的成员输入未变各有自己的合同。不做性能优化与成本目标。

目录对照为零差异时的原始意图核验归 `ZERO-DIFF-01`：本任务只负责"全部业务效果相同则不创建提交"
这一判定的出口与恢复，不承担客户端意图完整性。
