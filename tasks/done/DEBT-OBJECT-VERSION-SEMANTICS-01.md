# DEBT-OBJECT-VERSION-SEMANTICS-01 · 统一对象状态摘要与读取版本的定义

## 债

- 位置：`doc/concepts.md` 的 Object Version；`doc/design/object.md` 的读取；
  `doc/design/object-versioning.md` 的比较状态与范围。
- 信号：核心概念称跨仓对象只有一个全对象摘要，读取设计把对象版本称为各方面版本的组合，
  新提案则定义特定范围内的本地状态摘要，且允许部分读取。
- 判定：2026-10-20 静态审查确认，三者回答不同问题。D1 仅交付 A、D2 交付 A+B 时，
  两边均完整授权也不能产生同一个无范围限定的对象版本；状态摘要也不能标识 A→B→A 中的两次修订。
- 处置：以采用后的设计统一核心概念与引用文案，明确状态比较的范围、固定读取坐标和修订历史；
  用自动文档守卫或合同保护已在多处出现的术语混用，避免只靠人工约定。
- 触发条件：`OBJECT-VERSIONING-01` 开工时并入。

## 交付（2026-10-21）：自动检查已落地

设计侧三项依据已在 `doc/concepts.md` 统一（范围限定的本地状态摘要、固定来源及依赖的读取坐标、辨认
变化的修订历史）。本次补上债要求、此前缺失的那一半：自动检查保护采用后的区别。

新增 `scripts/check-docs/version_semantics.go`，接入 `checkDocumentation` 主流程，随 `make check-docs`
对所有 `doc/` 下设计文档逐行扫描三类“把彼此独立的依据压缩成同一个东西”的表述：

- 全局对象摘要：`全对象摘要`、`全局摘要`、`全局唯一版本` 等。
- 摘要冒充修订身份：`摘要即修订`、`修订等同于摘要` 等。
- 本地提交冒充完整固定：`单仓提交足以固定完整…`、`本地提交即固定全部…` 等。

命中即 `make check-docs` 失败，并直接给出该条为什么错（例如“A→B→A 会恢复摘要但不是同一修订”），
不靠评审者记住这条区分。守卫只拦混用措辞，不规定文档该怎么写，因此不会把当前实现反向固化成设计约束。

回归 `scripts/check-docs/version_semantics_test.go` 四条：三条混用措辞各自被拒、采用后的措辞通过、
扫描覆盖依赖文档而不只是对象设计、真实 `doc/` 文档全量通过。`go test ./scripts/check-docs` 通过，
`make check-docs` 通过（21 篇）。

仍留待做：债的验收里“同范围状态比较、不同 Dataset 范围、部分读取和 A→B→A 的例子能够同时成立”
这一项依赖实现合同（`OBJECT-VERSIONING-01` 的固定依据持久化与解析），文档与守卫只能保证表述一致，
不能证明行为。故本债不归档。

## 目标

调用者能判断哪项依据用于状态比较、哪项用于精确回读、哪项用于辨认历史修订，
不把局部状态摘要当作全局唯一版本或写入条件。

## 验收

- 三处文档采用一致定义，不再无条件承诺跨仓对象存在一个全局完整摘要。
- 同范围状态比较、不同 Dataset 范围、部分读取和 A→B→A 的例子能够同时成立。
- 自动检查保护采用后的区别，重读变更文档并通过 `make check-docs`；涉及代码的合同通过相应回归及 `make quality`。

## 设计修订（2026-10-20）

本轮统一概念与设计中的三项依据：范围限定的本地状态摘要、固定来源及依赖的读取坐标、辨认变化的修订历史。
同一选择规则下 Unit 集合改变属于状态变化；不同来源或选择规则之间不能直接比较摘要。
