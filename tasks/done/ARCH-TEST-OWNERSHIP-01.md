# ARCH-TEST-OWNERSHIP-01 · 目录迁移后的测试归属收尾

## 目标

测试位置反映其真实验证边界：模块算法与模块入口合同归所属包，
根 CLI 保留 argv、身份运输、部署宿主、跨模块旅程和实际 Server 集成。
目录迁移后测试覆盖、验证入口登记与架构守卫仍能准确识别同一行为。

## 依据

- [测试与验证](../../doc/engineering/testing.md)、[测试目录](../../doc/engineering/test-catalog.md)。
- [架构不变量](../../doc/engineering/architecture-invariants.md)、[工程质量闭环](../../doc/engineering/quality.md)。
- 实施时核对 `internal/arch/README.md` 的根 CLI 所有权守卫及各能力 README。

## 范围

只处理各迁移任务完成后的残留归属、重复夹具和登记收尾；
不承接它们应同批迁移的测试，也不重做已完成的 CLI 所有权清理。
按被断言的行为、真实调用和装配边界判定归属，公共夹具留在现有测试支持体系，
不创建新的根场景目录或把业务材料移出所属场景节点。

## 验收

- 测试改名、拆分或合并后，原授权、版本、失败及恢复断言完整保留，不以测试数量减少作为收益。
- 模块内部算法不靠虚假的 CLI/HTTP 调用伪装成集成测试；
  真实 argv、身份注入、宿主装配与跨模块旅程仍在真实边界执行。
- 根 CLI 生产/测试边界、公开入口保护、CLI/HTTP 同一执行器和测试 owner 守卫保留，
  守卫路径随真实 owner 更新，并用正反例证明不会因迁移漏扫。
- 测试辅助复用单一实现但不复用被测逻辑生成预期，不为迁出测试增加生产后门或公开工具函数。
- 测试目录、架构不变量、场景关联、race 清单和验证清单中的受影响定位均可解析到实际入口；
  `make check-validation` 无遗漏或重复认领。涉及场景时先读场景 README，再按其合同执行结构与关联检查。
- 按 `tasks/README.md` 的「目录重组的共同约定」取门禁范围；不以定向测试替代完整合同或真实部署验收。

## 前置

- `ARCH-INVOKE-01` 完成，及其传递前置：Object/Index 相关接口已交付、目录迁移与对应测试已各自通过后，最后核对残留。
- 触及 `ACCEPT-HARNESS-01` 仍在修改的 probe 或登记文件时，先固定其该批交付再更新定位；
  不要求所有真实部署验收先完成，不改规格原预期。

## 不做

不机械迁走所有 `cli/*_test.go`，不追求测试/生产行数比例，不删除、跳过或弱化断言，
不把未完成的实现验收记成测试整理完成。
