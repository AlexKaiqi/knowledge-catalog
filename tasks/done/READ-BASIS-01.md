# READ-BASIS-01 · 固定读取依据

## 目标

一次读取取得的依据足以按原样回读：原对象、选择范围、候选来源（含未贡献内容者）和全部解释依赖
都固定下来，跨重启仍可解析。来源或依赖推进后不跟随最新；缺失、无权、范围不符或不可解析时明确失败。

依据只固定坐标，不发权。每次回读重新鉴权。依据的保留独立于查询生成代，索引回收不得破坏仍有效的依据。

## 依据

设计篇：[对象版本与读写](../../doc/design/object-versioning.md)的"固定读取与缓存""精确回读"；
[对象](../../doc/design/object.md)的读取；[核心概念](../../doc/concepts.md)的三类依据。

实施入口与现状：

| 入口 | 现状与要求 |
|---|---|
| [持有者选择](../../object/holding.go)与[请求解析](../../invocation/reference_target.go) | 按候选范围读取，`Withheld` 不反映未选来源。须审查根对象、定位符、形状读取的比较范围与未决项表达 |
| [维护摘要](../../object/maintenance_digest.go) | Snapshot 比值、Binding 比本地声明、全 Snapshot 按组装值比。新增聚合摘要或声明敏感条件须说明用途与兼容性，不能静默改变现有相等关系 |

| [文件仓读取](../../object/reader/repository_service.go) | 批量入口仍逐对象逐路径调用。本轮不改批量、并发或缓存形态 |

## 已交付

### 依据与耐久记录

`object.ReadBasis` 记录实际来源实例绑定（与逻辑仓名分开）、全部候选来源（含未贡献者）、
选择规则和解释依赖；本地状态摘要与读取坐标、成员构建身份分开。编码版本为 1。
`reader.Serving.ReadBasis` 与 `reader.OpenReadBasis` 可导出并重新打开已固定且已授权的视图，
重开前逐项核对实例绑定与提交可用性，依赖不进入成员范围，核对后不重新查找实例或读取 head。

`reader.NewReadBasisStore` 以不可变内容身份去重，事务与初次建文件的目录同步成功后才返回引用；
缺记录不新建，损坏不覆盖。记录留在安装耐久状态，独立于可回收搜索资源，只含坐标元数据。

### 读取入口接入

`objects:read`、SDK `ReadRequest.Basis` 与 `kc read --basis` 已接通耐久引用输入；普通仓、组合对象
及 Dataset 读取输出保留 `basis` 与独立的 `state`。服务端只解析原记录，拒绝另一套范围或版本输入
与选择扩张；Dataset 沿原发布版重新校验，普通组合沿完整固定候选重做授权与持有者选择。

形状读取在整次调用中固定主仓版本及描述符候选版本。直接仓的描述符候选同时保留未贡献者；
固定回读不重新发现来源，且逐引用重新检查当前权限。Dataset 准备保留用于证明依赖唯一性的
全部候选提交。无法冻结的解释依赖单独保留未决信息。

### 临时定义

`ReadBasis.Temporary` 与 Reader 的对应固定视图标记明确区分临时定义；重开时由保存的候选提交和
实际文件选择重建临时读取视图，经过既有临时定义验证与当前授权，不跟随 HEAD，不套用命名发布授权。
临时配方的虚拟目标布局不属于对象 URN 的读取范围，恢复只保留原来源文件选择，不为缺失选择补成整仓。

### 并入 `DEBT-OBJECT-READ-DEPENDENCY-PIN-01`

- 位置：[对象版本与读写](../../doc/design/object-versioning.md)的固定读取与缓存；
  [依赖范围](../../invocation/descriptor_scope.go)与其回归的跨请求依赖解析合同。
- 信号：单仓提交只固定该仓本地保存内容，而精确回读要求固定全部所需解释依赖。单仓对象仍可引用
  其他仓的取值描述，普通新请求按其他可读仓当时的版本重新解析。
- 剩余验收：主仓提交不变、依赖仓推进时，普通新请求与携带原固定依据的回读分别符合各自承诺；
  固定依据不可用或当前无权时明确失败、不回退最新；外部观察仍可变但回读使用的本地声明与解释依赖
  保持原坐标；文档不把单仓提交等同于完整依赖向量。

## 验收

| 场景 | 判定 |
|---|---|
| 固定回读期间主仓 head 前进 | 沿原来源与完整依赖坐标读取及续页，不回退最新；普通新请求仍按既有新鲜度约定解析 |
| 依赖仓推进，主仓提交不变 | 携带原依据的回读使用原依赖坐标；普通新请求采用当时版本。两者各自成立且可区分 |
| Dataset 两版同来源 commit 但范围不同 | 各自保留文件范围与独立消费授权，不互相补齐 |
| 只有 Dataset 消费权的调用方 | 可读取清单内内容，不能借回读越界；来源仓历史权不被推导 |
| 依赖缺失、无权、组成冲突或不可解析 | 明确失败，不以部分结果冒充原完整回读；未决项与本地状态完整分开报告 |
| 跨重启 | 依据可重新解析；损坏拒绝且不静默修复；记录去重、缺失与并发写入有实际回归 |
| 临时定义 | 修订 0 的匿名定义、带标签的临时定义、文件切片、来源推进、服务重开、无需来源整仓读权、撤权，分别成立；同名命名发布授权不能替代临时定义授权 |

另需：公开 CLI/HTTP 的读取取得 basis 并回读、`basis` 与其它坐标混用被拒、改变选择范围被拒。
