# SYSTEM-MODEL-GUIDE-02 · 建模方法论在系统仓的承载形态与设计同源

## 目标

系统仓里"从资料推导出模型"这一层有稳定归属：读者从导读能区分"先想清楚怎么建模"与"照着命令做"，且方法论正文与设计文档的权威表述不会各写一份然后漂移。

当前状态：`guides/model-from-materials` 已出版推导顺序与判据，但它与 `first-publication` 等操作指南同处 `guides/` 一族，靠正文自述区分；设计文档 [object.md](../../doc/design/object.md) 的"一个对象，还是相关的两个对象"一节仍是同一判据的另一份表述，两者之间没有一致性约束。

## 依据

- [对象](../../doc/design/object.md)：对象边界、切面与成员、关系、Schema 复用的既有判定表述。
- [工程质量闭环](../../doc/engineering/quality.md)：增量不欠；同类信号出现两次以上升级为守卫或契约。
- 系统仓说明的分类守卫 `systemrepo/system_explanations_test.go`：`concepts`/`interfaces`/`mechanisms` 必须有已复核的既有系统依据，`guides` 不受该约束。

## 验收

- 方法论有独立且可被导读识别的位置：或新增分区（如 `method/`），或明确以成员/标签区分操作指南与判据指南；发布清单、导读、导航关系与该选择一致，`go test ./systemrepo/...` 全绿。
- 同源方案落定并生效：设计文档那段判据与系统仓正文二者之间，要么其一为出版源且另有守卫核对，要么另一侧改为指针；`make check-docs` 通过，且守卫能在两侧表述分叉时失败。
- 陌生读者只看导读，能说出"要先读方法论再读发布指南"这条路径，不需要通读全部指南才能发现。

## 前置

无。与 `SYSTEM-GUIDE-EXECUTABLE-01` 改同一批文件（`systemrepo/content/guides/`、导读），按 `## 前置` 依次执行，不并行。

## 不做

不改协议形状与既有 Schema 的字段结构；不为方法论引入新的领域概念或概念身份；不把设计文档收窄成系统仓现状的复述。

## 方案

保留已有指南身份、Schema、路径与两条 `uses` 导航关系，以导读中的“建模方法”“操作指南”分类标签
区分消费阶段，指南标题也标明“建模方法”。对象边界判据以设计文档为权威，出版物保持完整同文段落，
由自动守卫核对；对象概念页改为指南的内部指针，不再维护第三份判据。

## 交付（2026-10-20）

按上述方案完成。指南中的对象边界段与设计完整同文，保留“由建模者决定、判据仅供参考”的前提；
修正“所有 Schema 修改都是破坏性变更”的过强表述，兼容修改仍须解释已有实例。
导读明确方法在前、操作在后，试读已有对象另按任务进入；没有变更指南身份、Schema、路径和两条导航关系。

`systemrepo/model_guide_test.go` 从实际出版操作核对同源段落、导读分类与阅读顺序、概念指针、身份和关系；
反例分别修改设计或出版物的判据时均拒绝，双方空段也拒绝。独立读者只读导读，能准确指出
“先从资料到模型判断对象与切面，再首次发布”，无需通读指南；其发现的试读路线歧义已消除。

最终 `go test ./systemrepo/... -count=1`、`make quality`（含 `make check-docs`）通过，无测试跳过。
证据在 `.validation/remaining-20261020/system-model-guide-tests.log`、
`model-guide-final-tests.log`、`model-guide-quality.log`。未提交。
